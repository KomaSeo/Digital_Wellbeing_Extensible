# 여러 기기 동기화

이 문서는 여러 PC가 같은 설정, 같은 할 일 목록, 같은 지금 할 일을 쓰게 하는 방법을 설명합니다.

## 1. 낱말

- **기기**: 이 프로그램(Digital Wellbeing)이 설치된 PC 한 대를 말합니다.
- **동기화 서버**: 모든 기기가 공유하는 파일을 보관하는 프로그램입니다. 이 문서에서는 줄여서 "서버"라고 부릅니다. 서버는 기기 중 한 대에서 돌려도 되고, 따로 둔 PC에서 돌려도 됩니다.
- **서버 PC**: 서버가 도는 PC를 말합니다.
- **관리자 계정**: Windows에서 프로그램을 설치하고 서비스를 끄거나 켤 수 있는 계정입니다. 소유자는 이 계정의 비밀번호를 종이에 적어 물리적으로 보관합니다.
- **관리자 터미널**: 관리자 계정의 권한으로 연 명령 창입니다. 시작 메뉴에서 "터미널"이나 "명령 프롬프트"를 오른쪽 클릭하고 "관리자 권한으로 실행"을 고르면 열립니다. 이때 관리자 비밀번호를 묻습니다.
- **열쇠(기기 열쇠)**: 기기 하나와 서버만 아는 비밀 값입니다. 둘 사이의 모든 메시지를 이 값으로 암호화하고 서명합니다. 서버는 기기가 회원가입하거나 로그인할 때 열쇠를 새로 만들어 줍니다.
- **짝 코드**: 로그인 대신 쓰는 예전 방법입니다. 서버의 관리자 명령이 기기 하나를 받아들이며 한 번만 보여 주는 한 줄이고, 모양은 `<기기 이름>:<열쇠>`입니다.
- **동기화 한 번**: 기기가 바뀐 파일을 서버에 보내고, 다른 기기가 바꾼 파일을 서버에서 받는 일 한 번을 말합니다. 각 기기의 서비스가 20초마다 한 번 합니다.
- **로그인(계정)**: 동기화 서버에 둔 이름과 비밀번호입니다. 한 사람이 하나를 씁니다. Windows 계정과는 다른 것입니다. PC는 이 이름과 비밀번호로 서버에 붙고(5장), 각 PC의 Windows 계정이 한 번 로그인하면 그 계정의 접근 허용, 걸린 차단, AI 사용량이 로그인을 따라갑니다(7장).
- **회원가입**: 계정이 하나도 없는 서버에 첫 계정을 만드는 일입니다. 서버를 만들거나 처음부터 다시 만든 뒤 한 PC에서 한 번 합니다.
- **관리자 승인**: Windows가 관리자 비밀번호를 묻는 창(UAC)에서 승인하는 것입니다. 회원가입과 로그인은 관리자 승인이 있어야 합니다.
- **계정 키**: 비밀번호에서 만든, 되돌릴 수 없는 값입니다. 비밀번호 자체는 PC 밖으로 나가지 않고, 서버와 PC는 이 값으로 로그인을 확인합니다.

## 2. 무엇이 같아지는가

다음 파일은 모든 기기에서 같아집니다.

- 설정: `policy.json`(항상 막을 프로그램과 웹사이트), `ai_focus.json`(AI 검사 설정. Anthropic API 키는 빼고), `planner.json`(할 일 목록, 약속, 생활 규칙, AI 지시문)
- 설정 보호: `settings_protection.json`(보호가 켜졌는지), `settings_reservations.json`(예약된 설정 업데이트와 그 확인 답. API 키를 바꾸는 업데이트는 빼고)
- 지금 할 일과 기록: `planner_state.json`(지금 할 일, 사용 중지, 끝낸 일, 변경 요청 기록)
- 로그인(또는 로그인하지 않은 Windows 계정)마다 하나씩 있는 파일: `grants\<로그인>.json`(AI가 준 접근 허용), `blocks\<로그인>.json`(걸린 차단)
- 로그인 목록: `users.json`(이름과 비밀번호의 해시). 서버만 쓰고, 기기는 받기만 합니다.

다음 파일은 기기마다 따로 남습니다.

- `usage\<계정>.json`(AI 사용량): 각 기기는 자기 사용량만 보냅니다. 다른 기기의 사용량은 `usage\<기기>~<계정>.json`으로 받아 둡니다. 그래서 통계 탭의 AI 비용과 하루 예산은 모든 기기의 합계를 셉니다.
- **Anthropic API 키**는 PC마다 따로입니다. 키는 서버로 보내지 않고, 서버의 설정을 받을 때에도 그 PC의 키는 그대로 남습니다. 설정이 보호된 뒤 API 키를 바꾸는 예약된 업데이트도 그 PC에만 있고, 그 PC에서 확인 질문에 답합니다. 그러니 새 PC를 서버에 붙인 뒤에는 그 PC의 설정 탭에서 키를 넣어야 합니다.
- `machine.json`(이 PC에서 관리할 계정), `logins.json`(이 PC의 Windows 계정이 어느 로그인을 쓰는지), 로그, 모델 목록, 시간대와 업데이트 기록은 PC마다 다르므로 동기화하지 않습니다.

Claude API는 지금처럼 각 기기가 직접 부릅니다. 서버는 Claude와 통신하지 않습니다. 하루 예산은 모든 PC의 AI 비용을 더해서 셉니다.

## 3. 사용자가 서버의 내용을 바꾸지 못하는 이유

- 서버의 파일은 `C:\ProgramData\DigitalWellbeingSync`에 있고, 이 폴더는 SYSTEM과 관리자만 읽고 쓸 수 있습니다. 서버 프로그램은 `C:\Program Files\DigitalWellbeingSync`에 있고, 관리자만 바꿀 수 있습니다. 서버 서비스를 끄는 것도 관리자만 할 수 있습니다.
- 기기의 열쇠와 계정 키는 각 기기의 `C:\ProgramData\DigitalWellbeing\sync.json`에 있고, 이 폴더도 SYSTEM과 관리자만 읽을 수 있습니다. 열쇠가 없으면 서버에 아무것도 보낼 수 없습니다.
- **계정의 비밀번호를 아는 사람은 새 기기를 로그인시킬 수 있고**, 그 기기로 설정을 바꿀 수 있습니다. 그러니 이 비밀번호는 관리자 비밀번호처럼 종이에 적어 따로 보관하고, 평소에 외우지 않을 만큼 긴 것으로 정합니다. 서버는 한 이름의 로그인이 15분 안에 5번 틀리면 그 이름의 로그인을 15분 동안 받지 않으므로, 인터넷에서 비밀번호를 하나씩 넣어 보며 맞히기는 어렵습니다. 열쇠가 틀리거나, 메시지가 한 글자라도 바뀌거나, 예전 메시지를 다시 보내면 서버는 거절합니다. 거꾸로 기기도 지금 보낸 요청에 대한 서버의 답만 받습니다. 그래서 누가 예전 답을 저장해 두었다가 다시 보내도, 기기는 그 답에 든 예전 설정을 받지 않습니다.
- 서버는 정해진 파일만 받습니다. 한 기기는 다른 기기의 사용량 파일과 로그인 목록을 쓸 수 없습니다. 로그인은 서버의 관리자만 만들고 지웁니다.
- 설정 보호는 보호할 때 고른 방법으로만 풀립니다. 서버와 기기 모두 같은 규칙을 지킵니다.
  - **영구** 보호를 끄는 변경은 서버가 받지 않고, 기기도 받지 않습니다.
  - **기간** 보호를 끄는 변경은 그 기간이 끝난 뒤에만 받습니다.
  - **관리자 권한**과 **비밀번호** 보호는, 한 기기에서 그 방법으로 풀면(그 기기의 서비스가 관리자 권한이나 비밀번호를 확인합니다) 모든 기기에서 풀립니다. 그러면 모든 기기의 걸린 차단도 풀립니다.
  - **관리자 권한** 보호는 보호할 때 "어느 컴퓨터의 관리자가 풀 수 있나"를 고를 수 있습니다(기본값은 보호하는 컴퓨터). 예를 들어 "desktop"을 고르면, desktop에서 desktop의 관리자 승인으로만 풀립니다. 다른 컴퓨터에서는 버튼이 나오지 않고, 서버도 다른 컴퓨터가 보낸 "보호 풀림"을 받지 않습니다. "아무 컴퓨터"를 고르면 어느 컴퓨터든 그 컴퓨터의 관리자가 풀 수 있습니다. 고른 컴퓨터를 동기화에서 빼면(`sync-remove-device`) 그 보호는 풀 수 없게 됩니다.
  - 보호가 켜진 동안에는 푸는 방법을 바꾸는 변경도 서버가 받지 않습니다.
  - 받지 않은 기기는 다음 동기화에서 서버의 보호된 설정을 다시 받고, 보호된 기기는 자기의 보호된 설정을 서버에 다시 보냅니다.
- 서버는 한 번에 32개까지의 요청만 받고, 요청의 첫 부분(요청 줄과 헤더)은 16KB까지만 읽습니다. 그래서 포트를 인터넷에 열어도, 누가 연결을 잔뜩 열거나 끝없는 요청을 보내 서버 PC의 메모리를 다 쓰게 할 수 없습니다.
- 각 기기는 지금처럼 설정 보호의 규칙(더 엄격한 변경은 바로, 그 밖의 변경은 예약과 세 번의 확인)을 지킨 뒤에만 파일을 바꿉니다. 그래서 동기화는 규칙을 피하는 길이 되지 않습니다.

## 4. 서버 설치하기 (Windows)

서버 PC가 정해지면, 그 PC에서 다음 순서로 설치합니다.

1. 서버 PC에 `digital-wellbeing-service.exe`를 준비합니다. 서버 PC에 이 프로그램이 이미 설치되어 있으면 `C:\Program Files\DigitalWellbeing\digital-wellbeing-service.exe`를 쓰면 됩니다. 설치되어 있지 않으면 GitHub 릴리스 페이지에서 `…-windows-x64.zip`을 내려받아 풀고, 그 안의 `digital-wellbeing-service.exe`를 씁니다.
2. 관리자 터미널을 열고 다음 명령을 실행합니다. 경로는 1번에서 준비한 파일의 경로입니다.

   ```
   "C:\Program Files\DigitalWellbeing\digital-wellbeing-service.exe" sync-server-setup
   ```

   이 명령은 다음 일을 합니다.
   - 프로그램을 `C:\Program Files\DigitalWellbeingSync`에 복사하고, 관리자만 바꿀 수 있게 잠급니다.
   - `C:\ProgramData\DigitalWellbeingSync`를 만들고, SYSTEM과 관리자만 열 수 있게 잠급니다.
   - `DigitalWellbeingSync`라는 Windows 서비스를 등록합니다. 이 서비스는 PC가 켜질 때 저절로 시작하고, 멈추면 다시 시작합니다.
   - Windows 방화벽에서 47820번 포트를 엽니다. 다른 포트를 쓰려면 명령 끝에 `--port 50000`처럼 붙입니다.
3. 서버 PC의 주소를 알아 둡니다. 같은 집이나 같은 공유기 안의 기기만 동기화한다면, 서버 PC에서 `ipconfig`를 실행하고 "IPv4 주소"(예: `192.168.0.10`)를 적어 둡니다. 공유기는 이 주소가 바뀌지 않게 "고정 IP(DHCP 예약)"로 정해 두는 것이 좋습니다.
4. 집 밖의 기기(예: 학교에 가져가는 노트북)도 동기화하려면 둘 중 하나가 필요합니다.
   - Tailscale 같은 VPN을 서버 PC와 그 기기에 설치합니다. 그러면 VPN이 주는 주소(예: `100.x.x.x`)로 서버에 닿습니다. 포트를 인터넷에 열지 않아도 되므로 이 방법을 권합니다.
   - 공유기에서 47820번 포트를 서버 PC로 넘기는 "포트 포워딩"을 설정합니다. 메시지는 암호화되어 있지만, 서버가 인터넷 전체에 보이게 됩니다.
5. 각 PC에서 회원가입하거나 로그인합니다(5장).

서버 PC의 시계는 기기들의 시계와 10분 넘게 다르면 안 됩니다. Windows의 "자동으로 시간 설정"을 켜 두면 됩니다.

서버를 없애려면 관리자 터미널에서 `sc stop DigitalWellbeingSync`와 `sc delete DigitalWellbeingSync`를 실행하고, 두 폴더를 지웁니다.

### 클라우드 서버로 쓸 때 (권장: 24시간 켜 두기)

이 절에서 **클라우드 서버**는 클라우드 회사가 빌려주는 리눅스 컴퓨터를 말합니다. 집의 PC와 달리 꺼지지 않으므로, 동기화 서버를 24시간 두기에 알맞습니다. 이 프로그램의 서버는 한 사람이 기기 10대쯤으로 쓰기에 아주 작은 컴퓨터로 충분합니다. 서버는 한 번에 16개까지의 요청만 받는데, 기기마다 20초에 한 번 1초도 걸리지 않는 요청을 보내므로 넉넉합니다.

**권장: AWS Lightsail의 서울 리전, 가장 작은 리눅스 요금제.** 이유는 다음과 같습니다.
- 요금이 월 정액이고(가장 작은 요금제가 월 몇 달러), 고정 IP가 무료입니다(인스턴스에 붙어 있는 동안).
- 서울 리전이 있어 한국에서 빠릅니다.
- 자동 스냅샷(매일 백업)을 켤 수 있습니다.
- 무료 요금제(예: Oracle Cloud의 Always Free)는 쓰지 않는 것이 좋습니다. 이 서버처럼 CPU를 거의 쓰지 않는 인스턴스는 "놀고 있다"고 회수될 수 있기 때문입니다.

**1. 서버 만들기 (AWS 콘솔)**
1. AWS 계정을 만들고, 루트 계정에 MFA(두 번째 인증)를 켭니다.
2. Lightsail → 인스턴스 생성: 리전 **서울(ap-northeast-2)**, 플랫폼 **Linux/Unix**, 블루프린트 **OS 전용 → Ubuntu 24.04 LTS**, 요금제는 IPv4가 있는 가장 작은 것을 고릅니다.
3. 네트워킹 탭: **고정 IP**를 만들어 이 인스턴스에 붙입니다. 이 주소가 서버 주소입니다(예: `3.35.x.x`).
4. 네트워킹 탭 → IPv4 방화벽: **사용자 지정, TCP, 47820** 규칙을 더합니다. SSH(22)는 "Lightsail 브라우저 SSH/RDP만 허용"으로 좁힙니다.
5. 스냅샷 탭: **자동 스냅샷**을 켭니다.

**2. 서버 프로그램 받기와 켜기 (서버의 브라우저 SSH에서)**

이 저장소는 공개되어 있으므로, 서버가 GitHub 릴리스 `sync-latest`에서 바로 받을 수 있습니다. 이 릴리스에는 동기화 브랜치의 테스트를 모두 통과한 최신 빌드만 올라옵니다. Lightsail의 "SSH를 사용하여 연결"(브라우저 SSH)에서 다음을 실행합니다.

```
cd /tmp
base=https://github.com/KomaSeo/Digital_Wellbeing_Extensible/releases/download/sync-latest
for file in digital-wellbeing-service digital-wellbeing-service.sha256 digital-wellbeing-sync.service \
            digital-wellbeing-sync-update digital-wellbeing-sync-update.service digital-wellbeing-sync-update.timer; do
  curl -fsSLO "$base/$file"
done
sha256sum -c digital-wellbeing-service.sha256
sudo install -m 755 digital-wellbeing-service digital-wellbeing-sync-update /usr/local/bin/
sudo install -m 644 digital-wellbeing-sync.service digital-wellbeing-sync-update.service digital-wellbeing-sync-update.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now digital-wellbeing-sync digital-wellbeing-sync-update.timer
systemctl status digital-wellbeing-sync
```

**3. (예전 방법) PC에서 올리기**

GitHub Actions의 artifact `digital-wellbeing-sync-server-linux-x64`를 받아 `scp`로 올려도 됩니다. 그때도 서버에서는 위의 `install`과 `systemctl` 줄을 실행합니다.

서버 서비스는 서버가 켜질 때 저절로 시작하고, 멈추면 5초 뒤에 다시 시작합니다. 문서와 기기 열쇠는 `/var/lib/digital-wellbeing-sync`에 있고, root만 읽을 수 있습니다.

**4. 회원가입과 로그인 (각 PC에서, 5장)**

서버에서 할 일은 여기까지입니다. 가장 잘 설정해 둔 PC의 Focus 앱에서 고정 IP(또는 도메인)와 포트(예: `3.35.0.1:47820`)로 회원가입하고, 다른 PC에서는 같은 이름과 비밀번호로 로그인합니다.

**서버를 처음부터 다시 만들 때**는 `/var/lib/digital-wellbeing-sync` 폴더를 지우고(`sudo systemctl stop digital-wellbeing-sync`, `sudo rm -rf /var/lib/digital-wellbeing-sync`, `sudo systemctl start digital-wellbeing-sync`) 한 PC에서 다시 회원가입합니다. 나머지 PC는 다음 동기화에서 "서버가 이 기기를 모른다"는 답을 받고, 간직한 계정 키로 저절로 다시 로그인한 뒤 서버의 상태를 받습니다. 그러니 다시 회원가입할 때에도 이전과 같은 이름과 비밀번호를 씁니다.

**운영**
- 기록 보기: `journalctl -u digital-wellbeing-sync -f`
- **자동 업데이트:** `digital-wellbeing-sync-update.timer`가 날마다 한국 시간 새벽 4시 30분쯤(10분 안에서 무작위로) 릴리스 `sync-latest`를 확인합니다. 그 사이 서버가 꺼져 있었으면 켜진 뒤에 확인합니다.
  - 받은 파일의 SHA-256이 릴리스에 함께 올린 값과 다르면(받다가 끊기거나 깨지면) 설치하지 않습니다.
  - 지금 설치된 파일과 같으면 아무것도 하지 않습니다.
  - 새 빌드를 설치하고 서버를 다시 시작한 뒤 30초 안에 서버가 답하지 않으면, 예전 빌드를 다시 설치합니다. 그래서 업데이트가 서버를 멈춘 채로 두지 않습니다.
  - 지금 바로 업데이트하려면 `sudo systemctl start digital-wellbeing-sync-update`, 결과는 `journalctl -u digital-wellbeing-sync-update`로 봅니다.
  - 자동 업데이트를 끄려면 `sudo systemctl disable --now digital-wellbeing-sync-update.timer`.
  - 서버의 버전은 PC의 버전과 비교하지 않습니다(8장의 버전 맞추기는 PC끼리입니다). 그래서 서버가 먼저 업데이트되어도 PC들은 그대로 동기화합니다.
- 이 릴리스를 바꿀 수 있는 사람(저장소에 push할 수 있는 사람)은 서버의 프로그램을 바꿀 수 있습니다. 자동 업데이트를 쓰면 GitHub 계정도 관리자 비밀번호처럼 지켜야 합니다.
- 백업: 자동 스냅샷이 매일 서버 전체를 남깁니다.

**서버의 내용을 마음대로 바꾸지 못하게 하려면** 클라우드에서는 AWS 계정이 "관리자 비밀번호"입니다. AWS 계정의 비밀번호와 MFA 장치, 그리고 SSH 키(`.pem` 파일)를 관리자 비밀번호처럼 물리적으로 따로 보관하고, PC에 남은 `.pem` 파일은 지웁니다. 이것들이 있는 사람은 서버의 파일을 바꿀 수 있습니다.

### 리눅스 PC를 서버로 쓸 때

위의 3번과 같습니다. `digital-wellbeing-sync.service`를 설치해 systemd 서비스로 돌립니다. 터미널에서 잠깐 돌려 보려면 `sudo digital-wellbeing-service sync-serve --port 47820`을 씁니다.

## 5. 기기 붙이기: 회원가입과 로그인

PC를 서버에 붙이는 일은 Focus 앱에서 합니다. 서버에서 따로 할 일은 없습니다.

설치한 뒤 Focus 앱을 처음 열면, 아직 서버에 붙지 않은 PC에서는 **첫 화면**이 "이 PC를 여러 기기 동기화 서버에 붙일까요?"입니다. 첫 화면에서 아래의 회원가입이나 로그인을 바로 할 수 있고, **나중에 (동기화 없이 쓰기)**를 누르면 다시 묻지 않습니다. 나중에 붙이려면 설정 탭 맨 위의 같은 칸을 씁니다. 첫 화면에 답했다는 기록은 각 Windows 계정의 `AppData\Local\DigitalWellbeing`에 있으므로, 사용자 정보를 지우고 다시 설치하면 첫 화면이 다시 나옵니다.

1. **첫 PC(회원가입)**: 가장 잘 설정해 둔 PC의 Focus 앱에서 설정 탭 맨 위의 "여러 기기 동기화: 서버에 로그인하거나 회원가입하기"를 엽니다. 서버 주소(예: `3.35.0.1:47820`), 이름(예: `me`), 비밀번호(8자 이상)와 비밀번호 확인을 넣고 **회원가입 (관리자 승인)**을 누릅니다. Windows가 관리자 승인을 물으면 관리자 비밀번호를 넣습니다.
   - 회원가입은 계정이 없는 서버에서만 됩니다. 계정이 이미 있으면 서버가 "이 서버에는 이미 계정이 있습니다"라고 답합니다. 그래서 서버를 만든 사람(첫 회원가입을 한 사람)만 그 서버를 씁니다.
   - 회원가입을 하면 서버가 계정을 만들고, 이 PC를 기기로 받고, 이 Windows 계정을 그 로그인으로 로그인시킵니다.
2. **다른 PC(로그인)**: 같은 곳에서 같은 서버 주소, 이름, 비밀번호를 넣고 **로그인 (관리자 승인)**을 누릅니다. 서버가 이 PC를 기기로 받고, 이 PC의 이름(Windows의 컴퓨터 이름)을 기기 이름으로 씁니다.
3. 20초 안에 첫 동기화가 일어납니다. Focus 앱의 설정 탭 "기기 동기화"에서 마지막 동기화 시각을 확인할 수 있습니다.

관리자 터미널에서 같은 일을 할 수도 있습니다. 명령은 비밀번호를 묻습니다(입력한 글자는 보이지 않습니다). `--for <Windows 계정>`을 붙이면 그 Windows 계정도 로그인시킵니다.

```
"C:\Program Files\DigitalWellbeing\digital-wellbeing-service.exe" sync-signup 3.35.0.1:47820 me --for work
"C:\Program Files\DigitalWellbeing\digital-wellbeing-service.exe" sync-login 3.35.0.1:47820 me --for work
```

비밀번호 자체는 PC 밖으로 나가지 않습니다. PC는 비밀번호로 계정 키를 만들어 로그인 요청을 암호화하고, 서버는 계정 키로 그 요청을 열 수 있을 때만 이 PC에 새 열쇠를 줍니다. 회원가입 때에는 서버가 아직 계정 키를 모르므로, PC와 서버가 그 자리에서 한 번만 쓰는 비밀 값을 정해(X25519) 계정 키를 암호화해 보냅니다. PC는 계정 키를 `sync.json`에 간직하고, 서버가 이 기기를 모르게 되면(서버를 다시 만들면) 그 키로 저절로 다시 로그인합니다.

**잃어버린 기기**: 서버에서 `sync-remove-device <기기>`로 빼고, `sync-add-user <이름>`으로 비밀번호를 바꿉니다. 비밀번호를 바꾸지 않으면, 그 기기가 간직한 계정 키로 다시 로그인할 수 있습니다. 비밀번호를 바꾼 뒤에는 다른 PC도 새 비밀번호로 한 번씩 다시 로그인합니다.

**짝 코드로 붙이기(예전 방법)**: 서버의 관리자 터미널에서 `sync-add-device laptop`을 실행하면 짝 코드가 들어간 `sync-join` 명령 한 줄이 한 번만 나옵니다. 그 PC의 관리자 터미널에서 서버 주소를 넣어 그 줄을 실행합니다. 이렇게 붙인 PC는 계정 키가 없으므로, 서버를 다시 만들면 다시 짝지어야 합니다.

첫 동기화의 규칙은 다음과 같습니다.

- 서버에 아직 아무것도 없으면(처음 붙인 기기), 그 기기의 파일이 서버로 올라갑니다. 그러므로 **가장 잘 설정해 둔 기기에서 회원가입합니다.**
- 서버에 이미 파일이 있으면, 새로 붙인 기기(또는 다시 로그인한 기기)의 같은 파일은 서버의 것으로 바뀝니다. 서버에 없는 파일(예: 그 기기에만 있는 계정의 접근 허용)은 서버로 올라갑니다.

그 밖의 명령은 다음과 같습니다.

| 명령 | 어디서 | 하는 일 |
|---|---|---|
| `sync-devices` | 서버 PC, 관리자 | 서버에 붙은 기기와 마지막 동기화 시각을 보여 줍니다 |
| `sync-remove-device <기기>` | 서버 PC, 관리자 | 그 기기가 더는 동기화하지 못하게 합니다(노트북을 잃어버렸을 때) |
| `sync-add-user <이름>` | 서버 PC, 관리자 | 로그인을 만듭니다. 비밀번호를 두 번 묻습니다(입력한 글자는 보이지 않습니다). 이미 있는 이름이면 비밀번호를 바꿉니다. 이 기능 전에 만든 로그인은 여기서 비밀번호를 한 번 다시 정해야 PC가 그 로그인으로 서버에 붙을 수 있습니다 |
| `sync-users` | 서버 PC, 관리자 | 로그인 목록을 보여 줍니다 |
| `sync-remove-user <이름>` | 서버 PC, 관리자 | 로그인을 지웁니다. 그 로그인을 쓰던 계정은 다시 로그인해야 합니다 |
| `sync-status` | 기기 | 이 기기의 마지막 동기화와 오류를 보여 줍니다 |
| `sync-now` | 기기, 관리자 | 20초를 기다리지 않고 지금 한 번 동기화합니다 |
| `sync-signup <서버 주소> <이름>` / `sync-login <서버 주소> <이름>` | 기기, 관리자 | 회원가입하거나 로그인해서 이 기기를 붙입니다(위의 설명) |
| `sync-leave` | 기기, 관리자 | 이 기기의 동기화를 멈춥니다. 파일은 그대로 남습니다. 설정이 보호되어 있는 동안에는 되지 않습니다 |

## 6. 두 기기가 같은 것을 동시에 바꾸면

- 두 기기가 서로 다른 것을 바꾸면(예: 노트북은 할 일 A를 고치고, 데스크톱은 할 일 B를 더하면), 둘 다 남습니다. 할 일, 약속, 기록처럼 목록인 것은 항목마다 합쳐집니다.
- 두 기기가 같은 값을 다르게 바꾸면, 서버에 먼저 닿은 쪽이 이깁니다.
- "지금 할 일"은 통째로 한쪽이 이깁니다. 한 기기의 할 일과 다른 기기의 끝나는 시각이 섞이지 않게 하기 위해서입니다.
- 한 기기에서 할 일을 받거나, 끝냈다고 보고하거나, 사용 중지를 누르면, 다른 기기도 다음 동기화 뒤 몇 초 안에 같은 상태가 됩니다. 그러므로 두 기기의 상태가 같아지기까지 최대 40초쯤 걸릴 수 있습니다.

## 7. 로그인

접근 허용과 걸린 차단은 원래 Windows 계정 이름마다 따로입니다. 그래서 두 PC의 계정 이름이 다르면 공유되지 않습니다. 로그인은 이 문제를 풉니다.

1. 회원가입하거나 로그인한 Windows 계정(5장)은 그때 함께 로그인됩니다.
2. 같은 PC의 다른 Windows 계정은 동기화가 로그인 목록을 받아 온 뒤 Focus 앱 맨 위에 로그인 칸이 뜹니다. 이름과 비밀번호를 넣고 **로그인 (관리자 승인)**을 누릅니다. 이 PC가 이미 그 계정으로 서버에 붙어 있으면, 서버에 묻지 않고 이 PC가 간직한 계정 키로 비밀번호를 확인합니다. 이 일은 PC마다, Windows 계정마다 한 번만 합니다.
3. 로그인하면 그 계정의 agent가 몇 초 안에 다시 시작하고, 그때부터 `grants\me.json`, `blocks\me.json`, `usage\me.json`을 씁니다. 그래서 어느 PC의 어느 Windows 계정이든 같은 접근 허용과 차단을 씁니다.

- 로그인에는 관리자 승인이 있어야 합니다. 관리자 승인은 관리자 비밀번호를 아는 사람만 할 수 있습니다.
- **설정이 보호되어 있는 동안에는 로그아웃할 수 없습니다.** 로그아웃해서 공유된 차단과 접근 허용을 벗어나지 못하게 하기 위해서입니다. 설정 탭 맨 위에 어느 로그인을 쓰는지가 나오고, 로그아웃 버튼은 설정이 보호되지 않았을 때만 나옵니다. 같은 이유로 보호되어 있는 동안에는 `sync-leave`도 되지 않습니다.
- 설정이 보호된 뒤에는, 로그인 목록이 있는데 로그인하지 않은 계정은 로그인할 때까지 모든 앱과 웹사이트가 잠깁니다. 로그인하지 않는 것으로 공유된 차단을 피하지 못하게 하기 위해서입니다. 설정 단계에서는 잠기지 않습니다.
- 비밀번호는 서버와 각 PC에 해시와 계정 키(둘 다 되돌릴 수 없는 값)로만 저장됩니다.

## 8. 버전 맞추기

모든 PC는 같은 버전을 써야 합니다. 옛 버전은 새 버전이 더한 설정 칸을 모르고, 파일을 다시 쓸 때 그 칸을 지울 수 있기 때문입니다.

- 서버는 PC마다 마지막으로 동기화한 버전을 기억합니다. 어떤 PC가 다른 PC보다 옛 버전이면, 서버는 그 PC의 동기화를 받지 않습니다. 그 PC는 혼자서 지금처럼 동작하고, 설정 탭의 "기기 동기화"에 "이 PC의 프로그램이 다른 PC보다 오래되어 동기화를 멈췄습니다"와 릴리스 페이지 링크가 나옵니다. 그 PC를 업데이트하면 다음 동기화부터 다시 맞춰집니다.
- 새 버전의 PC에서는 설정 탭의 "기기 동기화"에 업데이트해야 하는 다른 PC의 이름과 버전이 나옵니다. `sync-devices`도 PC마다 버전을 보여 줍니다.
- 그러니 새 버전이 나오면 모든 PC를 같은 날 업데이트하는 것이 좋습니다.

## 9. 알아 둘 것

- 서버가 꺼져 있거나 닿지 않아도 각 기기는 혼자서 지금처럼 동작합니다. 서버에 다시 닿으면 그동안의 변경이 합쳐집니다.
- Anthropic API 키는 서버에 저장되지 않습니다(2장).
