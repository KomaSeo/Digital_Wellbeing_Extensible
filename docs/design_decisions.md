# 설계 결정 기록

이 문서는 기능마다 **누가 그 기능을 정했는지**와 **왜 그렇게 정했는지**를 남깁니다.
나중에 "이거 내가 지시한 건가, 아니면 AI가 알아서 넣은 건가?", "왜 이렇게 만들었지?"를 판단할 때 이 문서를 봅니다.

---

## 0. 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| **소유자** | 이 프로그램을 쓰고, 기능을 요청하는 사람입니다. |
| **AI** | 소유자의 요청을 받아 코드를 쓰는 Claude(개발 도우미)입니다. 프로그램 안에서 판정하는 AI와는 다릅니다. |
| **소유자 요청** | 소유자가 대화에서 직접 말한 것입니다. 원문을 따옴표로 옮깁니다. |
| **소유자가 말한 이유** | 소유자가 요청하면서 직접 밝힌 이유입니다. 소유자가 이유를 말하지 않았으면 "(말하지 않음)"이라고 적습니다. |
| **AI가 정한 세부** | 소유자가 정하지 않아서 AI가 정한 값과 방식입니다. 소유자가 나중에 바꿔도 되는 부분입니다. |
| **질문으로 정함** | AI가 선택지를 물었고 소유자가 고른 것입니다. 소유자 요청과 같은 무게입니다. |

**규칙:** 새 기능이나 동작 변경을 만들 때마다, AI는 이 문서 끝에 항목을 하나 추가합니다(`CLAUDE.md`).

## 1. 차단과 AI 판정

### 1.1 YouTube는 채널 단위로 막는다
- **소유자 요청:** "영상 설명은 일단 빼고 시작하자. 그리고, AI가 채널 단위로 막도록 하고, youtube만 일단 특별 취급하도록 해"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** 채널 이름은 AI가 화면에서 읽습니다. 채널을 모르면 페이지(영상 제목) 단위로 막습니다. YouTube Music은 제외합니다.

### 1.2 탭은 첫 판정에서 바로 막는다
- **소유자 요청:** "지금 생각난 건데 굳이 경고가 필요한가?"
- **소유자가 말한 이유:** (질문 형태) 경고를 기다리는 동안 딴짓을 계속할 수 있다.
- **AI가 정한 세부:** 브라우저 탭은 첫 `off_task` 판정에서 닫고, 앱(프로그램)은 지금처럼 경고 횟수(`strikes_to_block`)를 채운 뒤 끕니다. 앱은 잘못 끄면 작업을 잃을 수 있어서 AI가 경고를 남겼습니다.

### 1.3 차단은 시간이 지나도 풀리지 않는다
- **소유자 요청:** "차단이 정해진 시간이 지나면 풀리게 만드는 것도 이상하다. 사용자가 필요하면 어련히 접근을 요청하겠지."
- **소유자가 말한 이유:** "이는 같은 웹 사이트나 앱을 여러번 검사하게 만드니 경제적이지도 않아."
- **AI가 정한 세부:** 차단마다 고유 ID를 붙이고, 접근 요청 승인이나 Settings 탭의 unblock으로만 풉니다.

### 1.4 판정을 일정 시간 믿고, 관리자가 차단을 풀 수 있다
- **소유자 요청:** "판정 기록이 있으면 일정 기간동안 판정 안하는 정도로 줄이자. 지금처럼 모든 검사 간격에 다시 검사할 필요는 없으니. 관리자가 차단을 푸는 방법도 만들어둬."
- **AI가 정한 세부:** 할 일에 맞는 창은 15분(`recheck_minutes`), 애매한 창은 60초 뒤 다시 판정합니다. API 호출이 실패하면 60초 쉽니다.

### 1.5 열린 탭과 프로그램을 모두 판정한다
- **소유자 요청:** "지금 열려있는 탭 모두 + 지금 켜져있는 프로그램 모두를 전달하도록. 이미지를 모두 전달할 필요 없이 웹사이트는 웹 사이트 제목, 그리고 앱의 경우에는 앱 이름만 전달하면 된다."
- **AI가 정한 세부:** 화면 캡처는 맨 앞 창만 보냅니다. 뒤쪽의 딴짓 탭은 바로 차단하고, 화면에 보이면 포커스를 빼앗지 않고 최소화합니다. 탭은 그 창을 앞으로 가져올 때 닫습니다.

### 1.6 새 앱과 사이트는 바로 판정하고, 일정 시간 뒤 다시 본다
- **소유자 요청:** "1. 지금 올라가 있는 할 일에 부합하는지 판정 기록이 없는 웹사이트, 앱이 켜졌을 경우 이를 감지하여 바로 AI에게 판단을 맡긴다. 2. 마지막 판정으로부터 일정 시간이 지나면 해당 웹사이트나 앱을 다시 검사한다."
- **소유자가 말한 이유:** "잠깐 잠깐 웹사이트나 앱을 쓰는 것도 좀 이상하군."
- **AI가 정한 세부:** 3초마다 확인합니다. 무작위 정기 검사와 "10초 머문 창부터 검사" 규칙은 뺐습니다.

### 1.7 토큰 사용량 추적
- **소유자 요청:** "token 잔량이 얼마나 남아있는지 track할 수 있나?", "토큰 사용량 추적도 만들어줘"
- **AI가 정한 세부:** 잔량은 API로 알 수 없어서 사용량과 예상 비용을 기록합니다. **하루 예산**(다 쓰면 창 검사를 멈춤)은 AI가 덧붙인 기능입니다.

## 2. 설치, 계정, 실행

### 2.1 관리자/표준 계정을 프로그램에서 나누지 않는다
- **소유자 요청:** "관리자와 관리자 아님 계정을 프로그램에서 분리하기 보다, 관리자 계정으로 프로그램을 실행시켜서 다른 계정이 이 프로그램을 끌 수 없게 만들자."
- **소유자가 말한 이유:** "어차피 지정한 기간이 지나면 관리 화면을 풀 수 있으니까."
- **질문으로 정함:** 작업은 표준 계정에서 한다. 관리자용 설정 창은 없애고 하나로 통일하며, 비상 해제는 없다.
- **AI가 정한 세부:** 서비스(SYSTEM)가 사용자 세션마다 agent를 띄우는 구조, 데이터 폴더 권한(SYSTEM과 Administrators만).

### 2.2 관리자 계정도 관리하고, 서비스는 설치와 함께 깔려 부팅 때 시작한다
- **소유자 요청:** "관리자 계정도 관리 해줘.", "안되면 같이 설치되게 해주고 컴퓨터 시작될 때 시작되어서 계속 돌게 해줘."
- **AI가 정한 세부:** 설치기의 Work account 칸을 비우면 모든 계정을 관리합니다(`--manage-all`).

### 2.3 트레이 아이콘
- **소유자 요청:** "tray에서 앱을 열 수 있도록 만들어다오."
- **AI가 정한 세부:** 창을 닫으면 트레이로 숨고, 앱을 다시 실행하면 떠 있는 창을 보여 줍니다.

### 2.4 Linux에서도 돌고, 자동 검사(CI)를 한다
- **소유자 요청:** "윈도우 feature과 윈도우가 아닌 feature를 나누어서 리눅스에도 돌아가게 만들고, 너가 말한 것도 하고." (AI가 제안한 Windows 설치 검사 포함)
- **소유자가 말한 이유:** AI가 실제 Windows에서 시험하지 못한다는 점("너가 테스트를 못하고 있다는가지?")
- **AI가 정한 세부:** X11 구현, 가짜 Claude 서버를 쓰는 끝에서 끝까지 테스트, GitHub Actions의 Windows 설치·업데이트·제거 검사.

### 2.5 진짜 Claude API로 시험한다
- **소유자 요청:** "진짜 claude api로 시험하기를 원해. 내 말은 너가 일하고 있는 리눅스 서버에서도 이런일이 가능하냐는거야", "키를 넣어서 돌려볼래?"
- **AI가 정한 세부:** 키(`DW_E2E_ANTHROPIC_API_KEY`)가 있을 때만 도는 테스트, 운영체제 인증서 저장소를 쓰도록 바꾼 HTTPS(`native-certs`).

### 2.6 우회를 막는 추가 설정을 설명서에 적는다
- **소유자 요청:** "BIOS와 안전모드는 막지 못한다고 했지? 그런데 예전에 reddit 찾아보니까 bios는 비밀번호 걸면 되고 안전모드는 window의 어떤 명령어 입력하면 아예 안전모드를 틀 수가 없었다고 했었어 이 두 가지를 설치 설명서에 적어놔."
- **AI가 정한 세부:** 안전 모드를 막는 명령으로 `reagentc /disable`과 `bcdedit` 설정들을 골랐습니다(`multi_account.md` 4.4절). 소유자가 본 Reddit 글의 정확한 명령은 확인하지 못했습니다.

### 2.7 릴리스는 묻지 않고 한다
- **소유자 요청:** "앞으로 그냥 릴리스 해주면 안되나 어차피 나 혼자 쓸 건데"

## 3. 할 일 플래너

### 3.1 Claude Desktop과 연결하되, 추천 지시문은 고정한다
- **소유자 요청:** "PC claude desktop이고 claude docs 같은 게있어. 내가 다소 걱정되는 건, PC의 claude에 도구를 주었다가, 내가 돌고 싶을 때 claude에 "놀기" 같은 걸 줄까봐 걱정이야. 그래서 지금 할 일 추천하는 프롬프트는 고정하고 싶어."
- **소유자가 말한 이유:** 놀고 싶은 순간에 Claude를 통해 계획을 바꿀까 봐.
- **AI가 정한 세부:** MCP 서버의 도구는 Focus 앱이 할 수 있는 일만 합니다. 질문에 답하는 도구는 없습니다.
- **나중에 바뀜:** 지시문은 3.6에서 "보호된 설정"으로 바뀌었습니다.

### 3.2 생활 규칙으로 심사한다
- **소유자 요청:** "AI가 생활 규칙으로 심사해. 애초에 관리자가 나인데, 관리자 비밀번호를 내가 숨겨둘 뿐이라서."

### 3.3 할 일에는 쉬기와 놀기도 들어가고, 중요한 것은 지금 할 일을 정하는 것이다
- **소유자 요청:** "할 일을 내가 AI에게 제안할 때 AI가 받아들이는 건 테스트할 필요 없을 거 같아. "할 일"에는 내가 쉬거나 노는 것도 포함시킬 예정이거든. AI가 필요한 부분은 AI가 내가 지금 무엇을 해야할지 지정해줄 때야."

### 3.4 할 일마다 언제까지 할지 정하고, 시간이 끝나면 다시 고른다
- **소유자 요청:** "자동 재할당으로. 사실 AI랑 상의해서 자동 재할당과 알림만을 정할 수 있으면 좋겠는데"
- **AI가 정한 세부:** AI가 15~240분을 정하고 프로그램이 10~480분 안으로 맞춥니다. "알림만"은 AI가 심사하고, 자동 재할당으로 되돌리는 것은 묻지 않고 승인합니다. 15초마다 확인합니다.

### 3.5 할 일 변경은 AI가 심사하고, 빈 칸은 AI가 채운다
- **소유자 요청:** "제안 양식을 내가 비워두면 AI가 자동으로 그 양식은 채워주면 좋겠어.", "8은 (가)로 하되, AI가 문제가 생길 수 있으니 (나)를 사용할 수 있는 루트도 추가하도록. 단 이건 2시간 단위로 3번 해라."
- **질문으로 정함:** (나) 경로는 AI가 거절했거나 응답하지 못했을 때만 쓸 수 있다.
- **AI가 정한 세부:** 사용자가 적은 칸은 AI가 바꾸지 않습니다. 하루 30건 한도, 수정·삭제에는 4글자 이상의 이유. 하루 계획, 작업 메모, 할 일별 시간 기록은 AI가 제안하고 소유자가 검토한 To-do 탭 항목입니다.

### 3.6 일찍 끝냈을 때: 결과가 분명하면 증거, 아니면 남은 시간에 다듬기
- **소유자 요청:** "AI에게 결과를 입증할 자료를 보여주는 거야. 다만 결과가 decisive한 경우에만 (예를 들면 누군가에게 메일 보내기, 메시지 보내기, 혹은 뭔가 주문하기 등등.) 만약 결과가 decisive하지 않은 데, 언제나 "더 잘"할 수 있는 종류라면 (예를 들면, 보고서 작성, 발표 연습, 시험 준비 등등), 짧게 끝냈을 때 용인하고 넘어가되, 나중에 시간이 남을 때 "더 잘"하도록 리뷰하게 만들려고"
- **소유자가 말한 이유:** "그게 내가 거짓말을 하는 거일 수도 있지. 하기 싫은 일을 강제로 끝내려는 거야."
- **AI가 정한 세부:** 아래 10장에 적습니다.

## 4. 설정과 보호

### 4.1 설정은 잠글 수 있었다 (나중에 바뀜)
- **소유자 요청:** "관리자가 보는 관리 화면을 "잠궈두지" 않았을 때, 다른 유저도 수정할 수 있게 하되, 유저가 일정 기간 잠굴 수 있게 만들어줘"

### 4.2 잠겨 있어도 고칠 수 있지만, 잠금이 끝날 때 적용 (나중에 바뀜)
- **소유자 요청:** "앞으로 관리 tab은 항상 열려있으나, 내가 업데이트를 저장하면 그게 바로 업데이트 되는 게 아니라 락이 끊기는 시점에 업데이트 하게 해줘"
- **소유자가 말한 이유:** "그래서 내가 악의적으로 수정했을 때 즉각적인 보상을 얻지 못하게끔"

### 4.3 업데이트 예약과 이틀 간격 세 번 확인
- **소유자 요청:** "할 일 고르기, 심사 지시문, 생활 규칙과 다른 설정 역시 업데이트 예약은 걸 수 있게 해줘. 실제 업데이트 적용은 이틀 마다 한 번씩 나에게 "정말 이 업데이트가 맞습니까?"를 물어보고 한 번이라도 업데이트 승인을 안하면 리젝, 세 번 모두 연속으로 승인하면 업데이트 적용하도록"
- **소유자가 말한 이유:** "내가 비 이성적일 때 업데이트 결정을 내리지 않도록"
- **질문으로 정함:** 잠금을 없애고 항상 확인한다(설치 직후 설정 단계만 바로 적용). 답하지 않은 질문은 답할 때까지 기다린다. Claude Desktop도 예약할 수 있다.
- **AI가 정한 세부:** 첫 질문은 예약 이틀 뒤, 다음 질문은 답한 때로부터 이틀 뒤. 같은 파일을 다시 저장하면 예약을 대신하고 확인을 처음부터. 예약 취소(Withdraw)는 확인 없이. Claude Desktop은 설정 단계에서는 예약할 수 없음.

### 4.4 빡빡해지는 변경은 바로, 널널해지는 변경은 예약
- **소유자 요청:** "AI 판정은 빡빡해지는 건 바로 수행하고 널널해지는 건 2일 3회 판정으로 들어가라. (ex. always allow를 빼는 건 바로 수행 넣는 건 2일 3회 판정)"
- **질문으로 정함:** 방향을 판단할 수 있는 모든 설정에 적용한다.

## 8. 최근 항목 (새 항목은 이 아래에 추가합니다)

### 8.1 일찍 끝냈을 때의 증거와 다듬기 (3.6의 세부)
- **AI가 정한 세부:**
  - "끝냈다"를 심사할 때 AI는 결과가 **분명한 것**(보냈다, 주문했다, 제출했다, 예약했다)인지 **더 잘할 수 있는 것**(작성, 연습, 공부)인지 판단합니다.
  - 분명한 결과는 증거가 있어야 승인합니다. 증거는 사용자가 적는 글과, 원하면 화면 캡처 한 장입니다. 화면 캡처는 버튼을 누르고 5초 뒤에 찍으므로, 사용자는 그 사이에 증거가 보이는 창으로 바꿉니다.
  - 더 잘할 수 있는 일을 계획보다 일찍 끝내면 승인하고, 남은 시간을 **다듬기 시간**으로 남깁니다. 남은 시간 = 그 할 일에 필요하다고 본 시간(예상 시간, 없으면 이번 할당 시간) − 지금까지 쓴 시간. 10분보다 적으면 남기지 않습니다.
  - 다듬기 시간이 남은 일은 "Improve: …"라는 할 일로 목록에 나옵니다. AI는 급한 일이 없을 때, 쉬기나 놀기보다 먼저 이 일을 고르도록 지시받습니다. 다듬는 데 쓴 시간만큼 다듬기 시간이 줄고, 다 쓰거나 "끝냈다"가 승인되면 목록에서 빠집니다.
  - "Improve: …" 할 일은 앱이 만든 것이므로, 사용자는 To-do 탭에서 이 할 일을 고치거나 지울 수 없습니다.
  - 화면 캡처를 찍을 때 비공개 앱이 화면에 보이면, agent는 캡처하지 않고 요청을 오류로 돌려줍니다. 화면 캡처는 AI에게만 보내고 저장하지 않습니다.
  - Claude Desktop(MCP)으로는 증거 글만 보낼 수 있습니다. Claude Desktop이 요청할 때 맨 앞 창은 Claude Desktop 자신이므로 화면 캡처가 증거가 되지 않기 때문입니다.
- **실제 Claude로 시험한 결과:** AI는 글로 적은 증거만으로는 승인하지 않고 화면 캡처를 요구할 때가 많았습니다. 들인 시간이 0분인데 "보고서를 다 썼다"고 하면, 더 잘할 수 있는 일이어도 믿기 어렵다고 거절했습니다. 개발자는 이 동작이 소유자의 의도(거짓으로 끝내는 것을 막기)에 맞다고 보고 지시문을 그대로 두었습니다.

### 8.2 전체 코드 검토에서 고친 것
- **소유자 요청:** "/code-review high 타겟은 모든 코드."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** AI는 검토에서 찾은 문제 가운데 다음을 고쳤습니다.
  - Improve 할 일을 할 일 변경으로 고치거나 지우려 하면 agent가 거부합니다. 전에는 승인되어도 아무 일이 일어나지 않거나, 같은 id의 할 일이 목록에 둘 생길 수 있었습니다.
  - agent는 설정 파일과 예약된 업데이트를 한 번에 한 요청만 고치게 합니다. 전에는 Focus 앱과 Claude Desktop이 동시에 저장하면 한쪽의 변경이 사라지거나 파일이 깨질 수 있었습니다.
  - agent는 "끝냈다" 요청이 AI에게 갈 수 있는지 먼저 확인한 뒤에 화면 캡처를 기다립니다. 캡처를 못 하면 그 까닭(비공개 앱, 앞에 창 없음)을 알려 줍니다.
  - 예상 시간이 없는 할 일의 다듬기 시간은 이번 할당만으로 계산합니다.
- **처음에 고치지 않은 것:** 거절된 할 일 변경의 예약, Improve 할 일의 기한, 실패한 요청의 증거 칸. 소유자가 이 셋도 고치라고 했습니다(8.3).

### 8.7 설정 탭: 자동 임시 저장, 항목마다 저장과 적용, 기본값으로 되돌리기
- **소유자 요청:** "설정하는 탭은 자동으로 중간 세이브를 하되, save 버튼을 눌러 사용자가 save 되었음을 스스로 알 수 있게 하고, apply 버튼으로 설정할 수 있도록 만들어. 예를 들면 life rule처럼. AI Instructions도 마찬가지. built-in, default 프롬프트나 옵션이 있는 경우 revert to default 같은 버튼 만들도록 하고." 이어서 "save는 각 수정 탭 밑에다가 두렴. 왜냐하면 rules가 길긴 할테니"
- **소유자가 말한 이유:** 생활 규칙이 길어서, 맨 밑의 버튼까지 내려가기 불편하다.
- **AI가 정한 세부:**
  - 고친 내용은 1초 뒤에 사용자 폴더의 `settings_drafts.json`에 자동으로 임시 저장되고, 앱을 다시 켜면 되살아납니다. API 키는 임시 저장하지 않습니다.
  - 설정 묶음(API 키, 모델, 하루 예산, 플래너 켜기, 생활 규칙, 지시문 하나하나, 차단 목록 하나하나, 검사 간격 등)마다 아래에 "저장", "적용", "고친 것 버리기", "기본값으로 되돌리기" 버튼과, 적용하면 바로 적용되는지 예약되는지 미리 보기가 있습니다. "적용"은 그 묶음의 변경만 agent에 보냅니다.
  - "기본값으로 되돌리기"는 프로그램에 기본값이 있는 묶음(모델, 하루 예산, 지시문, 검사 간격, 접근 요청 한도, 검사하지 않는 앱·비공개 앱·브라우저 목록)에만 있습니다. API 키, 생활 규칙, 차단 목록에는 기본값이 없어서 버튼이 없습니다.

### 8.9 항상 막을 프로그램에 정규식, 항상 막을 웹사이트 목록
- **소유자 요청:** "Always bocked programs가 regular expression을 받을 수 있게 하렴. 그리고 프로그램 뿐만 아니라 always blocked website도 추가할 수 있도록 하렴"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - `* + ? ( ) [ ] { } | ^ $ \` 중 하나가 들어간 항목을 정규식으로 봅니다. 점(.)만 있는 `steam.exe`는 이름 그대로입니다. 대소문자는 무시하고, 프로그램 이름 전체가 맞아야 합니다. 잘못된 정규식은 글자 그대로 비교합니다. Windows에 꼭 필요한 프로그램과 이 프로그램 자신은 정규식에 걸려도 끄지 않습니다.
  - 웹사이트는 브라우저 탭의 제목으로 판단합니다. 프로그램은 탭의 주소(URL)를 읽지 못하기 때문입니다. 제목 끝의 브라우저 이름(" - Google Chrome" 등)은 빼고 봅니다. 맞는 탭은 데일리 웰빙이 꺼져 있어도 AI에게 묻지 않고 닫고, 뒤에 있는 창은 최소화합니다. 접근 허용으로도 풀리지 않습니다.

- **AI가 정한 세부:** 주제마다 접을 수 있는 글로 만들었습니다. 첫 주제는 Claude Desktop 연결 방법(설정 내용 복사 버튼 포함), 말하는 예, Claude Desktop으로 할 수 없는 것입니다. 소유자가 사용법을 더 말하면 이 탭에 주제를 더합니다.

### 8.11 지금 할 일은 AI가 정한다
- **소유자 요청:** "TO-DO는 내가 해야할 일을 "추가"하는 장소지 어떤 일을 할지 내가 "결정"하는 장소가 아니야. 그러니 내가 결정하도록 하지 마." 이어서 "결정은 AI가 해야해. 내가 하면 게을러 진다."
- **소유자가 말한 이유:** 사용자가 결정하면 게을러진다.
- **AI가 정한 세부:**
  - 할 일 탭의 "대신 이것 하기" 버튼과 변경 요청의 "다른 할 일", "목록에 없는 일"을 없앴습니다. Claude Desktop의 같은 요청(`switch_todo`, `switch_free`)도 없앴습니다.
  - 대신 "다른 일 받기"(`repick`)를 만들었습니다. 사용자는 이유만 적고, AI가 이유를 심사해 승인하면 AI가 이유를 보고 다음 할 일을 고릅니다. "막혔어요"와 "쉬고 싶어요" 버튼도 이 요청을 씁니다.
  - agent의 요청 자체(`switch_todo`, `switch_free`)는 예전 버전과의 호환을 위해 남겼지만, 어떤 화면이나 도구도 그 요청을 보내지 않습니다.
  - 플래너를 끈 상태(Settings에서 고름)에서는 지금도 사용자가 하는 일을 직접 적습니다. 이것을 없앨지는 소유자에게 묻기로 했습니다.

### 8.12 통계 탭
- **소유자 요청:** "AI Usage와 같이 지난 일에 대한 건 statistics 탭을 따로 만들어 거기에서 확인할 수 있도록 만들어라"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** AI 사용량(설정 탭에서), 오늘의 요약·끝낸 일·요청과 AI의 답(할 일 탭에서), 최근 AI 판정(차단 탭에서)을 통계 탭으로 옮겼습니다. 할 일 탭에는 지금 할 일, 변경 요청, 할 일 목록만 남았습니다.

### 8.13 플래너 끄기를 없앤다
- **소유자 요청:** "응 플래너 끄기 모드 없애줘" (AI가 "플래너를 끄면 지금도 사용자가 하는 일을 직접 적는데, 이것도 없앨까요?"라고 물은 데 대한 답)
- **소유자가 말한 이유:** 8.11과 같습니다. 결정은 AI가 해야 하고, 사용자가 하면 게을러진다.
- **AI가 정한 세부:**
  - 플래너는 언제나 켜져 있습니다. 설정 파일의 `enabled` 값은 무시하고, 예전 파일을 읽을 수 있도록 남겨 두었습니다.
  - 할 일 목록이 비어 있으면 할 일 탭은 할 일을 추가하라고 안내합니다. 사용자가 하는 일을 직접 적는 칸은 없습니다.
  - 예전 버전에서 직접 적은 일이 이어지고 있으면, 할 일이 생긴 뒤 agent가 15초 안에 AI가 고른 할 일로 바꿉니다.
  - "할 일 받기"는 agent가 이미 할 일을 고르는 중이면 그 결과를 기다렸다가 이어 받습니다. 전에는 "다른 요청을 처리하고 있다"는 오류가 났습니다.

### 8.14 앞으로 7일 계획: 일에 써야 할 시간과 여유를 파악한다
- **소유자 요청:** "음 다시 생각해봤는데, 일주일 계획과 하루 계획을 세우는 건 괜찮겠다. 다만 그 목적이 몇 시에 뭐하고 뭐하고 이런 걸 결정해 둔다는 느낌 보다는 이번 주에 몇 시간 일에 써야하고 여유 얼마나 있고 등등을 파악하기 위해서에 가깝게" 이어서, 가용 시간을 어디서 가져올지 묻자 "아. 내가 일에 쓸 수 있는 시간은 이번 주에 일을 해치우기 위해서 내가 들여야 하는 시간으로 결정되는 거니까. 내가 설정하는 건 없고 AI가 추정해야지. 그래서 이번 주 스케쥴을 세워보라는 거야." 그리고 보이는 곳은 "통계 탭"을 골랐습니다.
- **소유자가 말한 이유:** 몇 시에 무엇을 할지 정하는 것이 아니라, 이번 주에 일에 몇 시간을 써야 하고 여유가 얼마나 있는지 파악하기 위해서입니다. 8.6에서 없앤 하루 계획(시간표)과는 목적이 다릅니다.
- **AI가 정한 세부:**
  - 한 주를 월요일부터 일요일까지가 아니라 오늘부터 7일로 봅니다. 처음에는 일요일까지로 만들었는데, 일요일에 시험하니 오늘 하루만 남아 한 주를 볼 수 없었기 때문입니다.
  - AI는 사용자가 버튼을 누를 때만 부릅니다(비용). 하루 계획은 따로 부르지 않고, 7일 계획의 오늘 줄이 하루 계획 역할을 합니다.
  - AI가 날마다 일에 써야 할 시간, 여유, 할 일별 시간, 설명, 요약, 주의할 점을 돌려줍니다. 플래너는 7일 밖의 날과 목록에 없는 할 일을 버리고, 하루를 24시간 안으로 맞추고, 합계를 직접 더합니다.
  - 통계 탭에는 AI 없이 앱이 계산하는 "남은 일"(예상 시간 − 들인 시간을 마감별로 더한 것)도 함께 보여 줍니다.
  - 계획은 지금 할 일을 고르는 데 쓰지 않습니다. 고르기는 지금처럼 그때그때 생활 규칙에 맞춰 합니다.
  - 이 계획의 지시문도 다른 지시문처럼 설정 탭에서 고칠 수 있습니다.

### 8.15 관리자 권한이 필요한 프로그램 업데이트와 시간대 지키기
- **소유자 요청:** "내가 프로그램을 삭제하거나 시간을 조종해서는 안된단 말이지. 그런데 카카오톡 업데이트 같은 곳에는 관리자 권한이 필요해. AI 판단이나 미리 지정해둔 프로그램에 대해 관리자 권한을 일시적으로 부여할 수 있나?" AI가 사용자에게 권한을 주는 대신 서비스가 대신 업데이트하는 방법을 제안하고 요청할 때만·매일·둘 다, 시간대 막기, 만들 브랜치를 묻자 "둘 다 하고 시간대 막기도 넣어서 메인에 만들어줘."
- **소유자가 말한 이유:** 사용자가 프로그램을 지우거나 시간을 조종해서는 안 되지만, 카카오톡 업데이트처럼 관리자 권한이 필요한 일이 있다.
- **AI가 정한 세부:**
  - 사용자에게 관리자 권한을 잠깐이라도 주지 않습니다. 그동안 무엇이든 할 수 있고(이 앱 지우기, 관리자 계정 만들기), 관리자로 띄운 설치 창의 파일 대화상자로도 관리자 명령 창을 열 수 있기 때문입니다. AI 판단으로 권한을 주는 방법도 쓰지 않았습니다. AI는 처음 보는 프로그램이 무엇을 하는지 알 수 없기 때문입니다.
  - 대신 서비스(SYSTEM, 사용자가 볼 수 없는 세션 0)가 설정의 목록(`updatable_programs`, winget 이름)에 있는 프로그램만 `winget upgrade --silent`로 업데이트합니다. 지우기와 새로 설치하기는 하지 않습니다. 목록에 넣기는 느슨한 변경(예약), 빼기는 엄격한 변경(바로)입니다.
  - 요청은 설정 탭의 새 영역 **시스템**의 **지금 업데이트** 버튼으로 합니다. 하루 한 번 저절로 업데이트는 새벽 4시 이후 PC가 켜져 있는 첫 때에 하고, 기본값은 켜짐입니다. 30분이 넘는 업데이트는 멈춥니다.
  - 시간대: 설정에 지킬 시간대(`time_zone`)를 두고, 비어 있으면 서비스가 처음 돌 때의 시간대를 적습니다. 서비스는 5초마다 확인해서 다르면 되돌리고 기록합니다. 지킬 시간대를 바꾸는 것은 느슨한 변경(예약)입니다.
  - Claude Desktop과 AI 비서의 도구(`program_update`)로도 업데이트를 요청할 수 있습니다. 이 도구는 AI 비서 브랜치를 합칠 때 더했습니다(8.17).

### 8.16 AI 연결이 끊기면 모든 앱과 웹사이트를 잠근다
- **소유자 요청:** "생각해보니 API 키를 바꾸거나 원격으로 API Key를 바꾸어서 무력화시킬 수 있군. 이를 대비하여, 만약 API키가 연결이 안되있는 상태 + lock 상태이면 API 연결 전까지 "모든" 앱과 웹사이트를 잠구도록 해." 이어서 "아. 아무래도 API를 다시 연결할 때 필요하니까 claude 웹사이트와 claude desktop앱은 예외 처리 하도록 해."
- **소유자가 말한 이유:** API 키를 바꾸거나 원격으로(Anthropic 웹사이트에서) 키를 무력화해서 AI 검사를 끌 수 있기 때문입니다. Claude 웹사이트와 Claude Desktop은 API를 다시 연결할 때 필요하기 때문에 예외입니다.
- **AI가 정한 세부:**
  - "lock 상태"는 설정이 보호된 상태로 읽었습니다. "연결이 안 된 상태"는 키가 없거나, API가 키를 거부하거나(401·403), 크레딧이나 한도가 없거나, 모델을 모르는 경우로 정했습니다. 네트워크 오류와 과부하는 키 문제가 아니므로 잠그지 않습니다. 그래서 인터넷이 끊겨도 잠기지 않습니다(소유자가 원하면 바꿀 수 있습니다).
  - 끄지 않는 것: Windows에 꼭 필요한 프로그램, Windows 폴더 아래의 프로그램, 이 앱, Claude Desktop(`claude.exe`), Windows 설정(네트워크), 웹 보기, 작업 관리자, 설정의 "검사하지 않는 앱". 브라우저는 끄지 않고, 제목에 Claude나 Anthropic이 든 탭, 빈 새 탭, Google 로그인 페이지만 남기고 나머지 탭을 닫습니다.
  - 잠긴 동안에는 API 키를 고치는 것이 예약되지 않고 바로 적용됩니다. 그러지 않으면 새 키가 6일 뒤에야 적용되어 그동안 모든 앱이 잠기기 때문입니다. 모델이 문제일 때는 모델 변경도 바로 적용됩니다.
  - agent는 5분마다(끊긴 동안은 30초마다, 키나 모델이 바뀌면 바로) 비용이 들지 않는 모델 목록 API로 연결을 확인합니다. 크레딧 문제는 그 API로 알 수 없으므로, 그때만 가장 짧은 메시지로 확인합니다.
  - Focus 앱의 모든 탭 맨 위에 잠긴 이유와 푸는 방법을 보여 줍니다.

### 8.17 AI 비서: 이 프로그램의 기능을 말로 쓴다
- **소유자 요청:** "음 이 모든 기능을 자연어 인터페이스를 통해 쓸 수 있으면 좋겠는 데 그게 가능할라나? 기왕이면 AI 에이전트가 있어 가지고 내가 막 반복적으로 todo에 올려라 뭐 이런 요청을 할 수 있으면 좋을 거 같은데 혹시 모르니까 따로 브랜치 파서 만들어봐."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 처음에는 소유자의 말대로 따로 브랜치(`claude/natural-language-assistant`)에서 만들었습니다. 소유자가 "AI 비서 브랜치도 메인에 합쳐서 배포해줘"라고 해서 메인에 합쳐 배포했습니다.
  - 합칠 때 8.15의 프로그램 업데이트를 요청하는 도구(`program_update`)를 더했습니다. 그래서 AI 비서와 Claude Desktop도 목록에 있는 프로그램의 업데이트를 요청할 수 있습니다.
  - Focus 앱에 **AI 비서** 탭을 할 일 탭 바로 옆에 더했습니다. 사용자가 말을 적으면 Claude가 도구를 써서 그 일을 하고, 탭은 쓴 도구마다 이 프로그램의 AI의 답(승인, 거절, 오류)을 회색 줄로 보여 줍니다.
  - AI 비서는 Claude Desktop의 MCP 서버와 같은 도구를 씁니다. 그래서 도구를 `crates/machine/src/assistant_tools.rs`로 옮겨 두 곳이 함께 쓰게 했습니다. 두 도구를 새로 더했고, Claude Desktop도 이 두 도구를 받습니다: `plan_week`(앞으로 7일 계획), `request_access`(차단 탭의 접근 요청과 같음).
  - "결정은 AI가 해야 한다"(8.11)를 AI 비서에도 지킵니다. AI 비서는 다음에 할 일을 고르거나 추천하지 않고, 그만두고 싶다는 말은 `repick`으로 보냅니다. 확인 질문에 답하기, 거절된 변경을 AI 없이 하기, 차단 바로 풀기, 설정 보호 끄기는 AI 비서도 하지 못합니다.
  - 대화는 agent 안에서 돕니다. API 키를 agent만 읽을 수 있기 때문입니다. 한 차례가 몇 분 걸릴 수 있어서, Focus 앱은 말을 보내고 1초마다 대화를 읽습니다. 대화는 agent의 메모리에만 있고, 다시 로그온하거나 **새 대화**를 누르면 사라집니다.
  - 지시문은 영어로 적고, 화면과 답은 한국어입니다(8.7). 지금 시각은 사용자의 말 앞에 붙여 지시문이 늘 같게 했습니다(캐시 때문).
  - 하루 AI 예산은 지금처럼 AI 검사에만 적용하고, AI 비서는 막지 않습니다. 비용은 통계 탭의 AI 사용량에 "assistant"로 나옵니다.
  - "반복적으로 todo에 올려라"는 "말할 때마다 계속 올려 달라고 할 수 있다"로 읽었습니다. 정해진 때마다 저절로 올리는 반복 할 일은 만들지 않았고, 소유자에게 물어보기로 했습니다.

### 8.18 설치할 때 계정을 묻지 않고 모든 계정을 관리한다
- **소유자 요청:** "설치할 때 계정 이름 쓰는 것 말이야, 관리자 계정도 항상 포함시킬거니까 쓰지 말고 모든 유저 대상으로 하도록 해"
- **소유자가 말한 이유:** 관리자 계정도 항상 관리 대상에 포함시킬 것이기 때문입니다.
- **AI가 정한 세부:**
  - 설치 프로그램의 "Work account" 화면을 없애고, 설치 프로그램과 `install.cmd`가 언제나 `install --manage-all`을 실행하게 했습니다. 업데이트할 때도 모든 계정이 관리 대상이 됩니다.
  - 서비스의 `install --manage <계정>` 명령은 남겨 두었습니다. 관리자가 명령으로 직접 실행할 때만 씁니다.

### 8.19 도움말: 설정을 잠그는 방법, 누를 수 있는 Claude Console 링크
- **소유자 요청:** "도움말에 잠그는 방법도 추가해주렴. 어디에 버튼이 있는지 모르겠다." 이어서 "모든 앱이 잠겼을 때 도움말에 claude console의 주소가 적혀있기는 하나 주소를 클릭해서 들어갈 수 있게 해다오. 지금은 하이퍼링크가 아니라서" 그리고 "처음 설치할 때 설정을 보호하지 말고 내가 다 설정한 후 보호하게 만들거라."
- **소유자가 말한 이유:** 설정 보호 버튼이 어디에 있는지 몰랐습니다. Claude Console 주소가 링크가 아니어서 눌러 들어갈 수 없었습니다.
- **AI가 정한 세부:**
  - "잠그는 방법"은 설정 보호로 읽었습니다. 도움말 탭 맨 위에 펼쳐진 주제로 넣고, 설정 탭으로 바로 가는 버튼을 달았습니다. 확인 칸을 체크하기 전에는 **설정 보호하기** 버튼이 흐리게 보인다는 것도 적었습니다. 버튼을 찾기 어려웠던 까닭으로 보였기 때문입니다.
  - 설치 프로그램은 원래 설정을 보호하지 않으므로 코드는 바꾸지 않았습니다. 지웠다가 다시 설치하면 설정 폴더가 남아 보호가 이어진다는 것을 도움말에 적었습니다.
  - 링크는 Claude Console의 API 키 화면, 크레딧(결제) 화면, 예전 주소 세 개이고, 도움말과 잠금 안내(빨간 글) 양쪽에 넣었습니다.

### 8.20 다시 설치해도 API 키를 남긴다
- **소유자 요청:** "업데이트 할 때마다 api key 입력하는 게 번거로운데, 유지되게 만들 수는 없나"
- **소유자가 말한 이유:** 업데이트할 때마다 API 키를 넣는 것이 번거롭습니다.
- **AI가 정한 세부:**
  - 원인: 새 설치 파일을 그냥 실행하는 업데이트에서는 설정 폴더가 원래 남습니다. 그러나 프로그램을 지운 뒤 설치하면 설치기는 남은 설정 폴더를 믿지 않고 옆으로 옮겼습니다. 일반 사용자가 미리 만든 폴더일 수 있기 때문입니다. 그래서 그때마다 키가 사라졌습니다.
  - 해결: 설치기는 남은 폴더의 주인과 권한을 봅니다. 주인이 관리자 그룹이나 SYSTEM이고 다른 누구도 쓸 수 없으면 예전 설치가 잠가 둔 폴더이므로 그대로 씁니다. 설정 보호도 함께 이어집니다. 일반 사용자가 쓸 수 있는 폴더는 지금처럼 옮깁니다. Windows CI가 두 경우를 모두 시험합니다.
  - 키를 다른 곳(예: 사용자 폴더)에 따로 저장하지는 않았습니다. 사용자 폴더는 작업 계정이 마음대로 고칠 수 있어서, 보호된 설정을 우회하는 길이 되기 때문입니다.
  - 함께 고친 것: 설정 파일을 읽지 못하면 기본값으로 덮어쓰지 않습니다. 키가 사라질 수 있는 다른 길이었습니다.

### 8.21 관리자 말고는 프로그램을 지우지 못하게 한다
- **소유자 요청:** "흠 생각해보니 설치된 파일들을 유저가 지워버릴 수도 있군 혹시 관리자 빼고는 프로그램을 못 지우게 만드는 것(폴더 내 쓰기 권한 수정)도 설치할 때 같이 할 수 있나?"
- **소유자가 말한 이유:** 사용자가 설치된 파일을 지워 버릴 수 있기 때문입니다.
- **AI가 정한 세부:**
  - `C:\Program Files\DigitalWellbeing`은 Windows 기본값으로 이미 일반 사용자가 읽고 실행만 할 수 있었습니다. 그래도 위 폴더에서 물려받는 권한에 기대지 않도록, 설치기가 설치할 때마다 폴더의 주인을 관리자 그룹으로 바꾸고 권한(SYSTEM·관리자 모든 권한, Users 읽기와 실행)을 직접 씁니다. 물려받는 권한은 끊습니다.
  - Users에게 읽기와 실행은 남겼습니다. 작업 계정이 Focus 앱과 MCP 서버를 실행해야 하기 때문입니다.
  - Windows CI가 설치 뒤에 SYSTEM과 관리자 말고는 아무도 프로그램 폴더와 그 안의 파일을 고치거나 지울 수 없는지 확인합니다.

### 8.22 반복하는 할 일, AI가 정하는 시간, 할 일을 기다리는 잠금, 완료 보고, AI가 정하는 허용 기간, 할 일별 차단
- **소유자 요청:** "추가사항
1. 잠 자기나 출근 준비, 혹은 운동하기 처럼 반복적인 일을 끝냈을 때 없어지지 않고 후에 반복할 수 있도록, 할 일 수행 이후에 없어지지 않는 타입의 할 일도 추가할 수 있도록 하기
2. 할 일 목록에서 정해진 duration 외에도 AI가 지정할 수 있는지 확인하고 만약 지정할 수 없으면, AI 자의적 판단 하에 시간을 짧게 잡거나 길게 잡을 수 있는 기능을 추가하기.
3. 할 일을 받자마자 시작해버리면 내가 컴퓨터를 켜놓고 물 마시러 가거나 다른 일을 하고 있을 때도 시간이 지나가버린다. 그렇다고 내가 시작 버튼을 누를 때 까지 기다렸다 시작하면, 7시에 지정해준 게 8시 30분에 할 일을 시작해서 틀어질 수 있지. 그러니 할 일을 배정받지 않았을 때는 모든 앱과 웹사이트를 잠구고 유저가 할 일 받기 버튼을 누를 때 까지 기다려라.
4. 할 일이 완료 된 후에 사용자가 완료보고를 하도록 해서 해당 할 일을 없앨지 유지할지 고려하기. (완료 보고 전에 다른 일로 넘어가지 말라)
할 일 목록에서 예상 시간 뿐만 아니라 지금까지 소요한 시간 역시 적기
5. 5번 접근 허용 기간은 사용자가 기본적으로 요청하지 않고 AI가 판단해서 허용하도록
6. 할 일 별로 차단 목록을 관리하기. 그래서 할 일이 바뀌었을 때 차단 목록도 바뀌게."
- **소유자가 말한 이유:**
  - 1번: 잠자기, 출근 준비, 운동처럼 반복하는 일은 끝낸 뒤에도 나중에 다시 해야 합니다.
  - 2번, 5번: (말하지 않음)
  - 3번: 할 일을 받자마자 시간이 흐르면, 사용자가 자리를 비운 동안에도 시간이 지나갑니다. 사용자가 시작 버튼을 누를 때 시작하면, 7시에 정해 준 일이 8시 30분에 시작되어 계획이 틀어질 수 있습니다.
  - 4번: 끝난 할 일을 목록에서 없앨지 남길지 정하기 위해서입니다. 완료 보고 전에는 다른 일로 넘어가면 안 됩니다.
  - 6번: 할 일이 바뀌면 차단 목록도 바뀌어야 합니다.
- **AI가 정한 세부:**
  - 1번: 할 일에 "반복하는 할 일"(`repeat`) 표시를 더했습니다. 반복하는 할 일은 끝내도 목록에 남고, 할 일 탭·AI 비서·Claude Desktop 모두에서 표시할 수 있습니다. 목록에는 "(반복)"이 붙습니다. 8.17에서 미뤄 둔 "반복 할 일"이 이것입니다.
  - 2번 확인 결과: AI는 원래 할 일의 시간(분)을 스스로 정했습니다. 다만 지시문은 15~240분이라고 했고, 코드는 10~480분으로 잘랐습니다. 이제 지시문과 코드가 모두 10~720분(12시간)이고, 지시문은 예상 시간에 묶이지 말고 AI의 판단으로 짧게도 길게도 정하라고 말합니다. 12시간은 잠자기 같은 반복하는 할 일을 담기 위해 고른 상한입니다.
  - 3번: 할 일은 사용자가 "할 일 받기"를 누를 때만 정해집니다. 예전에는 agent가 15초마다 스스로 할 일을 정했습니다. 맡은 할 일이 없으면 모든 앱과 브라우저를 잠급니다(잠금 이유 `NoTask`). 이 잠금은 AI 연결 잠금(8.16)처럼 설정이 보호되어 있을 때만 걸립니다. 설정 단계에서 시험하다가 갇히지 않게 하기 위해서입니다. Claude Desktop, Windows에 필요한 프로그램, 이 앱, "검사하지 않는 앱"은 남깁니다. 브라우저는 이 잠금에서는 끕니다. "할 일 받기" 버튼 하나로 풀리므로 웹사이트가 필요 없기 때문입니다. 다시 로그온하면, 이미 맡은 할 일이 있으면 그대로 이어집니다.
  - 4번: 할 일의 계획된 끝이 지나면 완료 보고만 받습니다. "끝냈다"는 지금처럼 AI가 심사하고, "다 못 했다"(`not_finished`)는 심사 없이 받아들여지며 할 일은 목록에 남습니다. 보고 전에는 다른 일 받기와 AI 검사 멈추기가 거절됩니다. 보고한 뒤에는(끝냈다가 승인되어도) 다음 "할 일 받기"까지 아무 할 일도 정하지 않습니다. 그래서 예전의 "시간이 다 되면 알리기만"과 "시간이 다 되면 새 할 일 받기" 요청은 없앴습니다. 계획된 끝 전에 끝냈다고 하는 것은 지금처럼 됩니다.
  - 4번의 둘째 줄: 할 일 목록의 줄마다 "지금까지 쓴 시간 / 예상 시간"을 보여 줍니다. 반복하는 할 일은 마지막으로 끝낸 뒤에 쓴 시간을 셉니다.
  - 5번: "5번 접근 허용"은 차단 탭의 접근 요청으로 읽었습니다. 차단 탭에서 기간 칸을 없앴고, 요청은 "AI가 정함"(`ai_decides`)으로 갑니다. AI는 설정의 최대 길이와 영구 허용 여부 안에서 정합니다. AI 비서와 Claude Desktop은 사용자가 기간을 직접 말했을 때만 기간을 보냅니다.
  - 6번: AI가 건 차단은 그 차단을 건 할 일에 속합니다. 할 일이 바뀌면 이전 할 일의 차단은 보관되고 새 할 일의 차단이 적용되며, 이전 할 일로 돌아오면 그 차단이 다시 적용됩니다. 할 일의 글만 고친 것은 같은 할 일입니다. 항상 막을 프로그램과 항상 막을 웹사이트는 할 일과 상관없이 늘 적용됩니다. 이 버전 전에 걸린 차단은 어느 할 일에도 속하지 않아 적용되지 않고, 설정 탭의 "걸린 차단"에만 남습니다.

### 8.23 컴퓨터 없이 하는 일은 모든 앱을 잠그고, 급한 일로만 바꾼다
- **소유자 요청:** "아 그리고 컴퓨터로 하지 않는 종류의 일이면 모든 앱과 웹사이트를 잠구도록 해줄래? 예를 들면 잠자기라든지 운동하기 라든지, 그리고 급한 일로만 바꾸도록"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 할 일에 "컴퓨터 없이 하는 일"(`away_from_computer`) 칸을 더했습니다. 사용자가 비워 두면 할 일 변경을 심사하는 AI가 채우고, 이 기능 전에 만든 할 일은 AI가 고를 때 판단합니다. 할 일의 값이 AI의 판단보다 우선합니다.
  - 잠금은 다른 잠금처럼 설정이 보호되어 있을 때만 걸리고, 브라우저도 끕니다. 이 앱은 열려 있어서 끝나면 보고할 수 있습니다.
  - "급한 일로만 바꾸도록"은 "이런 일을 하는 동안에는 급한 이유가 있을 때만 다른 일 받기와 AI 검사 멈추기를 승인한다"로 읽고, 변경 요청 심사 지시문에 넣었습니다. 코드가 급한지 판단할 수는 없으므로 AI가 판단합니다. "끝냈다"는 지금처럼 심사합니다.

### 8.24 약속: 시각이 정해진 일은 고정하고, 받을지는 AI가 약속 규칙에 따라 정한다
- **소유자 요청:** "음 그리고 할 일 말고 "약속"을 추가해주도록 할래? 그래서 약속이 있을 때는 고정해서 하도록" 이어서 "약속을 악용할 수도 있으니 약속을 받을지 말지 AI가 결정하게 하는데, 그 룰도 설정에서 설정할 수 있게 해줘."
- **소유자가 말한 이유:** 약속이 있을 때는 그 시간에 고정해서 해야 합니다. 약속은 악용될 수 있습니다.
- **AI가 정한 세부:**
  - "고정"을 "시작 시각에 하던 일 대신 저절로 현재 할 일이 되고, 끝나는 시각에 저절로 끝난다"로 읽었습니다. 사용자가 "할 일 받기"를 누르지 않아도 시작합니다(agent가 15초마다 확인). 하던 할 일은 보고 없이 끝나고 목록에 남습니다. 약속은 완료 보고가 필요 없습니다.
  - AI가 할 일을 고를 때 다가오는 약속을 보고, 할 일의 계획된 끝은 다음 약속의 시작에서 끊깁니다. 7일 계획도 약속을 압니다.
  - "그 룰"은 설정 탭의 새 칸 **약속 규칙**(`appointment_rules`)과, 고칠 수 있는 다섯째 지시문 "약속을 받을지 심사"(`APPOINTMENT_PROMPT`)로 만들었습니다. 생활 규칙처럼 보호된 뒤에는 변경이 예약됩니다.
  - 코드가 먼저 막는 것: 2글자보다 짧은 제목, 이미 지난 약속, 24시간이 넘는 약속, 이미 받은 약속과 겹치는 약속.
  - 거절된 약속은 할 일 변경과 달리 "AI 없이 하기"로 예약할 수 없게 했습니다. "받을지 말지 AI가 결정하게"라는 요청 때문입니다. 지우기는 시간을 돌려줄 뿐이므로 AI 없이 바로 됩니다.
  - 약속 동안 다른 일로 바꾸려면 8.23처럼 급한 이유가 필요합니다. 컴퓨터 없이 하는 약속이면 모든 앱이 잠깁니다.
  - 할 일 탭, AI 비서, Claude Desktop(`add_appointment`, `remove_appointment`)에서 약속을 넣고 지울 수 있습니다. 시각은 "14:00", "오후 2시", "2시 반"처럼 적을 수 있습니다.

### 8.25 모델은 목록에서 고르고, 적용 전에 확인하고, 목록은 일주일마다 새로 받는다
- **소유자 요청:** "모델을 dropdown 메뉴로 변경할 수 있게 해줘. 그래야 내가 오타를 안내지 그리고 내가 모델을 없는 이름으로 고쳐서 악용할 수 있기도 하고. 이 역시 적용버튼 누르면 모델이 있는지 아무 콜이나 보내서 확인하도록 하고. 그리고 주기적으로 claude model을 찾아서 뭐가 있는지 확인하고  업데이트 하도록 해.(한 일주일 마다 한번씩?)"
- **소유자가 말한 이유:** 오타를 막고, 없는 모델 이름으로 고쳐서 악용하는 것을 막기 위해서입니다.
- **AI가 정한 세부:**
  - "아무 콜"은 비용이 들지 않는 모델 API 조회(`GET /v1/models/<모델>`)로 했습니다. 확인이 실패하면(모델이 없거나 인터넷이 끊김) 적용하지 않습니다. 이 확인은 연결 상태를 바꾸지 않습니다.
  - 확인은 agent가 설정을 쓰기 직전에 하므로, 설정 탭뿐 아니라 Claude Desktop의 설정 예약도 같은 확인을 거칩니다.
  - 목록은 agent가 일주일마다 받아 `models.json`에 둡니다. 받지 못하면 6시간 뒤에 다시 시도하고, 그동안은 프로그램에 들어 있는 기본 목록을 보여 줍니다.
  - API 키가 없을 때는 확인할 수 없으므로 변경을 받아들입니다. 키가 없으면 어차피 모든 호출이 실패하고, 보호된 뒤라면 모든 앱이 잠기기 때문입니다.

### 8.26 통계 탭에 기능별 AI 비용을 보여 준다
- **소유자 요청:** "AI API call이 생각보다 비싸더라고 60분 썼는데 1달러 정도 들었어. 그래서 어느 기능에서 가격이 드는지 알고 싶으니 통계에서 이를 보여주도록 해. 각 기능에서 얼마나 썼는지."
- **소유자가 말한 이유:** 60분에 약 1달러가 들어서, 어느 기능이 비용을 쓰는지 알고 싶습니다.
- **AI가 정한 세부:**
  - 프로그램은 이미 용도별로 사용량을 세고 있었으므로, 새로 센 것은 없고 보여 주는 표만 만들었습니다. 표는 기능마다 오늘, 최근 7일, 이번 달의 비용과 호출 수, 한 번의 평균 비용, 이번 달 비중, 이번 달의 입력과 출력 토큰을 보여 줍니다. 이번 달 비용이 큰 기능부터 나옵니다.
  - 기능 이름은 한국어로 바꾸고("창 검사(AI 검사)" 등), 이름 위에 마우스를 올리면 그 기능이 언제 AI를 부르는지 나오게 했습니다.

  - 이 잠금은 다른 잠금과 달리 설정 단계에서도 겁니다. 사용자가 직접 눌렀고 **다시 사용하기** 하나로 풀리기 때문입니다. "할 일 받기"도 멈춤을 풉니다.

### 8.31 이미 판정한 창의 다시 검사는 싼 모델이 먼저 하고, 판정이 바뀌면 기본 모델이 재확인한다
- **소유자 요청:** "이미 이전에 판정된 앱이나 웹사이트는 싼 모델을 쓸 수도 있겠구만. 그것도 추가해줘." 이어서 비용 방법 목록을 보고 "AI 비서를 초기 빼고는 많이 쓸 것 같지 않으므로 J는 기각 F는 중요 요소이므로 할 수 없어. K는 너가 제안한대로 판정의 결과값이 같으면 유지, 바뀌면 고급 모델이 재확인을 하는 방식으로 가자."
- **소유자가 말한 이유:** AI 비용을 줄이기 위해서입니다. J(AI 비서에 싼 모델)는 AI 비서를 많이 쓰지 않을 것이라서, F(다시 검사하기까지의 시간 늘리기)는 그 시간이 중요한 요소라서 하지 않습니다.
- **AI가 정한 세부:**
  - 설정에 **다시 검사 모델**(`recheck_model`)을 더했고, 기본값은 Claude Haiku 5.5입니다. 설정 탭의 모델 영역에 둘째 메뉴로 두었고, "쓰지 않음"을 고르면 예전처럼 기본 모델이 모든 검사를 합니다. 바꾸는 것은 모델처럼 느슨한 변경(보호된 뒤에는 예약)이고, 적용하기 전에 그 모델이 있는지 확인합니다.
  - "이미 판정된"은 "지금 할 일에서 판정된 적이 있는 창"으로 정했습니다. 할 일이 바뀌면 판정 기록이 지워지므로, 새 할 일의 첫 검사는 기본 모델이 합니다. 한 번의 검사에 함께 묻는 뒤쪽 창 중 하나라도 처음 보는 창이면 기본 모델이 묻습니다.
  - 지난번 판정을 알아야 하므로, 판정 기록을 다시 검사할 시각이 지나도 24시간 동안 남기게 바꿨습니다. 다시 검사할 때를 정하는 규칙은 그대로입니다.
  - 기본 모델이 재확인할 때는 같은 화면 캡처를 다시 씁니다. 다시 검사 모델의 호출이 실패하면 기본 모델이 판정합니다. 다만 키나 다시 검사 모델이 문제인 실패는 다른 연결 문제처럼 잠금으로 이어지게 했습니다. 없는 모델 이름으로 검사를 피하지 못하게 하기 위해서입니다. 같은 이유로 정기 연결 확인도 두 모델을 모두 확인하고, 잠긴 동안에는 다시 검사 모델도 바로 고칠 수 있습니다.
  - 통계 탭은 다시 검사 모델의 호출을 "창 다시 검사(싼 모델)"로 따로 셉니다. 그래서 줄어든 비용을 소유자가 직접 볼 수 있습니다.

### 8.32 테스트판과 본편을 따로 내고, 테스트판에만 보호 풀기를 둔다
- **소유자 요청:** "test 버전과 본편을 분리해서 release 할 수 있나? test 버전은 보호를 풀 수 있는 버튼이 있도록."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 저장소와 코드는 하나로 두고, 빌드할 때 켜는 기능(`test-edition`) 하나로 두 판을 나눴습니다. 두 판이 따로 자라면 고칠 곳이 두 배가 되기 때문입니다. 두 판의 차이는 보호 풀기 요청을 받는지와 화면의 표시뿐입니다.
  - "분리해서 release"는 같은 릴리스 페이지에 이름이 다른 파일(`-TEST`)로 올리는 것으로 했습니다. 버전 번호와 릴리스 노트를 하나로 두기 위해서입니다.
  - 보호를 푸는 것은 버튼만이 아니라 agent가 판을 보고 정합니다. 본편의 agent는 요청 자체를 거부합니다.
  - 두 판은 같은 설치 폴더와 설정 폴더를 씁니다. 따로 쓰면 테스트판에서 API 키와 설정을 다시 넣어야 하고, 두 서비스가 함께 돌 수도 있어서 더 복잡해지기 때문입니다. 대신 테스트판에서 보호를 풀면 본편으로 돌아와도 다시 보호해야 한다는 것을 문서에 적었습니다.
  - Linux CI는 테스트판도 빌드하고, 보호 풀기 테스트를 두 판 모두에서 돌립니다.

### 8.33 차단 직후에 창을 띄워 무엇을 할지 묻는다
- **소유자 요청:** "내가 상관 없어 보이는 탭이나 앱을 열었을 때, 그 앱을 막되, 바로 창을 띄워서 거기서 내가 실수를 인정하거나, 권한을 요청하거나, 할 일을 추가하거나, 급한 일로 지정하고 지금 할 일을 변경하도록 만들어 줄 수 있겠니? 이왕 막을거, 앱은 끄는 게 어쩔 수 없겠지만, 웹사이트는 웹사이트 자체가 변경되어서(cold turkey blocker같이) 권한 요청이 통과되거나 급한 일로 지정하여 통과되면 original website가 떳으면 좋겟어."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 창은 AI의 판정으로 새 차단이 걸릴 때만 띄웁니다. 항상 막을 프로그램과 웹사이트는 협상할 수 없으므로 묻지 않습니다.
  - "실수를 인정"은 창을 닫는 것으로 했고, 따로 기록하지는 않았습니다.
  - 접근 요청과 할 일 추가는 새 화면을 만들지 않고, 이미 있는 차단 탭의 접근 요청 칸과 할 일 탭의 추가 양식을 채워서 엽니다. 코드를 늘리지 않기 위해서입니다.
  - "급한 일로 지정하고 지금 할 일을 변경"은 예전에 화면에서 뺀 "목록 밖의 일로 바꾸기"(`switch_free`)를 이 창에서만 다시 씁니다. 8.11의 "사용자는 다음 할 일을 고르지 않는다"의 예외이므로, 변경 요청 심사 지시문에 "정말 미룰 수 없을 때만 승인하고 놀이는 거절하라"를 더했습니다.
  - 웹사이트를 차단 화면으로 바꾸는 부분은 이번에 만들지 않았습니다. 탭의 주소를 알아야 하는데, 방법(브라우저 확장, 닫힌 탭 다시 열기, 화면 자동화)마다 장단이 커서 소유자가 고르도록 했습니다. 그동안 창은 Ctrl+Shift+T로 닫힌 탭을 다시 열라고 안내합니다.

### 8.34 검색 사이트는 사이트 대신 검색어를 막는다
- **소유자 요청:** "구글과 같이 검색기능이 달린 사이트의 경우, 구글자체를 막기보다는 regular expression을 활용해서 검색어를 막는 편이 낫겠어."
- **소유자가 말한 이유:** (말하지 않음. 구글 전체를 막으면 일에 필요한 검색도 막히기 때문으로 읽었습니다.)
- **AI가 정한 세부:**
  - 정규식은 AI가 판정할 때 함께 적게 했습니다. 딴짓 검색어 하나만 막으면 비슷한 검색("cat videos", "funny cat")을 하나하나 다시 판정해야 하기 때문입니다.
  - AI의 정규식이 너무 넓으면(빈 글이나 한 글자에도 맞음) 버리고 검색어 그대로를 막습니다. 정규식 하나로 검색 전체가 막히는 일을 막기 위해서입니다.
  - 검색 사이트는 탭 제목의 끝으로 알아봅니다(Google, 네이버, Daum, Bing, DuckDuckGo). 목록은 설정이 아니라 코드에 두었습니다. 설정을 늘리지 않기 위해서입니다.

### 8.35 거절된 할 일 변경과 약속을 고쳐서 다시 보내는 "수정하기"
- **소유자 요청:** "할 일 추가가 거절되었을 때, AI 없이 하기 버튼 말고도 수정하기 버튼을 추가해서 내가 충분한 내용을 AI에게 전달할 수 있도록 해줘. 그래서 내가 조그만 실수로 거절되었을 때 수정할 수 있도록."
- **소유자가 말한 이유:** 조그만 실수로 거절되었을 때 고쳐서 다시 보내기 위해서입니다.
- **AI가 정한 세부:** 추가뿐 아니라 고치기와 약속 추가에도 버튼을 두었습니다. 버튼은 보낸 내용과 이유로 같은 양식을 다시 열 뿐이고, 다시 보내면 AI가 처음부터 다시 심사합니다. AI가 답하지 못한 변경에도 버튼이 나옵니다.

### 8.36 약속은 끝난 뒤 30분 더 이어지고, 연장은 AI가 까닭을 보고 정한다
- **소유자 요청:** "약속이 예상보다 늦게 끝날 때 다른 사람과 하는 일은 끊기면 안되니까, 약속은 종료 하자마자 끄지 말고 30분간 더 유지하도록 해. 30분이 지나면 연장할지 나에게 창을 띄워서 알려주고, 내가 연장에 적절한 사유를 말할 때에만 연장을 허가해줘."
- **소유자가 말한 이유:** 다른 사람과 하는 일은 끊기면 안 되기 때문입니다.
- **AI가 정한 세부:**
  - 30분이 지나면 약속은 끝나고(할 일을 기다리는 잠금으로 넘어감), 그 뒤 30분 동안 Focus 앱이 연장을 물어봅니다. 사용자가 자리에 없어도 약속이 끝없이 이어지지 않게 하기 위해서입니다.
  - 연장은 변경 요청(`ExtendAppointment`)으로 만들어 지금의 심사와 기록을 그대로 씁니다. 한 번에 10~240분이고, AI는 더 짧게 줄 수 있습니다. 연장한 끝에는 30분을 더하지 않고 바로 다시 묻습니다.

### 8.37 AI 비서 탭은 최신 대화부터 보여 준다
- **소유자 요청:** "AI 비서 내용이 세로로 길어져서 스크롤을 너무 많이 해야해. AI 비서 탭을 클릭했을 때 최신 것부터 보여줄래?"
- **소유자가 말한 이유:** 대화가 길어지면 스크롤을 너무 많이 해야 합니다.
- **AI가 정한 세부:** 입력 칸을 맨 위로 옮기고, 대화를 "사용자의 말 하나와 그 답"의 묶음으로 나눠 최신 묶음부터 보여 줍니다. 묶음 안의 줄까지 거꾸로 하면 답이 질문보다 먼저 나와 읽기 어렵기 때문입니다.

### 8.38 끈 프로그램과 끄지 못한 프로그램을 기록하고 보여 준다
- **소유자 요청:** "차단된 프로그램 일부가 로깅이 안되고 있는 거 같은데 확인해볼래? (백그라운드 프로그램이라든지)"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 확인한 것: 끄기에 실패한 프로그램은 자세한 로그에만 남아 보이지 않았고, 끈 프로그램도 Focus 앱 어디에도 나오지 않았습니다.
  - 끄지 못한 것은 같은 프로세스에 한 번만 경고로 남기고, 다시 시도하는 것은 조용히 둡니다. 0.8초마다 같은 경고가 쌓이지 않게 하기 위해서입니다.
  - 세션 0의 프로그램(Windows 서비스)과 다른 이름의 도우미 프로그램은 이번에 바꾸지 않고 문서에 한계로 적었습니다. 서비스를 끄면 Windows가 망가질 수 있고, 도우미 프로그램까지 끄는 것은 동작을 바꾸는 일이어서 소유자가 정할 일이기 때문입니다.

### 8.39 변경 요청 "연장하기"와 그 심사 지시문
- **소유자 요청:** "변경 요청에 "연장하기"도 추가해줘. 이때, 연장 시 사용할 프롬프트 설정 창도 따로 만들어주고"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 연장은 시간이 끝난 뒤에도 보낼 수 있게 했습니다(완료 보고 대신). 시간이 끝났을 때 가장 필요하기 때문입니다. 한 번에 5~240분이고, AI는 더 짧게 줄 수 있습니다. 시간이 이미 끝났으면 지금부터 셉니다.
  - "프롬프트 설정 창"은 설정 탭의 AI 지시문에 여섯째 지시문 "할 일 연장 요청 심사"로 두었습니다. 다른 지시문과 같이 기본 지시문 보기, 복사해서 고치기, 기본값으로 되돌리기가 있고, 보호된 뒤에는 바꾸기가 예약됩니다.
  - 약속은 이 요청을 받지 않습니다. 약속에는 끝난 뒤 묻는 연장(8.36)이 따로 있기 때문입니다.

### 8.40 할 일 시간이 끝나면 창을 띄워 묻는다
- **소유자 요청:** "할 일에 설정된 시간이 끝났을 때, 팝업창을 띄워서 끝났고 연장이 필요한지 끝냈는지 물어보자."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** "끝냈어요"는 창에서 바로 보내지 않고 할 일 탭의 완료 보고로 데려갑니다. 결과가 분명한 일은 증거(글과 화면 캡처)를 붙여야 하는데, 그 칸이 할 일 탭에 있기 때문입니다. "연장"과 "다 못 했어요"는 창에서 바로 보냅니다. 창을 닫아도 연장된 시간이 다시 끝나면 또 뜹니다.

### 8.41 변경 요청을 심사하면서 AI가 할 일 목록을 고친다
- **소유자 요청:** "AI가 변경 요청(끝냈어요. 막혔어요, 쉬고 싶어요)를 제목, 내용, 메모와 단계를 수정, 추가, 삭제할 수 있도록 해줘 + 그래서 내가 예를 들면, 메일 확인했고 이틀 뒤에 답장 보내자 라고 완료 요청을 했을 때, 메일 확인 task를 없애고 할 일 목록에 답장하기 - 메모 몇월 몇칠 이후 수행 가능 뭐 이런식으로 할 수 있게"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 목록의 변경은 요청이 승인될 때만 적용합니다. 거절된 요청으로 목록이 바뀌면 할 일을 피하는 길이 될 수 있기 때문입니다.
  - "몇월 며칠 이후 수행 가능"은 새 칸을 만들지 않고 메모에 "Not before YYYY-MM-DD"로 적게 했고, 할 일 고르기 지시문이 그 날짜 전에는 고르지 않게 했습니다. 설정과 화면을 늘리지 않기 위해서입니다. 코드가 날짜를 강제하지는 않습니다.
  - 한 번에 다섯 개까지, 목록에 있는 할 일만 고치고 지울 수 있게 했습니다. 끝낸 할 일은 "끝냈다"로 이미 목록에서 빠지므로 다시 지우지 않습니다.

### 8.42 할 일이 시작될 때 필요한 웹사이트를 연다
- **소유자 요청:** "어떤 일에 필요한 프로그램이 확실해지면(예를 들면, 이메일 확인의 경우 gmail, kaist mail, naver mail을 켜야겠지.) 이를 자동으로 켜줄 수도 있나? 만약에 가능하면 해봐"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 웹사이트만 열고 앱은 열지 않았습니다. AI는 이 PC에 설치된 프로그램을 모르고, 이름으로 실행하면 엉뚱한 것이 켜질 수 있기 때문입니다. 소유자의 예(메일 사이트들)는 모두 웹사이트입니다.
  - 웹사이트는 서비스(SYSTEM 권한)가 아니라 사용자 권한으로 도는 Focus 앱이 엽니다. 그래야 사용자의 브라우저와 로그인이 그대로 쓰입니다.
  - AI는 할 일과 메모로 확실할 때만 주소를 적게 했고, 플래너는 https 주소 다섯 개까지만 받습니다. 정확한 주소(예: KAIST 메일)를 쓰게 하려면 할 일의 메모에 주소를 적어 두면 됩니다.

### 8.43 설정에서 AI의 노력을 고른다
- **소유자 요청:** "설정에서 모델 뿐만 아니라 노력 low, medium, high, max 등등도 설정할 수 있게 해줘. 이건 서버 브랜치 말고 본 브랜치에서 적용해주고."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 노력은 두 가지로 나눴습니다. "창 검사의 노력"(기본 low)과 "그 밖의 판단의 노력"(기본 medium)입니다. 창 검사는 하루에 수십 번 일어나므로, 하나로 묶으면 판단을 꼼꼼하게 하려고 올린 노력이 창 검사 비용을 크게 늘리기 때문입니다.
  - 고를 수 있는 값은 실제 API로 확인한 low, medium, high, xhigh, max 다섯 개입니다(Opus 5.5와 Haiku 5.5 모두 받음).
  - 노력이 높으면 생각이 답의 최대 길이를 다 써서 답이 잘릴 수 있으므로, 최대 길이와 기다리는 시간을 노력에 맞춰 늘렸습니다.
  - 노력 바꾸기는 모델처럼 느슨한 변경으로 보고, 보호된 뒤에는 예약됩니다.

### 8.44 작업 관리자는 언제나 검사하지 않는다
- **소유자 요청:** "taskmgr도 디폴트로 검사하지 않고 언제나 allow하는 프로그램에 추가시켜둬"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** 설정의 "검사하지 않는 앱" 목록에 넣지 않고, 프로그램에 붙박은 목록(`BUILT_IN_ALWAYS_ALLOW`)에 두었습니다. 이미 설치된 PC의 설정 파일에는 목록이 저장되어 있어서 기본값을 바꿔도 반영되지 않고, 설정 파일을 고치면 보호된 뒤에 느슨한 변경으로 예약되기 때문입니다. 그래서 목록에서 뺄 수는 없고, 설정 탭은 목록 위에 이 사실을 보여 줍니다. 모든 앱이 잠겼을 때에도 작업 관리자는 열 수 있습니다. 작업 관리자로는 SYSTEM으로 도는 서비스와 agent를 끌 수 없으므로 우회 길이 되지 않습니다.

### 8.45 할 일 탭의 겹치는 빠른 요청 버튼을 없앤다
- **소유자 요청:** "UI를 보면 같은 역할을 하는 게 두 개가 있어 완료 보고 위에 끝냈어요 다 못 했어요 버튼이 있고 그 밑에도 끝냈다, 다 못 했다가 2개가 있지. 이렇게 겹치는 UI를 삭제해줘"
- **소유자가 말한 이유:** 같은 역할을 하는 것이 두 개 있습니다.
- **AI가 정한 세부:** 위의 빠른 요청 버튼 줄(끝냈어요, 시간이 더 필요해요, 다 못 했어요, 막혔어요, 쉬고 싶어요)을 모두 없애고 아래의 라디오 버튼만 남겼습니다. 빠른 버튼이 하던 일(이유 칸을 "끝낸 것: "처럼 미리 채우기)은 라디오 버튼으로 종류를 고를 때 하게 했고, 사용자가 이미 자기 말을 적었으면 이유 칸을 바꾸지 않습니다. 시간이 끝났을 때 뜨는 창의 버튼은 겹치는 것이 아니어서 그대로 두었습니다.

### 8.46 막은 프로그램의 도우미 프로그램도 끈다
- **소유자 요청:** "그냥 꺼. 나중에 문제 생기면 추가하면 되지."(AI가 막은 앱의 다른 이름 도우미 프로그램까지 끌지 묻자)
- **소유자가 말한 이유:** 나중에 문제가 생기면 예외를 더하면 됩니다.
- **AI가 정한 세부:**
  - 도우미는 "막은 프로그램 파일이 있는 폴더(그 안의 폴더 포함)에서 실행된 프로그램"으로 정했습니다. 부모와 자식 관계로 찾으면, 막은 앱이 연 브라우저처럼 상관없는 프로그램이 함께 꺼지고, 부모가 먼저 꺼지면 관계를 놓치기 때문입니다.
  - `C:\Program Files`, Windows 폴더, 사용자의 AppData와 다운로드 같은 여러 프로그램이 함께 쓰는 폴더는 한 프로그램의 폴더로 보지 않습니다. 그런 폴더에 바로 있는 프로그램을 막을 때 이웃 프로그램이 모두 꺼지면 안 되기 때문입니다.
  - AI 차단뿐 아니라 항상 막을 프로그램과 모든 앱 잠금에도 같은 규칙을 적용했습니다. 어느 규칙으로 막든 도우미가 남으면 같은 문제이기 때문입니다.
  - Steam을 막으면 Steam 폴더 안의 게임도 함께 꺼집니다.

### 8.47 막는 순간 "맞는 차단인가요?" 창을 띄우고, 허용되면 닫은 탭을 다시 연다
- **소유자 요청:** "내 말은 2번을 선택하되, 꺼지게 명령어를 보내자 마자 창을 열어서 지금 차단이 정당했는지, 권한을 요청해야하는지 알게 해."(2번: 탭을 닫고, 허용되면 Ctrl+Shift+T로 다시 열기)
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - Focus 앱이 0.3초마다 agent에게 마지막 차단만 묻는 가벼운 조회(`last_block`)를 만들었습니다. 예전에는 2초마다 오는 전체 상태로 알았습니다. 새 차단이 오면 숨어 있던 창도 바로 띄웁니다. agent(SYSTEM)는 사용자의 창을 직접 띄울 수 없어서, 차단을 거는 순간과 창이 뜨는 순간 사이에 0.3초 정도의 틈이 남습니다.
  - 창의 질문을 "맞는 차단인가요?"로 바꾸고, "아니요, 지금 일에 필요해요"를 누르면 차단 탭으로 보내지 않고 그 창 안에서 접근을 요청하게 했습니다. 답도 같은 창에 나옵니다.
  - 탭이 허용되면 agent가 아니라 Focus 앱이 그 브라우저 창을 앞으로 가져와 Ctrl+Shift+T를 누릅니다. Windows는 사용자가 쓰고 있는 프로그램만 다른 창을 앞으로 가져오게 하기 때문입니다. 창이 앞으로 오지 않으면 사용자에게 직접 누르라고 안내합니다.
  - Ctrl+Shift+T는 그 창에서 마지막으로 닫힌 탭을 엽니다. 차단 뒤에 사용자가 다른 탭을 닫았다면 그 탭이 열릴 수 있고, 창이 그 사실을 알려 줍니다.

### 8.48 코드 리뷰에서 나온 것 고치기, README 다시 쓰기
- **소유자 요청:** "전부 고쳐줘. 그리고 readme.md 파일 과거에 내가 쓴 거랑 너가 쓴 거랑 섞여서 알아보기가 힘들군. 아예 지우고 너가 다시 써봐라"
- **소유자가 말한 이유:** README는 소유자와 AI가 쓴 내용이 섞여서 알아보기 어렵습니다.
- **AI가 정한 세부:**
  - 도우미 프로그램을 끌 때, 어느 규칙이든 일부러 남기는 프로그램(검사하지 않는 앱, 브라우저, 접근이 허용된 앱, 모든 앱 잠금이 남기는 Claude Desktop과 Windows 프로그램, 화이트리스트의 프로그램)은 도우미로 끄지 않습니다. 규칙마다 "남기는 프로그램"을 말하게 했습니다(`BlockRule::keeps`). 예를 들어 모든 앱 잠금이 Chrome 폴더의 다른 도우미를 끌 때 Chrome까지 꺼져, API 키를 고치러 갈 브라우저가 사라지는 일을 막기 위해서입니다.
  - 허용된 탭을 다시 열 때, 사용자가 Shift, Alt, Ctrl, Windows 키를 누르고 있으면 Ctrl+Shift+T를 보내지 않고 직접 누르라고 안내합니다. agent의 Ctrl+W와 같은 규칙입니다. 탭을 다시 여는 일은 화면이 멈추지 않게 따로 돌게 했습니다.
  - README는 한국어로, 낱말 정의, 하는 일, 설치, 문서 목록, 저장소 구성, 빌드와 테스트, 배포만 담아 새로 썼습니다. 기능의 자세한 설명은 `docs/`에 이미 있어서 README에서는 문서로 안내만 합니다. 더는 설치 파일에 들어가지 않는 예전 독립 실행 창과 함수 호출 API의 설명은 뺐습니다.

### 8.49 설정 보호를 푸는 방법을 고른다, 보호를 풀면 차단도 푼다, 테스트판을 없앤다
- **소유자 요청:** "설정 보호 (잠금)을 cold turkey blocker 처럼 옵션을 선택할 수 있게 만들고 TEST 케이스를 없애자. 옵션은 "시간 단위 설정(일정 기간 동안 설정 보호 해제 불가)", "영구", "관리자 권한 요함(관리자 권한을 요청해보고 사용자가 승인할 수 있는 상태일 때만 해제 가능)", "비밀번호"" / "설정 보호 잠금이 해제되었을 경우 차단도 풀도록 해. Lock되어 있지 않으면 차단이 사실 의미가 없으니"
- **소유자가 말한 이유:** 보호되지 않은 설정에서는 차단이 사실 의미가 없습니다.
- **AI가 정한 세부:**
  - 기간 보호는 시간이 지나도 저절로 풀리지 않고, 사용자가 버튼을 눌러야 풀립니다. "기간 동안 해제 불가"를 지키면서, 풀리는 순간 모든 차단이 사용자도 모르게 사라지지 않게 하기 위해서입니다. 가장 짧은 기간은 10분입니다.
  - 관리자 권한 보호는 Focus 앱이 Windows에 `digital-wellbeing-service.exe settings-unlock`을 관리자 권한으로 실행해 달라고 요청해서 풉니다(UAC 승인 창). agent(SYSTEM)는 사용자가 관리자인지 알 수 없으므로 이 보호를 풀어 달라는 요청을 거부하고, 관리자만 열 수 있는 데이터 폴더를 읽을 수 있는 프로그램만 풀 수 있게 했습니다.
  - 비밀번호는 PBKDF2-HMAC-SHA256 해시로만 저장하고, 틀리면 1초 기다린 뒤 답해 빠르게 맞혀 보기 어렵게 했습니다.
  - 예전 버전에서 보호한 설정(푸는 방법이 적혀 있지 않음)은 영구 보호로 봅니다. 그때 사용자가 고른 것이 "풀 수 없는 보호"였기 때문입니다.
  - 보호를 풀 때 agent가 모든 계정의 차단 파일을 비우고, 돌고 있는 agent는 3초마다 보호가 풀렸는지 보고 메모리의 차단도 풉니다. 그래서 관리자 권한으로 풀거나 다른 계정에서 풀어도 차단이 풀립니다. 항상 막을 프로그램과 웹사이트는 설정이므로 그대로 둡니다.
  - 테스트판은 빌드, 설치 파일, CI, 문서에서 모두 없앴습니다.

### 8.50 컴퓨터를 쓰지 않는 동안 할 일의 시간을 멈추고, 통계에 시간표를 둔다
- **소유자 요청:** "내가 컴퓨터에서 활동을 안 하는 걸 감지해서 시간을 멈춰줘. "컴퓨터로 하는 활동"의 경우에만. "컴퓨터로 하지 않는 활동"은 시간을 멈추지 말아줘." / "내가 과거에 어떻게 시간을 썼는지 통계에서 확인하고 싶어. 앞으로는 통계에 시간표를 추가해서 내가 과거를 어떻게 살았는지 기간을 설정해서 확인할 수 있게 해줘.  만약 "컴퓨터로 하는 활동"인데 컴퓨터로 활동 하지 않는 걸 감지했다면 "알 수 없음"으로 기입해줘."
- **소유자가 말한 이유:** 과거에 시간을 어떻게 썼는지 확인하기 위해서입니다.
- **AI가 정한 세부:**
  - "활동을 안 한다"는 키보드와 마우스를 5분 넘게 쓰지 않은 것으로 정했습니다. 영상을 보며 잠깐 생각하는 정도로는 멈추지 않게 하기 위해서입니다. 멈춤은 5분이 지난 때가 아니라 마지막으로 쓴 때부터 셉니다.
  - "시간을 멈춘다"는 할 일의 끝나는 시각을 자리를 비운 만큼 늦추고, 그동안 시간이 다 되지 않게 하고, 그 시간을 들인 시간에서 빼는 것으로 정했습니다.
  - 약속은 컴퓨터로 하는 것이어도 멈추지 않습니다. 약속은 시각이 정해져 있어서 늦출 수 없기 때문입니다. 그래서 약속 중의 자리 비움은 "알 수 없음"으로도 적지 않습니다.
  - 시간이 이미 다 된 뒤의 자리 비움은 멈추지 않습니다. 완료 보고를 미루는 길이 되지 않게 하기 위해서입니다.
  - 시간표는 날마다 0시부터 24시까지의 막대와 줄 목록으로 보여 주고, 기간 전체의 종류별, 할 일별 합계를 함께 보여 줍니다. 기간은 하루에서 1년까지이고, 기록은 최근 1000개의 할당까지 남습니다.
  - 테스트의 agent가 실제 입력 기록에 흔들리지 않도록, 플래너는 입력 기록을 밖에서 받습니다(`with_idle_source`). 서비스의 agent만 실제 데스크톱의 기록을 넘깁니다.

### 8.51 여러 기기 동기화 (브랜치 `claude/multi-device-sync`)
- **소유자 요청:** "여러 기기에서도 적용 가능하도록 만들고 싶어(동기화 하기). 서버는 비밀번호가 걸린 관리자 계정(내가 이 비밀번호를 물리적으로 보관할거야.)으로 작동시킬 거야. 동기화할 때 서버의 내용을 내가 마음대로 변경하지 못하게. 동기화는 할 일과 지금 하고 있는 일, 설정 동기화 등 가급적 모든 state를 동일하게 가져가도록 해. 통계도 합계내서 내주고. 생각해보니 그렇게 되면 claude API도 서버에서 통신 하면 되긴하겠지만, 일단은 서버 관리라는 걸 내가 해본 적이 없어서 문제 생길 수도 있으니까 놔두자. 이건 되게 큰 변화라고 생각해서 여러 테스트가 필요할 거 같아. 브랜치 따로 파서 작업해봐" / "서버 side 프로그램 쓴 이후에는 서버에서 어떻게 설치하는지도 같이 써줘."
- **소유자가 말한 이유:** 서버 관리를 해 본 적이 없어서, Claude API는 서버로 옮기지 않고 각 기기에 둡니다. 큰 변화라서 따로 브랜치에서 여러 테스트와 함께 만듭니다.
- **AI가 정한 세부:**
  - 서버는 새 프로그램이 아니라 같은 `digital-wellbeing-service.exe`의 `sync-…` 명령입니다. Windows에서는 `DigitalWellbeingSync` 서비스(SYSTEM)로 돌고, 파일 폴더는 SYSTEM과 관리자만 열 수 있습니다. 설치 파일을 하나 더 만들지 않기 위해서입니다.
  - 기기마다 서버가 주는 열쇠가 있고, 모든 메시지는 그 열쇠로 암호화하고 서명합니다(XChaCha20-Poly1305). 메시지마다 늘어나는 번호와 보낸 시각을 넣어, 예전 메시지를 다시 보내는 것을 막습니다. 그래서 HTTPS 인증서 없이 HTTP로 통신합니다. 인증서를 관리하는 일을 소유자에게 지우지 않기 위해서입니다.
  - 기기는 바뀐 파일을 통째로 보내고, 서버는 파일마다 판 번호(revision)를 둡니다. 두 기기가 같은 파일을 바꾸면 늦은 쪽이 3-way 병합을 하고 다시 보냅니다. 같은 값을 둘 다 바꾸면 서버(먼저 닿은 쪽)가 이깁니다. 지금 할 일, 사용 중지, 주간 계획은 섞이지 않게 통째로 한쪽이 이깁니다.
  - 동기화하는 것: 설정 세 파일, 설정 보호와 예약된 업데이트, 플래너 상태(지금 할 일과 기록), 계정마다의 접근 허용과 걸린 차단. 동기화하지 않는 것: 관리할 계정(`machine.json`), 로그, 모델 목록, 시간대와 업데이트 기록. 이것들은 PC마다 달라야 하기 때문입니다.
  - AI 사용량은 기기마다 자기 것만 보내고, 다른 기기의 것은 `usage\<기기>~<계정>.json`으로 받습니다. 통계 탭과 하루 예산이 원래 `usage\`의 파일을 모두 더하므로, 둘 다 저절로 모든 기기의 합계가 됩니다. 하루 예산도 합계로 세는 것은 한 사람의 예산이기 때문입니다.
  - Anthropic API 키는 `ai_focus.json`에 있어서 함께 동기화됩니다. 키를 기기마다 넣지 않아도 되게 하기 위해서이고, 키는 서버의 잠긴 폴더에 저장됩니다.
  - 서버는 보호가 켜진 설정 보호 파일을 끄는 변경을 받지 않습니다(테스트판 서버만 예외). 정해진 파일 이름만 받고, 한 기기가 다른 기기의 사용량을 쓰지 못하게 합니다.
  - 처음 짝지은 기기는 서버를 채우고, 그 뒤에 짝지은 기기는 서버의 상태를 받습니다. 새 PC의 느슨한 설정이 보호된 설정을 덮지 못하게 하기 위해서입니다.
  - 기기 안에서는, 서비스가 파일을 바꾸면 에이전트가 몇 초 안에 받아들입니다. 파일을 메모리에 들고 있는 저장소(`JsonStore`)는 다른 프로세스가 파일을 바꿨으면 저장하기 전에 다시 읽습니다. 걸린 차단은 메모리의 변경과 파일의 변경을 합칩니다. 플래너는 다른 기기가 정한 지금 할 일을 AI 검사에 바로 반영합니다. 이 변경은 한 PC의 두 계정이 같은 파일을 쓸 때에도 서로 덮어쓰지 않게 해 줍니다.
  - 기기는 20초마다 동기화합니다. 서버가 닿지 않으면 각 기기는 혼자 동작하고, 다시 닿으면 그동안의 변경을 합칩니다.
  - 서버 설치 방법(Windows 서비스, 방화벽, 고정 IP, 집 밖의 기기를 위한 Tailscale 또는 포트 포워딩, 리눅스 systemd)은 `docs/sync.md`와 도움말 탭에 적었습니다.
  - 이 브랜치는 소유자가 확인하기 전까지 릴리스하지 않습니다.

### 8.52 동기화: API 키는 PC마다, 하루 예산은 합계, 버전 맞추기, 로그인
- **소유자 요청:** "API 키는 기기마다 따로 두게 해줘 / 하루 예산 모든 PC 합계로 측정해 / 버전 되도록 맞춰두자. / 계정보다는 로그인 할 수 있는 시스템을 만들자."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - API 키: 기기는 `ai_focus.json`을 보낼 때 `api_key`를 빼고, 받을 때 자기 키를 남깁니다. 서버도 받은 문서에서 키를 지웁니다(옛 기기가 보내도 저장되지 않게). API 키를 바꾸는 예약된 업데이트도 그 PC에만 남깁니다. 다른 PC에서 확인 질문에 답해 적용되면 엉뚱한 PC의 키가 바뀌기 때문입니다.
  - 하루 예산: 이미 모든 PC의 사용량 파일을 더해 세고 있어서 바꾸지 않았습니다.
  - 버전: 기기는 요청마다 자기 버전(`installer/RELEASE_VERSION`)을 보냅니다. 서버는 짝지은 PC 중 가장 새 버전보다 옛 버전인 PC의 동기화를 거절하고, 새 버전의 PC에게는 뒤처진 PC의 목록을 알려 줍니다. 자동 업데이트는 만들지 않았습니다. 이 프로그램을 스스로 바꾸는 일은 위험이 커서 따로 정할 일이기 때문입니다.
  - 로그인: "계정"은 Windows 계정 이름을 뜻한다고 보고, 접근 허용, 걸린 차단, AI 사용량을 Windows 계정 대신 로그인에 묶었습니다.
    - 로그인은 서버의 관리자만 만듭니다(`sync-add-user`). 사용자가 로그인을 새로 만들 수 있으면, 차단이 없는 새 로그인으로 차단을 피할 수 있기 때문입니다.
    - 비밀번호는 PBKDF2-HMAC-SHA256(20만 번)의 해시로만 저장되고, 로그인 목록(`users.json`)은 서버만 씁니다.
    - 설정이 보호된 뒤에는 로그인하지 않은 계정은 모든 앱이 잠깁니다(`LoginRequired`). 로그인하지 않는 것이 공유된 차단을 피하는 길이 되지 않게 하기 위해서입니다.
    - 로그인하거나 로그아웃하면 agent가 끝나고, 서비스가 2초 안에 다시 띄워 로그인의 파일을 엽니다. 파일을 연 채로 바꾸는 것보다 단순하기 때문입니다.
    - 서버에 로그인이 하나도 없으면 지금처럼 Windows 계정 이름을 씁니다.
  - 잠금 안내의 API 키 설명은 AI 연결이 끊겼을 때만 보이게 했습니다. 로그인 잠금이나 할 일 잠금에서도 이 설명이 나와 헷갈렸기 때문입니다.

### 8.53 동기화 코드 리뷰에서 나온 것 고치기
- **소유자 요청:** "전부 고쳐줘."(코드 리뷰의 발견 사항)
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 서버의 답에 그 답이 대답하는 요청의 번호를 넣고, 기기는 번호가 맞고 서버 시각이 10분 안일 때만 답을 받습니다. 예전 답을 다시 보내 보호를 끄는 길을 막기 위해서입니다.
  - 보호된 기기는 서버가 보호를 끈 설정을 보내도 받지 않습니다(테스트판 기기만 예외). 서버의 규칙과 같은 규칙을 기기에도 두어, 한쪽이 뚫려도 보호가 남게 했습니다.
  - 이름에 점이 있는 파일(예: `grants/john.doe.json`)도 동기화합니다. 예전에는 점이 하나인 파일만 보내서 이런 계정의 접근 허용과 차단이 빠졌습니다.
  - 동기화가 쓰는 파일은 디스크에 기록한 뒤 이름을 바꿉니다(`sync_all`). 정전이 나도 빈 파일이 남아 할 일 기록을 잃지 않게 하기 위해서이고, `JsonStore`와 같은 방식입니다.
  - 서버는 동시에 32개까지 요청을 받고, 요청 줄과 헤더는 16KB까지만 읽습니다.
  - 한 PC에서 동기화는 하나만 돕니다(`sync.lock`). `sync-now`와 서비스의 20초 동기화가 겹치면 같은 번호를 두 번 보내거나 기준본을 엉키게 했기 때문입니다. 5분 넘은 잠금은 멈춘 동기화가 남긴 것으로 보고 치웁니다.
  - 서버는 시작할 때 포트를 `server.json`에 적고, `sync-add-device`의 안내는 그 포트를 씁니다.
  - 로그인 확인은 두 파일의 크기와 수정 시각이 바뀔 때만 다시 읽습니다. 모든 앱 잠금이 1초에 여러 번 묻기 때문입니다.

### 8.54 동기화: 설정 보호를 푸는 방법에 맞춰 보호를 푼다
- **소유자 요청:** "설정 보호 (잠금)을 cold turkey blocker 처럼 옵션을 선택할 수 있게 만들고 TEST 케이스를 없애자."(8.49를 동기화 브랜치에 맞춘 것)
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 8.50과 8.52의 "테스트판만 예외" 규칙을 없애고, 보호를 푸는 방법에 따라 정합니다. 영구는 받지 않고, 기간은 끝난 뒤에만 받고, 관리자 권한과 비밀번호는 받습니다. 관리자 권한과 비밀번호는 서버도 다른 기기도 확인할 수 없어서, 그 방법으로 푼 기기의 서비스가 확인한 것을 믿습니다. 그 기기의 열쇠는 관리자만 읽을 수 있는 폴더에 있습니다.
  - 보호를 풀 때 파일을 지우지 않고 "보호되지 않음"(`protected_since: null`)을 씁니다. 지운 파일은 동기화가 다른 기기에 알리지 못하기 때문입니다.
  - 보호가 켜진 동안 푸는 방법을 바꾸는 변경은 서버가 받지 않습니다. 예를 들어 영구 보호를 비밀번호 보호로 바꾼 뒤 푸는 길을 막기 위해서입니다.

### 8.55 동기화: 관리자 권한 보호를 한 컴퓨터에 묶는다, 클라우드 서버
- **소유자 요청:** "설정 보호도 동기화가 되나? 되었으면 좋겠는데. 이때 보호 : 관리자 권한 바탕으로 동기화 방식의 경우, 특정 컴퓨터에서의 관리자만 풀 수 있도록 하면 좋겠어. 예를 들면 컴퓨터 A 컴퓨터 B가 있으면 컴퓨터 A의 관리자 권한 필요 이런식으로 설정할 수 있으면 좋겠네." / "이제 서버 설치하려고 하는데 클라우드 서비스를 써보려고. 24/7 이 프로그램이 안정적으로 작동했으면 좋겠어. 어떤 클라우드 서비스를 써야할지, 어떻게 설정할지 알려주도록 해." / "아 참고로 이 서비스는 나 혼자 쓸 거야. 그러니 한 10대 정도의 동시 접속까지만 고려하면 될 듯. 중요한 건 동시 접속 디바이스 갯수는 적게 설정하되, 24/7 안정적인 접속을 지원할 수 있어야해"
- **소유자가 말한 이유:** 서버가 24시간 안정적으로 돌아야 합니다. 쓰는 사람은 소유자 혼자입니다.
- **AI가 정한 세부:**
  - 설정 보호는 이미 동기화되고 있었습니다(8.54).
  - 관리자 권한 보호에 "어느 컴퓨터"(동기화 기기 이름)를 둡니다. 기본값은 보호하는 컴퓨터입니다. 그 컴퓨터의 `settings-unlock`만 풀 수 있고, 서버도 그 기기가 보낸 "보호 풀림"만 받습니다. 기기는 서버가 받은 것을 믿습니다. 고를 수 있게 서버가 짝지은 기기의 목록을 함께 보냅니다.
  - 서버가 한 번에 받는 요청을 32개에서 16개로 줄였습니다. 기기 10대가 20초마다 짧은 요청을 보내므로 넉넉하고, 그보다 많은 연결은 바로 끊어 서버가 지치지 않게 합니다.
  - 클라우드는 AWS Lightsail 서울 리전의 가장 작은 리눅스 요금제를 권했습니다. 월 정액이고, 고정 IP가 무료이며, 서울에 있어 가깝고, 매일 스냅샷을 켤 수 있기 때문입니다. 무료 요금제는 놀고 있는 인스턴스를 회수할 수 있어 24시간 서버에 맞지 않습니다.
  - 리눅스용 서버를 정적 실행 파일(musl)로 빌드해 CI의 artifact로 올리고, systemd 서비스 파일(부팅 때 시작, 멈추면 5초 뒤 다시 시작, 데이터 폴더는 root만)을 함께 둡니다. 어느 리눅스 배포판에서도 다른 파일 없이 돌게 하기 위해서입니다. 서버의 기록은 systemd 저널로 갑니다.

### 8.56 동기화 서버의 자동 업데이트
- **소유자 요청:** "자동 업데이트도 만들어줘."(서버를 매번 올려서 업데이트해야 하는지 물은 뒤)
- **소유자가 말한 이유:** 서버를 매번 손으로 올리는 것이 번거롭습니다.
- **AI가 정한 세부:**
  - 동기화 브랜치는 정식 릴리스를 내지 않으므로, CI가 테스트를 모두 통과한 리눅스 서버 빌드를 고정 이름의 릴리스 `sync-latest`에 덮어 올립니다(프리릴리스, "최신 릴리스"로 표시하지 않음). 저장소가 공개라 서버는 로그인 없이 받습니다.
  - 서버의 타이머가 하루 한 번(한국 시간 새벽 4시 30분쯤) 확인합니다. 받은 파일은 함께 올린 SHA-256으로 확인하고, 지금 것과 같으면 아무것도 하지 않습니다. 새 빌드가 30초 안에 답하지 않으면 예전 빌드로 되돌립니다. 24시간 안정적으로 돌아야 한다는 요구 때문입니다.
  - CI는 실제 systemd에서 이 업데이트를 시험합니다: 옛 빌드에서 새 빌드로 바뀌는지, 두 번째에는 아무것도 하지 않는지, 깨진 파일은 설치하지 않는지.
  - 새 서버는 `scp` 없이 서버에서 바로 `curl`로 받아 설치할 수 있게 설명을 바꿨습니다.
  - 서버 프로그램을 GitHub에서 받으므로, 저장소에 push할 수 있는 GitHub 계정도 관리자 비밀번호처럼 지켜야 한다고 문서에 적었습니다.


### 8.57 동기화: 짝 코드 대신 회원가입과 로그인
- **소유자 요청:** "근데 궁금한 게, 로컬에서 로그인해서 아이디와 비밀번호가 맞으면 저 key를 주면 되는 거 아니야? 왜 저걸 기억해야해?" / "흠 Key를 받는 거는 앞으로 서버 초기화 여러 번 시킬 작정이라 번거로운데 회원가입의 방식으로 운용할 수는 없나? 대신 한번 관리자 권한으로 로그인 하면 로그아웃이 사용자 설정 보호되고 있는 동안에는 안되게"
- **소유자가 말한 이유:** 서버를 여러 번 초기화할 생각이라, 그때마다 기기마다 짝 코드를 받는 것이 번거롭습니다.
- **AI가 정한 세부:**
  - 회원가입은 계정이 하나도 없는 서버에서만 받습니다. 쓰는 사람이 소유자 혼자이므로, 첫 회원가입을 한 사람이 그 서버를 갖게 했습니다. 더 만들 계정은 서버의 `sync-add-user`로 만듭니다.
  - 비밀번호는 PC 밖으로 보내지 않습니다. PC가 비밀번호로 계정 키(PBKDF2, 이름을 소금으로)를 만들어 로그인 요청을 암호화하고, 서버는 그 키로 열릴 때만 새 기기 열쇠를 줍니다. 서버와 PC 사이에 HTTPS가 없기 때문입니다. 회원가입 때에는 서버가 아직 계정 키를 모르므로 X25519로 그 자리에서만 쓰는 키를 정해 보냅니다(서버의 공개 키는 `GET /public-key`). 이 방법은 엿듣기는 막지만, 회원가입하는 순간 중간에서 서버인 척하는 공격은 막지 못합니다. 서버를 만든 직후 한 번만 하는 일이라 받아들였습니다.
  - 서버는 한 이름의 로그인이 15분 안에 5번 틀리면 15분 동안 그 이름의 로그인을 받지 않고, 틀린 답은 1초 늦게 보냅니다. 서버가 인터넷에 열려 있어 비밀번호를 하나씩 넣어 보는 것을 막기 위해서입니다. 같은 이유로 비밀번호는 8자 이상으로 했습니다(예전 로그인은 4자).
  - PC는 계정 키를 `sync.json`(관리자만 읽는 폴더)에 간직하고, 서버가 "이 기기를 모른다"고 답하면 그 키로 저절로 다시 로그인한 뒤 서버의 상태를 받습니다. 서버를 초기화하면 한 PC에서 다시 회원가입하기만 하면 되게 하기 위해서입니다. 그래서 잃어버린 기기는 `sync-remove-device`만으로는 막히지 않고, 비밀번호도 바꿔야 한다고 문서에 적었습니다. 다시 로그인하다가 "비밀번호가 맞지 않습니다"를 받으면 PC는 간직한 계정 키를 지웁니다. 낡은 키로 20초마다 틀려서 그 이름의 로그인이 모두에게 막히지 않게 하기 위해서입니다.
  - 같은 컴퓨터가 다시 로그인하면 기기 이름을 그대로 두고 열쇠만 바꿉니다. 관리자 권한 보호가 기기 이름에 묶여 있기 때문입니다(8.55).
  - 로그인(서버에 붙기, Windows 계정 로그인 둘 다)은 서비스의 `sync-login`을 관리자 승인으로 돌립니다. Focus 앱은 비밀번호를 사용자의 임시 폴더에 있는 파일로 넘기고, 명령은 읽자마자 지웁니다. agent의 예전 "login" API는 관리자 승인 없이 로그인하게 하므로 없앴습니다. 이미 그 계정으로 붙은 PC의 다른 Windows 계정은 서버에 묻지 않고 간직한 계정 키로 비밀번호를 확인합니다.
  - 설정이 보호되어 있는 동안에는 로그아웃과 `sync-leave`를 받지 않습니다. 로그아웃 버튼도 보호되지 않았을 때만 보입니다.
  - 비밀번호를 아는 사람은 다른 컴퓨터를 로그인시켜 설정을 바꿀 수 있습니다. 이것은 서버가 막을 수 없으므로, 이 비밀번호를 관리자 비밀번호처럼 따로 보관하라고 문서와 Focus 앱에 적었습니다.
  - agent는 이제 자기 Windows 계정의 로그인이 바뀐 것을(다른 프로세스가 바꾼 것도) 스스로 알아채고 다시 시작합니다.
  - 짝 코드(`sync-add-device`, `sync-join`)는 예전 방법으로 남겼습니다.

### 8.58 제거하거나 설치할 때 사용자 정보를 남길지 고른다
- **소유자 요청:** "로컬 프로그램 제거할 때 로컬에 사용자 관련 정보(할 일 목록, 생활 규칙 등등)를 남겨둘 건지 옵션을 제공해줘." / "아 그리고 설치할 때도 기존에 설치된 유저 정보를 지우고 설치할지 아니면 이를 유지한 채로 설치할지 물어봐줘. 디폴트는 유지한 채로 설치하는 걸로 하고"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - Windows의 "앱 제거"가 처음에 "이 PC에 남은 사용자 정보를 지울까요?"라고 묻고, 기본 단추는 "아니요"(남김)입니다. 되돌릴 수 없는 일은 일부러 고를 때만 하게 하기 위해서입니다.
  - 조용한 제거(`/VERYSILENT`)는 물을 사람이 없으므로 남깁니다.
  - "지움"은 데이터 폴더 전체(설정, 할 일, 생활 규칙, 지금 할 일, 기록, 차단과 허용, API 키, 설정 보호, 로그)와 모든 Windows 계정의 `AppData\Local\DigitalWellbeing`, `AppData\Roaming\DigitalWellbeing`(Focus 앱의 설정 초안, 예전 버전의 설정)을 지웁니다. 사용자 정보의 일부만 고르는 옵션은 두지 않았습니다.
  - 명령으로는 `uninstall --delete-data`입니다. 서비스를 멈추면 agent도 끝나므로 열린 파일이 없지만, 그래도 몇 초 동안 다시 시도합니다.
  - 설정이 보호되어 있어도 지울 수 있습니다. 제거는 관리자만 할 수 있고, 관리자는 원래 데이터 폴더를 직접 지울 수 있기 때문입니다.
  - 설치 프로그램은 데이터 폴더가 이미 있을 때만(업데이트이거나, 남겨 두고 제거한 뒤 다시 설치할 때) 묻습니다. 묻는 때는 파일을 복사하기 직전이고, "예"이면 `install --delete-data`가 서비스를 멈춘 뒤 지우고 처음 설치처럼 설치합니다. 지우다 실패하면 설치를 멈추고 예전 서비스를 다시 켭니다.
  - 제거 창의 글은 한국어로 썼고, 그래서 설치 스크립트를 UTF-8(BOM)으로 저장했습니다.
  - release 작업이 실제 설치 프로그램으로 설치하고 조용히 제거해 보고, CI가 `uninstall --delete-data` 뒤 데이터 폴더가 없어지는지 확인합니다.

### 8.59 동기화: 첫 화면에서 서버에 붙을지 묻는다

### 8.60 동기화: 짝 코드로 붙은 PC도 첫 화면에서 계정으로 로그인하게 한다, 포트는 빼도 된다
- **소유자 요청:** "클라이언트에서 서버 IP를 어떻게 찾지? 그리고 금방 실험해봤는데 처음에 로그인/ 회원가입 창이 안떠"

### 8.62 이 프로그램을 설정 탭에서 업데이트한다, 업데이트하는 동안 모든 앱을 닫는다
- **소유자 요청:** "PC도 자동 업데이트 되게 만들어줘" / "그리고 업데이트 확인 버튼도 만들어줘 설정에. 대신, 업데이트 하는 동안 프로그램이 무력화 되므로 사용자가 악용할 우려가 있어. 그러므로 설정 보호가 꺼져있을 때만 업데이트 확인 및 업데이트를 가능하게 해다오." / (보호 중에도 자동 업데이트를 할지 묻자) "고민이 되는 군 서버만 업데이트 해버리면 골치가 아프니까... 아니면 업데이트 하는 동안 일시적으로 모든 앱과 웹사이트를 잠글 수는 없나?" / "만약 그게 되면 업데이트는 수동으로 하되 항상 열려있도록"
- **소유자가 말한 이유:** 업데이트하는 동안 프로그램이 무력화되어 악용될 수 있습니다. 서버만 업데이트되면 PC와 버전이 어긋나 골치가 아픕니다.
- **AI가 정한 세부:**
  - 마지막 요청에 따라 자동 업데이트는 두지 않고, 설정 탭 → 시스템 → **이 프로그램 업데이트**의 버튼으로만 합니다. 업데이트하는 동안 모든 앱을 닫으므로, 버튼은 설정 보호와 상관없이 언제나 누를 수 있습니다.
  - 확인과 설치는 두 단계입니다("업데이트 확인" → "지금 업데이트" → "닫고 업데이트하기"). 모든 앱이 닫히므로 저장할 틈을 주기 위해서입니다.
  - 서비스가 GitHub의 릴리스 목록(API)에서 지금보다 새 `v…` 릴리스의 설치 파일을 고르고, GitHub이 주는 SHA-256으로 받은 파일을 확인합니다. 이 저장소의 릴리스 주소가 아니면 받지 않습니다.
  - 서비스는 자기 프로그램을 데이터 폴더에 복사해 업데이트 지킴이로 띄웁니다. 지킴이는 서비스가 멈춰도 남는 별개의 프로세스이고, 사용자 세션의 모든 앱과 브라우저를 0.5초마다 닫으면서 설치 파일을 조용한 모드로 실행합니다(사용자 정보를 남김). 새 서비스가 돈 뒤 20초 동안 더 닫다가 멈춥니다. 브라우저 탭만 골라 닫는 일은 세션 0에서 할 수 없어 브라우저도 닫습니다.
  - 설치가 실패하거나 15분을 넘으면 지킴이가 서비스를 다시 켭니다.
  - 업데이트가 끝나도 Focus 앱은 저절로 다시 뜨지 않습니다. 설치 프로그램이 닫은 Focus 앱을 SYSTEM이 사용자로 다시 띄울 수 없기 때문입니다. 화면에 그 안내를 적었습니다.
  - CI는 실제 GitHub 릴리스 목록으로 확인(`self-update-check`)이 되는지 시험합니다. 실제 설치(지킴이)는 더 새로운 릴리스가 있어야 해서 CI에서 시험하지 못했습니다.
  - 동기화 브랜치의 설치 파일은 정식 릴리스가 아니어서, 이 버튼은 동기화 판에서 따로 맞춰야 합니다.

### 8.63 동기화 판의 업데이트: 빌드마다 `sync-windows-latest`에 올리고, 설정 탭은 그곳에서 받는다
- **소유자 요청:** "PC도 자동 업데이트 되게 만들어줘" 외(8.62와 같은 요청을 동기화 판에 맞춘 것)
- **소유자가 말한 이유:** 서버만 업데이트되면 PC와 버전이 어긋나 골치가 아픕니다.
- **AI가 정한 세부:**
  - 동기화 브랜치는 번호 붙은 릴리스를 내지 않으므로, push할 때마다 release 작업이 설치 파일을 고정 이름의 프리릴리스 `sync-windows-latest`에 `DigitalWellbeing-Setup-<버전>-<커밋 7자>.exe`로 올립니다. 이전 빌드의 파일은 지웁니다. 이 링크에서 exe를 로그인 없이 바로 받을 수도 있습니다(zip artifact 대신).
  - 동기화 판의 "업데이트 확인"은 그 릴리스의 빌드가 이 PC의 빌드(빌드할 때 넣은 커밋)와 다르고 버전이 같거나 높으면 새 버전으로 봅니다. 화면에는 "0.1.0-rc.37 (abc1234)"처럼 버전과 빌드를 함께 보여 줍니다.
  - 이 브랜치의 release 작업은 모든 push에서 돌고(`paths` 조건을 뺐습니다), 이 브랜치에서는 `v…` 릴리스를 절대 만들지 않습니다. 동기화를 main에 합칠 때 이 두 가지를 되돌려야 합니다.
  - 릴리스가 아직 없거나 바꾸는 중이라 GitHub이 404를 주면 "새 빌드 없음"으로 봅니다.

### 8.64 동기화: OPAQUE 로그인, API 키를 서버가 읽지 못하게 암호화해 모든 PC가 하나로 쓴다
- **소유자 요청:** "유저의 비밀번호와 설정 파일을 영지식으로 서버에서 판정하는 방법이 있나?" / "사실 왜 이걸 만드려고 하냐면 API KEY를 서버에 보관하고 싶거든" / (질문에 답하여) "모든 PC가 서버 키 하나", "서버도 못 읽게", "OPAQUE에 대해 설명해봐. 서버 관리자 조차도 비밀번호를 모르게 만들어야해." / "가로 해줘"
- **소유자가 말한 이유:** API 키를 서버에 보관하고 싶습니다. 서버 관리자조차 비밀번호를 몰라야 합니다.
- **AI가 정한 세부:**
  - 로그인과 회원가입을 OPAQUE(RFC 9807, `opaque-ke` 4, Ristretto255, Argon2id 기본값)로 바꿨습니다. 서버는 비밀번호도 해시도 받지 않고, OPAQUE의 비밀번호 파일(`accounts.json`)과 자기 키(`opaque_setup.json`)만 둡니다. 예전의 계정 키(PBKDF2)와 회원가입용 X25519, `GET /public-key`는 없앴습니다. 요청은 `POST /account`로 두 번 오갑니다.
  - 공유 문서 `users.json`에서 비밀번호 해시를 뺐습니다(이름만). 해시가 모든 PC에 퍼져 있으면 그것으로도 대입 공격을 할 수 있기 때문입니다. 같은 PC의 다른 Windows 계정은 PC가 잠가 둔 비밀번호와 비교해 로그인합니다.
  - 틀린 비밀번호는 PC에서 알게 되므로(봉투가 열리지 않음), 서버는 "끝나지 않은 로그인 시작"을 셉니다. 한 이름이 15분에 5번 넘게 끝내지 못하면 15분 동안 받지 않습니다. 모르는 이름도 같은 모양의 답(OPAQUE의 가짜 비밀번호 파일)을 받아, 어떤 이름이 있는지 알아낼 수 없습니다.
  - API 키는 OPAQUE의 export key에서 만든 보관함 열쇠로 암호화해 공유 문서 `vault.json`으로 보냅니다. 각 PC는 지금처럼 자기 `ai_focus.json`의 키를 쓰고(그 값은 지금처럼 동기화하지 않음), 동기화 전후에 보관함과 맞춥니다. 어느 쪽이 바뀌었는지는 마지막으로 맞춘 키의 SHA-256(`vault_base.json`)으로 알고, 둘 다 바뀌면 서버의 것이 이깁니다. 8.52의 "API 키는 기기마다 따로"를 소유자의 새 선택("모든 PC가 서버 키 하나")으로 바꾼 것입니다.
  - 설정 보호 중 키 변경은 그 PC의 예약된 업데이트(세 번 확인)를 거친 뒤에야 보관함으로 갑니다. 예약된 업데이트에는 새 키가 평문으로 있어서 동기화하지 않습니다.
  - OPAQUE에서는 다시 로그인하려면 비밀번호가 있어야 하므로, 서버를 다시 만들어도 PC가 저절로 다시 붙도록 비밀번호를 `sync.json`에 DPAPI(이 컴퓨터에서만 풀림)로 잠가 둡니다. 다시 로그인하다 비밀번호가 틀리면 지웁니다.
  - 서버의 `sync-add-user`는 없앴습니다. 서버에서 비밀번호를 치면 관리자가 비밀번호를 알게 되기 때문입니다. 비밀번호를 바꾸는 기능은 없고, 바꾸려면 서버를 다시 만들어 새로 회원가입합니다. 대신 `sync-remove-device`로 뺀 기기는 같은 이름으로 다시 로그인하지 못하게 했습니다.
  - 서버 파일을 모두 가진 사람의 비밀번호 대입은 어떤 방식으로도 막을 수 없으므로, 긴 비밀번호를 쓰라고 문서에 적었습니다. 최소 길이는 8자입니다.
  - 형식이 바뀌어 지금의 계정은 쓸 수 없습니다. 서버를 비우고 다시 회원가입해야 합니다.

  - 지킴이는 지금 설치된 프로그램의 복사본이므로, 이 고침은 이 버전을 한 번 직접 설치한 뒤의 업데이트부터 효과가 있습니다.

### 8.67 Focus 앱의 화면을 정리한다(테마와 공통 부품)
- **소유자 요청:** "UI UX를 개량하고 싶은데 혹여나 코드 복잡도가 올라갈까 두렵군" / "복잡도가 크게 늘지 않는 선에서 UI를 정리해줘."
- **소유자가 말한 이유:** 코드 복잡도가 올라가는 것이 두렵습니다.
- **AI가 정한 세부:**
  - 화면의 구조와 기능은 그대로 두고, 생김새만 한 파일(`apps/focus/src/style.rs`)에 모았습니다. 다른 파일들은 오히려 24줄 줄었고, 새 파일이 115줄입니다.
  - 테마: 글자를 키우고(본문 15, 작은 글 13, 제목 20), 줄 간격과 버튼 안쪽 여백을 넓히고, 모서리를 조금 둥글게 했습니다. 작은 설명문이 읽기 어려웠기 때문입니다. 기본 창 크기도 560×680에서 620×780으로 키웠습니다.
  - 섹션 제목(`section`): 구분선과 제목을 한 부품이 그리게 해서, 구분선이 있는 곳과 없는 곳이 섞이던 것을 통일했습니다. 화면 맨 위의 제목에는 구분선을 긋지 않습니다.
  - 안내 띠(`notice`): 꼭 읽어야 하는 글(설정 단계, 키 없음, 모든 앱 잠김, 할 일을 기다림)을 색칠한 상자로 보여 줍니다.
  - 주요 버튼(`primary`): 화면에서 가장 누를 만한 버튼(할 일 받기, 적용, 설정 보호하기, 보내기)을 강조 색으로 칠합니다. 누를 수 없을 때는 보통 버튼으로 보여, 누를 수 있는 것처럼 보이지 않게 했습니다.
  - 리눅스 가상 화면에서 전후 화면을 찍어 비교했습니다.

### 8.68 설치할 때 안전 모드를 막는 선택, 제거할 때 다시 여는 선택
- **소유자 요청:** "처음 설치할 떄, 안전모드를 해제하는 옵션도 추가해줄 수 있나 대신 이건 체크박스로 하고 디폴트로 체크 해제되어 있는 상태로 + 경고문도 함께. 그리고 설치 해제할 때 안전모드 다시 활성화하는 체크박스 추가해주고 이건 체크 되어 있는 상태로"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - "안전모드를 해제"는 4.4절의 "안전 모드로 들어가는 길 막기"로 읽었습니다. 명령도 그 절의 것(`reagentc /disable`, `bcdedit`의 recoveryenabled, bootstatuspolicy, displaybootmenu)을 씁니다.
  - 설치 프로그램에 "안전 모드 막기 (선택)" 화면을 하나 더했습니다. 체크 칸은 처음에 해제되어 있고, "이 PC 초기화, 시스템 복원, 자동 복구도 못 쓴다, 설치 USB를 만들어 두라, BitLocker 복구 키를 따로 두라"는 경고를 함께 보여 줍니다. 조용한 설치는 막지 않습니다.
  - 제거 프로그램의 "사용자 정보를 지울까요?" 질문(8.58)을 체크 칸 두 개가 있는 창 하나로 바꿨습니다. "사용자 정보도 지우기"는 처음에 해제, "안전 모드와 Windows 복구 환경을 다시 열기"는 처음에 체크입니다. 질문 창이 두 번 뜨지 않게 하기 위해서이고, 취소 버튼도 있습니다.
  - 다시 열 때는 Windows의 원래 설정으로 돌립니다(`bcdedit /deletevalue`). 예전 문서에 있던 `displaybootmenu Yes`는 막은 적이 없는 PC에서도 부팅 메뉴를 매번 띄우기 때문입니다. 그래서 막은 적이 없는 PC에서 그대로 두어도 해가 없습니다.
  - 명령 하나가 실패해도(예: 복구 환경이 없는 PC의 reagentc) 경고만 남기고 나머지를 실행하며, 설치나 제거는 실패하지 않습니다.
  - CI가 실제 Windows에서 막고(복구 화면 꺼짐) 다시 여는 것을 bcdedit로 확인합니다. 설치 화면과 제거 창 자체는 조용한 모드로만 시험할 수 있어서 화면은 시험하지 못했습니다.

### 8.69 동기화를 main 브랜치에 합친다
- **소유자 요청:** "혹시 동기화 판을 main 브랜치롤 병합해줄 수 있나?"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 동기화 브랜치(`claude/multi-device-sync`)를 main(`claude/digital-wellness-app-dfj98x`)에 합쳤습니다. 이제 정식 릴리스의 설치 파일에 동기화, 회원가입과 로그인, API 키 보관함이 들어 있습니다. 동기화 서버에 붙지 않으면 예전처럼 혼자 동작합니다.
  - 업데이트 버튼은 다시 번호 붙은 릴리스(`v…`)를 봅니다(8.62). 동기화 브랜치에서만 쓰던 "같은 버전의 다른 빌드" 비교(8.63)는 없앴습니다.
  - 이미 동기화 브랜치의 빌드를 쓰는 PC를 위해, 동기화 브랜치를 이 커밋으로 한 번 더 올려 마지막 빌드를 `sync-windows-latest`에 둡니다. 그 빌드에는 번호 붙은 릴리스를 보는 업데이트 확인이 들어 있으므로, 그 PC들은 버튼 한 번으로 정식 릴리스로 넘어옵니다. release 작업은 다시 버전이 바뀐 push에서만 돕니다.
  - 리눅스 서버 빌드(`sync-latest`)는 이제 main에 push할 때 테스트를 통과하면 올라갑니다. 서버의 자동 업데이트는 그대로 그곳에서 받습니다.
