# 설계 결정 기록

이 문서는 기능마다 **누가 그 기능을 정했는지**와 **왜 그렇게 정했는지**를 남깁니다.
나중에 "이거 내가 지시한 건가, 아니면 AI가 알아서 넣은 건가?", "왜 이렇게 만들었지?"를 판단할 때 이 문서를 봅니다.

---

## 0. 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| **소유자** | 이 프로그램을 쓰고, 기능을 요청하는 사람입니다. |
| **AI** | 소유자의 요청을 받아 코드를 쓰는 Claude(개발 도우미)입니다. 프로그램 안에서 판정하는 AI와는 다릅니다. |
| **소유자 요청** | 소유자가 대화에서 직접 말한 것입니다. 원문을 따옴표로 옮깁니다. |
| **소유자가 말한 이유** | 소유자가 요청하면서 직접 밝힌 이유입니다. 소유자가 이유를 말하지 않았으면 "(말하지 않음)"이라고 적습니다. |
| **AI가 정한 세부** | 소유자가 정하지 않아서 AI가 정한 값과 방식입니다. 소유자가 나중에 바꿔도 되는 부분입니다. |
| **질문으로 정함** | AI가 선택지를 물었고 소유자가 고른 것입니다. 소유자 요청과 같은 무게입니다. |

**규칙:** 새 기능이나 동작 변경을 만들 때마다, AI는 이 문서 끝에 항목을 하나 추가합니다(`CLAUDE.md`).

## 1. 차단과 AI 판정

### 1.1 YouTube는 채널 단위로 막는다
- **소유자 요청:** "영상 설명은 일단 빼고 시작하자. 그리고, AI가 채널 단위로 막도록 하고, youtube만 일단 특별 취급하도록 해"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** 채널 이름은 AI가 화면에서 읽습니다. 채널을 모르면 페이지(영상 제목) 단위로 막습니다. YouTube Music은 제외합니다.

### 1.2 탭은 첫 판정에서 바로 막는다
- **소유자 요청:** "지금 생각난 건데 굳이 경고가 필요한가?"
- **소유자가 말한 이유:** (질문 형태) 경고를 기다리는 동안 딴짓을 계속할 수 있다.
- **AI가 정한 세부:** 브라우저 탭은 첫 `off_task` 판정에서 닫고, 앱(프로그램)은 지금처럼 경고 횟수(`strikes_to_block`)를 채운 뒤 끕니다. 앱은 잘못 끄면 작업을 잃을 수 있어서 AI가 경고를 남겼습니다.

### 1.3 차단은 시간이 지나도 풀리지 않는다
- **소유자 요청:** "차단이 정해진 시간이 지나면 풀리게 만드는 것도 이상하다. 사용자가 필요하면 어련히 접근을 요청하겠지."
- **소유자가 말한 이유:** "이는 같은 웹 사이트나 앱을 여러번 검사하게 만드니 경제적이지도 않아."
- **AI가 정한 세부:** 차단마다 고유 ID를 붙이고, 접근 요청 승인이나 Settings 탭의 unblock으로만 풉니다.

### 1.4 판정을 일정 시간 믿고, 관리자가 차단을 풀 수 있다
- **소유자 요청:** "판정 기록이 있으면 일정 기간동안 판정 안하는 정도로 줄이자. 지금처럼 모든 검사 간격에 다시 검사할 필요는 없으니. 관리자가 차단을 푸는 방법도 만들어둬."
- **AI가 정한 세부:** 할 일에 맞는 창은 15분(`recheck_minutes`), 애매한 창은 60초 뒤 다시 판정합니다. API 호출이 실패하면 60초 쉽니다.

### 1.5 열린 탭과 프로그램을 모두 판정한다
- **소유자 요청:** "지금 열려있는 탭 모두 + 지금 켜져있는 프로그램 모두를 전달하도록. 이미지를 모두 전달할 필요 없이 웹사이트는 웹 사이트 제목, 그리고 앱의 경우에는 앱 이름만 전달하면 된다."
- **AI가 정한 세부:** 화면 캡처는 맨 앞 창만 보냅니다. 뒤쪽의 딴짓 탭은 바로 차단하고, 화면에 보이면 포커스를 빼앗지 않고 최소화합니다. 탭은 그 창을 앞으로 가져올 때 닫습니다.

### 1.6 새 앱과 사이트는 바로 판정하고, 일정 시간 뒤 다시 본다
- **소유자 요청:** "1. 지금 올라가 있는 할 일에 부합하는지 판정 기록이 없는 웹사이트, 앱이 켜졌을 경우 이를 감지하여 바로 AI에게 판단을 맡긴다. 2. 마지막 판정으로부터 일정 시간이 지나면 해당 웹사이트나 앱을 다시 검사한다."
- **소유자가 말한 이유:** "잠깐 잠깐 웹사이트나 앱을 쓰는 것도 좀 이상하군."
- **AI가 정한 세부:** 3초마다 확인합니다. 무작위 정기 검사와 "10초 머문 창부터 검사" 규칙은 뺐습니다.

### 1.7 토큰 사용량 추적
- **소유자 요청:** "token 잔량이 얼마나 남아있는지 track할 수 있나?", "토큰 사용량 추적도 만들어줘"
- **AI가 정한 세부:** 잔량은 API로 알 수 없어서 사용량과 예상 비용을 기록합니다. **하루 예산**(다 쓰면 창 검사를 멈춤)은 AI가 덧붙인 기능입니다.

## 2. 설치, 계정, 실행

### 2.1 관리자/표준 계정을 프로그램에서 나누지 않는다
- **소유자 요청:** "관리자와 관리자 아님 계정을 프로그램에서 분리하기 보다, 관리자 계정으로 프로그램을 실행시켜서 다른 계정이 이 프로그램을 끌 수 없게 만들자."
- **소유자가 말한 이유:** "어차피 지정한 기간이 지나면 관리 화면을 풀 수 있으니까."
- **질문으로 정함:** 작업은 표준 계정에서 한다. 관리자용 설정 창은 없애고 하나로 통일하며, 비상 해제는 없다.
- **AI가 정한 세부:** 서비스(SYSTEM)가 사용자 세션마다 agent를 띄우는 구조, 데이터 폴더 권한(SYSTEM과 Administrators만).

### 2.2 관리자 계정도 관리하고, 서비스는 설치와 함께 깔려 부팅 때 시작한다
- **소유자 요청:** "관리자 계정도 관리 해줘.", "안되면 같이 설치되게 해주고 컴퓨터 시작될 때 시작되어서 계속 돌게 해줘."
- **AI가 정한 세부:** 설치기의 Work account 칸을 비우면 모든 계정을 관리합니다(`--manage-all`).

### 2.3 트레이 아이콘
- **소유자 요청:** "tray에서 앱을 열 수 있도록 만들어다오."
- **AI가 정한 세부:** 창을 닫으면 트레이로 숨고, 앱을 다시 실행하면 떠 있는 창을 보여 줍니다.

### 2.4 Linux에서도 돌고, 자동 검사(CI)를 한다
- **소유자 요청:** "윈도우 feature과 윈도우가 아닌 feature를 나누어서 리눅스에도 돌아가게 만들고, 너가 말한 것도 하고." (AI가 제안한 Windows 설치 검사 포함)
- **소유자가 말한 이유:** AI가 실제 Windows에서 시험하지 못한다는 점("너가 테스트를 못하고 있다는가지?")
- **AI가 정한 세부:** X11 구현, 가짜 Claude 서버를 쓰는 끝에서 끝까지 테스트, GitHub Actions의 Windows 설치·업데이트·제거 검사.

### 2.5 진짜 Claude API로 시험한다
- **소유자 요청:** "진짜 claude api로 시험하기를 원해. 내 말은 너가 일하고 있는 리눅스 서버에서도 이런일이 가능하냐는거야", "키를 넣어서 돌려볼래?"
- **AI가 정한 세부:** 키(`DW_E2E_ANTHROPIC_API_KEY`)가 있을 때만 도는 테스트, 운영체제 인증서 저장소를 쓰도록 바꾼 HTTPS(`native-certs`).

### 2.6 우회를 막는 추가 설정을 설명서에 적는다
- **소유자 요청:** "BIOS와 안전모드는 막지 못한다고 했지? 그런데 예전에 reddit 찾아보니까 bios는 비밀번호 걸면 되고 안전모드는 window의 어떤 명령어 입력하면 아예 안전모드를 틀 수가 없었다고 했었어 이 두 가지를 설치 설명서에 적어놔."
- **AI가 정한 세부:** 안전 모드를 막는 명령으로 `reagentc /disable`과 `bcdedit` 설정들을 골랐습니다(`multi_account.md` 4.4절). 소유자가 본 Reddit 글의 정확한 명령은 확인하지 못했습니다.

### 2.7 릴리스는 묻지 않고 한다
- **소유자 요청:** "앞으로 그냥 릴리스 해주면 안되나 어차피 나 혼자 쓸 건데"

## 3. 할 일 플래너

### 3.1 Claude Desktop과 연결하되, 추천 지시문은 고정한다
- **소유자 요청:** "PC claude desktop이고 claude docs 같은 게있어. 내가 다소 걱정되는 건, PC의 claude에 도구를 주었다가, 내가 돌고 싶을 때 claude에 "놀기" 같은 걸 줄까봐 걱정이야. 그래서 지금 할 일 추천하는 프롬프트는 고정하고 싶어."
- **소유자가 말한 이유:** 놀고 싶은 순간에 Claude를 통해 계획을 바꿀까 봐.
- **AI가 정한 세부:** MCP 서버의 도구는 Focus 앱이 할 수 있는 일만 합니다. 질문에 답하는 도구는 없습니다.
- **나중에 바뀜:** 지시문은 3.6에서 "보호된 설정"으로 바뀌었습니다.

### 3.2 생활 규칙으로 심사한다
- **소유자 요청:** "AI가 생활 규칙으로 심사해. 애초에 관리자가 나인데, 관리자 비밀번호를 내가 숨겨둘 뿐이라서."

### 3.3 할 일에는 쉬기와 놀기도 들어가고, 중요한 것은 지금 할 일을 정하는 것이다
- **소유자 요청:** "할 일을 내가 AI에게 제안할 때 AI가 받아들이는 건 테스트할 필요 없을 거 같아. "할 일"에는 내가 쉬거나 노는 것도 포함시킬 예정이거든. AI가 필요한 부분은 AI가 내가 지금 무엇을 해야할지 지정해줄 때야."

### 3.4 할 일마다 언제까지 할지 정하고, 시간이 끝나면 다시 고른다
- **소유자 요청:** "자동 재할당으로. 사실 AI랑 상의해서 자동 재할당과 알림만을 정할 수 있으면 좋겠는데"
- **AI가 정한 세부:** AI가 15~240분을 정하고 프로그램이 10~480분 안으로 맞춥니다. "알림만"은 AI가 심사하고, 자동 재할당으로 되돌리는 것은 묻지 않고 승인합니다. 15초마다 확인합니다.

### 3.5 할 일 변경은 AI가 심사하고, 빈 칸은 AI가 채운다
- **소유자 요청:** "제안 양식을 내가 비워두면 AI가 자동으로 그 양식은 채워주면 좋겠어.", "8은 (가)로 하되, AI가 문제가 생길 수 있으니 (나)를 사용할 수 있는 루트도 추가하도록. 단 이건 2시간 단위로 3번 해라."
- **질문으로 정함:** (나) 경로는 AI가 거절했거나 응답하지 못했을 때만 쓸 수 있다.
- **AI가 정한 세부:** 사용자가 적은 칸은 AI가 바꾸지 않습니다. 하루 30건 한도, 수정·삭제에는 4글자 이상의 이유. 하루 계획, 작업 메모, 할 일별 시간 기록은 AI가 제안하고 소유자가 검토한 To-do 탭 항목입니다.

### 3.6 일찍 끝냈을 때: 결과가 분명하면 증거, 아니면 남은 시간에 다듬기
- **소유자 요청:** "AI에게 결과를 입증할 자료를 보여주는 거야. 다만 결과가 decisive한 경우에만 (예를 들면 누군가에게 메일 보내기, 메시지 보내기, 혹은 뭔가 주문하기 등등.) 만약 결과가 decisive하지 않은 데, 언제나 "더 잘"할 수 있는 종류라면 (예를 들면, 보고서 작성, 발표 연습, 시험 준비 등등), 짧게 끝냈을 때 용인하고 넘어가되, 나중에 시간이 남을 때 "더 잘"하도록 리뷰하게 만들려고"
- **소유자가 말한 이유:** "그게 내가 거짓말을 하는 거일 수도 있지. 하기 싫은 일을 강제로 끝내려는 거야."
- **AI가 정한 세부:** 아래 10장에 적습니다.

## 4. 설정과 보호

### 4.1 설정은 잠글 수 있었다 (나중에 바뀜)
- **소유자 요청:** "관리자가 보는 관리 화면을 "잠궈두지" 않았을 때, 다른 유저도 수정할 수 있게 하되, 유저가 일정 기간 잠굴 수 있게 만들어줘"

### 4.2 잠겨 있어도 고칠 수 있지만, 잠금이 끝날 때 적용 (나중에 바뀜)
- **소유자 요청:** "앞으로 관리 tab은 항상 열려있으나, 내가 업데이트를 저장하면 그게 바로 업데이트 되는 게 아니라 락이 끊기는 시점에 업데이트 하게 해줘"
- **소유자가 말한 이유:** "그래서 내가 악의적으로 수정했을 때 즉각적인 보상을 얻지 못하게끔"

### 4.3 업데이트 예약과 이틀 간격 세 번 확인
- **소유자 요청:** "할 일 고르기, 심사 지시문, 생활 규칙과 다른 설정 역시 업데이트 예약은 걸 수 있게 해줘. 실제 업데이트 적용은 이틀 마다 한 번씩 나에게 "정말 이 업데이트가 맞습니까?"를 물어보고 한 번이라도 업데이트 승인을 안하면 리젝, 세 번 모두 연속으로 승인하면 업데이트 적용하도록"
- **소유자가 말한 이유:** "내가 비 이성적일 때 업데이트 결정을 내리지 않도록"
- **질문으로 정함:** 잠금을 없애고 항상 확인한다(설치 직후 설정 단계만 바로 적용). 답하지 않은 질문은 답할 때까지 기다린다. Claude Desktop도 예약할 수 있다.
- **AI가 정한 세부:** 첫 질문은 예약 이틀 뒤, 다음 질문은 답한 때로부터 이틀 뒤. 같은 파일을 다시 저장하면 예약을 대신하고 확인을 처음부터. 예약 취소(Withdraw)는 확인 없이. Claude Desktop은 설정 단계에서는 예약할 수 없음.

### 4.4 빡빡해지는 변경은 바로, 널널해지는 변경은 예약
- **소유자 요청:** "AI 판정은 빡빡해지는 건 바로 수행하고 널널해지는 건 2일 3회 판정으로 들어가라. (ex. always allow를 빼는 건 바로 수행 넣는 건 2일 3회 판정)"
- **질문으로 정함:** 방향을 판단할 수 있는 모든 설정에 적용한다.

## 8. 최근 항목 (새 항목은 이 아래에 추가합니다)

### 8.1 일찍 끝냈을 때의 증거와 다듬기 (3.6의 세부)
- **AI가 정한 세부:**
  - "끝냈다"를 심사할 때 AI는 결과가 **분명한 것**(보냈다, 주문했다, 제출했다, 예약했다)인지 **더 잘할 수 있는 것**(작성, 연습, 공부)인지 판단합니다.
  - 분명한 결과는 증거가 있어야 승인합니다. 증거는 사용자가 적는 글과, 원하면 화면 캡처 한 장입니다. 화면 캡처는 버튼을 누르고 5초 뒤에 찍으므로, 사용자는 그 사이에 증거가 보이는 창으로 바꿉니다.
  - 더 잘할 수 있는 일을 계획보다 일찍 끝내면 승인하고, 남은 시간을 **다듬기 시간**으로 남깁니다. 남은 시간 = 그 할 일에 필요하다고 본 시간(예상 시간, 없으면 이번 할당 시간) − 지금까지 쓴 시간. 10분보다 적으면 남기지 않습니다.
  - 다듬기 시간이 남은 일은 "Improve: …"라는 할 일로 목록에 나옵니다. AI는 급한 일이 없을 때, 쉬기나 놀기보다 먼저 이 일을 고르도록 지시받습니다. 다듬는 데 쓴 시간만큼 다듬기 시간이 줄고, 다 쓰거나 "끝냈다"가 승인되면 목록에서 빠집니다.
  - "Improve: …" 할 일은 앱이 만든 것이므로, 사용자는 To-do 탭에서 이 할 일을 고치거나 지울 수 없습니다.
  - 화면 캡처를 찍을 때 비공개 앱이 화면에 보이면, agent는 캡처하지 않고 요청을 오류로 돌려줍니다. 화면 캡처는 AI에게만 보내고 저장하지 않습니다.
  - Claude Desktop(MCP)으로는 증거 글만 보낼 수 있습니다. Claude Desktop이 요청할 때 맨 앞 창은 Claude Desktop 자신이므로 화면 캡처가 증거가 되지 않기 때문입니다.
- **실제 Claude로 시험한 결과:** AI는 글로 적은 증거만으로는 승인하지 않고 화면 캡처를 요구할 때가 많았습니다. 들인 시간이 0분인데 "보고서를 다 썼다"고 하면, 더 잘할 수 있는 일이어도 믿기 어렵다고 거절했습니다. 개발자는 이 동작이 소유자의 의도(거짓으로 끝내는 것을 막기)에 맞다고 보고 지시문을 그대로 두었습니다.

### 8.2 전체 코드 검토에서 고친 것
- **소유자 요청:** "/code-review high 타겟은 모든 코드."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** AI는 검토에서 찾은 문제 가운데 다음을 고쳤습니다.
  - Improve 할 일을 할 일 변경으로 고치거나 지우려 하면 agent가 거부합니다. 전에는 승인되어도 아무 일이 일어나지 않거나, 같은 id의 할 일이 목록에 둘 생길 수 있었습니다.
  - agent는 설정 파일과 예약된 업데이트를 한 번에 한 요청만 고치게 합니다. 전에는 Focus 앱과 Claude Desktop이 동시에 저장하면 한쪽의 변경이 사라지거나 파일이 깨질 수 있었습니다.
  - agent는 "끝냈다" 요청이 AI에게 갈 수 있는지 먼저 확인한 뒤에 화면 캡처를 기다립니다. 캡처를 못 하면 그 까닭(비공개 앱, 앞에 창 없음)을 알려 줍니다.
  - 예상 시간이 없는 할 일의 다듬기 시간은 이번 할당만으로 계산합니다.
- **처음에 고치지 않은 것:** 거절된 할 일 변경의 예약, Improve 할 일의 기한, 실패한 요청의 증거 칸. 소유자가 이 셋도 고치라고 했습니다(8.3).

### 8.7 설정 탭: 자동 임시 저장, 항목마다 저장과 적용, 기본값으로 되돌리기
- **소유자 요청:** "설정하는 탭은 자동으로 중간 세이브를 하되, save 버튼을 눌러 사용자가 save 되었음을 스스로 알 수 있게 하고, apply 버튼으로 설정할 수 있도록 만들어. 예를 들면 life rule처럼. AI Instructions도 마찬가지. built-in, default 프롬프트나 옵션이 있는 경우 revert to default 같은 버튼 만들도록 하고." 이어서 "save는 각 수정 탭 밑에다가 두렴. 왜냐하면 rules가 길긴 할테니"
- **소유자가 말한 이유:** 생활 규칙이 길어서, 맨 밑의 버튼까지 내려가기 불편하다.
- **AI가 정한 세부:**
  - 고친 내용은 1초 뒤에 사용자 폴더의 `settings_drafts.json`에 자동으로 임시 저장되고, 앱을 다시 켜면 되살아납니다. API 키는 임시 저장하지 않습니다.
  - 설정 묶음(API 키, 모델, 하루 예산, 플래너 켜기, 생활 규칙, 지시문 하나하나, 차단 목록 하나하나, 검사 간격 등)마다 아래에 "저장", "적용", "고친 것 버리기", "기본값으로 되돌리기" 버튼과, 적용하면 바로 적용되는지 예약되는지 미리 보기가 있습니다. "적용"은 그 묶음의 변경만 agent에 보냅니다.
  - "기본값으로 되돌리기"는 프로그램에 기본값이 있는 묶음(모델, 하루 예산, 지시문, 검사 간격, 접근 요청 한도, 검사하지 않는 앱·비공개 앱·브라우저 목록)에만 있습니다. API 키, 생활 규칙, 차단 목록에는 기본값이 없어서 버튼이 없습니다.

### 8.9 항상 막을 프로그램에 정규식, 항상 막을 웹사이트 목록
- **소유자 요청:** "Always bocked programs가 regular expression을 받을 수 있게 하렴. 그리고 프로그램 뿐만 아니라 always blocked website도 추가할 수 있도록 하렴"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - `* + ? ( ) [ ] { } | ^ $ \` 중 하나가 들어간 항목을 정규식으로 봅니다. 점(.)만 있는 `steam.exe`는 이름 그대로입니다. 대소문자는 무시하고, 프로그램 이름 전체가 맞아야 합니다. 잘못된 정규식은 글자 그대로 비교합니다. Windows에 꼭 필요한 프로그램과 이 프로그램 자신은 정규식에 걸려도 끄지 않습니다.
  - 웹사이트는 브라우저 탭의 제목으로 판단합니다. 프로그램은 탭의 주소(URL)를 읽지 못하기 때문입니다. 제목 끝의 브라우저 이름(" - Google Chrome" 등)은 빼고 봅니다. 맞는 탭은 데일리 웰빙이 꺼져 있어도 AI에게 묻지 않고 닫고, 뒤에 있는 창은 최소화합니다. 접근 허용으로도 풀리지 않습니다.

- **AI가 정한 세부:** 주제마다 접을 수 있는 글로 만들었습니다. 첫 주제는 Claude Desktop 연결 방법(설정 내용 복사 버튼 포함), 말하는 예, Claude Desktop으로 할 수 없는 것입니다. 소유자가 사용법을 더 말하면 이 탭에 주제를 더합니다.

### 8.11 지금 할 일은 AI가 정한다
- **소유자 요청:** "TO-DO는 내가 해야할 일을 "추가"하는 장소지 어떤 일을 할지 내가 "결정"하는 장소가 아니야. 그러니 내가 결정하도록 하지 마." 이어서 "결정은 AI가 해야해. 내가 하면 게을러 진다."
- **소유자가 말한 이유:** 사용자가 결정하면 게을러진다.
- **AI가 정한 세부:**
  - 할 일 탭의 "대신 이것 하기" 버튼과 변경 요청의 "다른 할 일", "목록에 없는 일"을 없앴습니다. Claude Desktop의 같은 요청(`switch_todo`, `switch_free`)도 없앴습니다.
  - 대신 "다른 일 받기"(`repick`)를 만들었습니다. 사용자는 이유만 적고, AI가 이유를 심사해 승인하면 AI가 이유를 보고 다음 할 일을 고릅니다. "막혔어요"와 "쉬고 싶어요" 버튼도 이 요청을 씁니다.
  - agent의 요청 자체(`switch_todo`, `switch_free`)는 예전 버전과의 호환을 위해 남겼지만, 어떤 화면이나 도구도 그 요청을 보내지 않습니다.
  - 플래너를 끈 상태(Settings에서 고름)에서는 지금도 사용자가 하는 일을 직접 적습니다. 이것을 없앨지는 소유자에게 묻기로 했습니다.

### 8.12 통계 탭
- **소유자 요청:** "AI Usage와 같이 지난 일에 대한 건 statistics 탭을 따로 만들어 거기에서 확인할 수 있도록 만들어라"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:** AI 사용량(설정 탭에서), 오늘의 요약·끝낸 일·요청과 AI의 답(할 일 탭에서), 최근 AI 판정(차단 탭에서)을 통계 탭으로 옮겼습니다. 할 일 탭에는 지금 할 일, 변경 요청, 할 일 목록만 남았습니다.

### 8.13 플래너 끄기를 없앤다
- **소유자 요청:** "응 플래너 끄기 모드 없애줘" (AI가 "플래너를 끄면 지금도 사용자가 하는 일을 직접 적는데, 이것도 없앨까요?"라고 물은 데 대한 답)
- **소유자가 말한 이유:** 8.11과 같습니다. 결정은 AI가 해야 하고, 사용자가 하면 게을러진다.
- **AI가 정한 세부:**
  - 플래너는 언제나 켜져 있습니다. 설정 파일의 `enabled` 값은 무시하고, 예전 파일을 읽을 수 있도록 남겨 두었습니다.
  - 할 일 목록이 비어 있으면 할 일 탭은 할 일을 추가하라고 안내합니다. 사용자가 하는 일을 직접 적는 칸은 없습니다.
  - 예전 버전에서 직접 적은 일이 이어지고 있으면, 할 일이 생긴 뒤 agent가 15초 안에 AI가 고른 할 일로 바꿉니다.
  - "할 일 받기"는 agent가 이미 할 일을 고르는 중이면 그 결과를 기다렸다가 이어 받습니다. 전에는 "다른 요청을 처리하고 있다"는 오류가 났습니다.

### 8.14 앞으로 7일 계획: 일에 써야 할 시간과 여유를 파악한다
- **소유자 요청:** "음 다시 생각해봤는데, 일주일 계획과 하루 계획을 세우는 건 괜찮겠다. 다만 그 목적이 몇 시에 뭐하고 뭐하고 이런 걸 결정해 둔다는 느낌 보다는 이번 주에 몇 시간 일에 써야하고 여유 얼마나 있고 등등을 파악하기 위해서에 가깝게" 이어서, 가용 시간을 어디서 가져올지 묻자 "아. 내가 일에 쓸 수 있는 시간은 이번 주에 일을 해치우기 위해서 내가 들여야 하는 시간으로 결정되는 거니까. 내가 설정하는 건 없고 AI가 추정해야지. 그래서 이번 주 스케쥴을 세워보라는 거야." 그리고 보이는 곳은 "통계 탭"을 골랐습니다.
- **소유자가 말한 이유:** 몇 시에 무엇을 할지 정하는 것이 아니라, 이번 주에 일에 몇 시간을 써야 하고 여유가 얼마나 있는지 파악하기 위해서입니다. 8.6에서 없앤 하루 계획(시간표)과는 목적이 다릅니다.
- **AI가 정한 세부:**
  - 한 주를 월요일부터 일요일까지가 아니라 오늘부터 7일로 봅니다. 처음에는 일요일까지로 만들었는데, 일요일에 시험하니 오늘 하루만 남아 한 주를 볼 수 없었기 때문입니다.
  - AI는 사용자가 버튼을 누를 때만 부릅니다(비용). 하루 계획은 따로 부르지 않고, 7일 계획의 오늘 줄이 하루 계획 역할을 합니다.
  - AI가 날마다 일에 써야 할 시간, 여유, 할 일별 시간, 설명, 요약, 주의할 점을 돌려줍니다. 플래너는 7일 밖의 날과 목록에 없는 할 일을 버리고, 하루를 24시간 안으로 맞추고, 합계를 직접 더합니다.
  - 통계 탭에는 AI 없이 앱이 계산하는 "남은 일"(예상 시간 − 들인 시간을 마감별로 더한 것)도 함께 보여 줍니다.
  - 계획은 지금 할 일을 고르는 데 쓰지 않습니다. 고르기는 지금처럼 그때그때 생활 규칙에 맞춰 합니다.
  - 이 계획의 지시문도 다른 지시문처럼 설정 탭에서 고칠 수 있습니다.

### 8.15 관리자 권한이 필요한 프로그램 업데이트와 시간대 지키기
- **소유자 요청:** "내가 프로그램을 삭제하거나 시간을 조종해서는 안된단 말이지. 그런데 카카오톡 업데이트 같은 곳에는 관리자 권한이 필요해. AI 판단이나 미리 지정해둔 프로그램에 대해 관리자 권한을 일시적으로 부여할 수 있나?" AI가 사용자에게 권한을 주는 대신 서비스가 대신 업데이트하는 방법을 제안하고 요청할 때만·매일·둘 다, 시간대 막기, 만들 브랜치를 묻자 "둘 다 하고 시간대 막기도 넣어서 메인에 만들어줘."
- **소유자가 말한 이유:** 사용자가 프로그램을 지우거나 시간을 조종해서는 안 되지만, 카카오톡 업데이트처럼 관리자 권한이 필요한 일이 있다.
- **AI가 정한 세부:**
  - 사용자에게 관리자 권한을 잠깐이라도 주지 않습니다. 그동안 무엇이든 할 수 있고(이 앱 지우기, 관리자 계정 만들기), 관리자로 띄운 설치 창의 파일 대화상자로도 관리자 명령 창을 열 수 있기 때문입니다. AI 판단으로 권한을 주는 방법도 쓰지 않았습니다. AI는 처음 보는 프로그램이 무엇을 하는지 알 수 없기 때문입니다.
  - 대신 서비스(SYSTEM, 사용자가 볼 수 없는 세션 0)가 설정의 목록(`updatable_programs`, winget 이름)에 있는 프로그램만 `winget upgrade --silent`로 업데이트합니다. 지우기와 새로 설치하기는 하지 않습니다. 목록에 넣기는 느슨한 변경(예약), 빼기는 엄격한 변경(바로)입니다.
  - 요청은 설정 탭의 새 영역 **시스템**의 **지금 업데이트** 버튼으로 합니다. 하루 한 번 저절로 업데이트는 새벽 4시 이후 PC가 켜져 있는 첫 때에 하고, 기본값은 켜짐입니다. 30분이 넘는 업데이트는 멈춥니다.
  - 시간대: 설정에 지킬 시간대(`time_zone`)를 두고, 비어 있으면 서비스가 처음 돌 때의 시간대를 적습니다. 서비스는 5초마다 확인해서 다르면 되돌리고 기록합니다. 지킬 시간대를 바꾸는 것은 느슨한 변경(예약)입니다.
  - Claude Desktop과 AI 비서의 도구(`program_update`)로도 업데이트를 요청할 수 있습니다. 이 도구는 AI 비서 브랜치를 합칠 때 더했습니다(8.17).

### 8.16 AI 연결이 끊기면 모든 앱과 웹사이트를 잠근다
- **소유자 요청:** "생각해보니 API 키를 바꾸거나 원격으로 API Key를 바꾸어서 무력화시킬 수 있군. 이를 대비하여, 만약 API키가 연결이 안되있는 상태 + lock 상태이면 API 연결 전까지 "모든" 앱과 웹사이트를 잠구도록 해." 이어서 "아. 아무래도 API를 다시 연결할 때 필요하니까 claude 웹사이트와 claude desktop앱은 예외 처리 하도록 해."
- **소유자가 말한 이유:** API 키를 바꾸거나 원격으로(Anthropic 웹사이트에서) 키를 무력화해서 AI 검사를 끌 수 있기 때문입니다. Claude 웹사이트와 Claude Desktop은 API를 다시 연결할 때 필요하기 때문에 예외입니다.
- **AI가 정한 세부:**
  - "lock 상태"는 설정이 보호된 상태로 읽었습니다. "연결이 안 된 상태"는 키가 없거나, API가 키를 거부하거나(401·403), 크레딧이나 한도가 없거나, 모델을 모르는 경우로 정했습니다. 네트워크 오류와 과부하는 키 문제가 아니므로 잠그지 않습니다. 그래서 인터넷이 끊겨도 잠기지 않습니다(소유자가 원하면 바꿀 수 있습니다).
  - 끄지 않는 것: Windows에 꼭 필요한 프로그램, Windows 폴더 아래의 프로그램, 이 앱, Claude Desktop(`claude.exe`), Windows 설정(네트워크), 웹 보기, 작업 관리자, 설정의 "검사하지 않는 앱". 브라우저는 끄지 않고, 제목에 Claude나 Anthropic이 든 탭, 빈 새 탭, Google 로그인 페이지만 남기고 나머지 탭을 닫습니다.
  - 잠긴 동안에는 API 키를 고치는 것이 예약되지 않고 바로 적용됩니다. 그러지 않으면 새 키가 6일 뒤에야 적용되어 그동안 모든 앱이 잠기기 때문입니다. 모델이 문제일 때는 모델 변경도 바로 적용됩니다.
  - agent는 5분마다(끊긴 동안은 30초마다, 키나 모델이 바뀌면 바로) 비용이 들지 않는 모델 목록 API로 연결을 확인합니다. 크레딧 문제는 그 API로 알 수 없으므로, 그때만 가장 짧은 메시지로 확인합니다.
  - Focus 앱의 모든 탭 맨 위에 잠긴 이유와 푸는 방법을 보여 줍니다.

### 8.17 AI 비서: 이 프로그램의 기능을 말로 쓴다
- **소유자 요청:** "음 이 모든 기능을 자연어 인터페이스를 통해 쓸 수 있으면 좋겠는 데 그게 가능할라나? 기왕이면 AI 에이전트가 있어 가지고 내가 막 반복적으로 todo에 올려라 뭐 이런 요청을 할 수 있으면 좋을 거 같은데 혹시 모르니까 따로 브랜치 파서 만들어봐."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 처음에는 소유자의 말대로 따로 브랜치(`claude/natural-language-assistant`)에서 만들었습니다. 소유자가 "AI 비서 브랜치도 메인에 합쳐서 배포해줘"라고 해서 메인에 합쳐 배포했습니다.
  - 합칠 때 8.15의 프로그램 업데이트를 요청하는 도구(`program_update`)를 더했습니다. 그래서 AI 비서와 Claude Desktop도 목록에 있는 프로그램의 업데이트를 요청할 수 있습니다.
  - Focus 앱에 **AI 비서** 탭을 할 일 탭 바로 옆에 더했습니다. 사용자가 말을 적으면 Claude가 도구를 써서 그 일을 하고, 탭은 쓴 도구마다 이 프로그램의 AI의 답(승인, 거절, 오류)을 회색 줄로 보여 줍니다.
  - AI 비서는 Claude Desktop의 MCP 서버와 같은 도구를 씁니다. 그래서 도구를 `crates/machine/src/assistant_tools.rs`로 옮겨 두 곳이 함께 쓰게 했습니다. 두 도구를 새로 더했고, Claude Desktop도 이 두 도구를 받습니다: `plan_week`(앞으로 7일 계획), `request_access`(차단 탭의 접근 요청과 같음).
  - "결정은 AI가 해야 한다"(8.11)를 AI 비서에도 지킵니다. AI 비서는 다음에 할 일을 고르거나 추천하지 않고, 그만두고 싶다는 말은 `repick`으로 보냅니다. 확인 질문에 답하기, 거절된 변경을 AI 없이 하기, 차단 바로 풀기, 설정 보호 끄기는 AI 비서도 하지 못합니다.
  - 대화는 agent 안에서 돕니다. API 키를 agent만 읽을 수 있기 때문입니다. 한 차례가 몇 분 걸릴 수 있어서, Focus 앱은 말을 보내고 1초마다 대화를 읽습니다. 대화는 agent의 메모리에만 있고, 다시 로그온하거나 **새 대화**를 누르면 사라집니다.
  - 지시문은 영어로 적고, 화면과 답은 한국어입니다(8.7). 지금 시각은 사용자의 말 앞에 붙여 지시문이 늘 같게 했습니다(캐시 때문).
  - 하루 AI 예산은 지금처럼 AI 검사에만 적용하고, AI 비서는 막지 않습니다. 비용은 통계 탭의 AI 사용량에 "assistant"로 나옵니다.
  - "반복적으로 todo에 올려라"는 "말할 때마다 계속 올려 달라고 할 수 있다"로 읽었습니다. 정해진 때마다 저절로 올리는 반복 할 일은 만들지 않았고, 소유자에게 물어보기로 했습니다.

### 8.18 설치할 때 계정을 묻지 않고 모든 계정을 관리한다
- **소유자 요청:** "설치할 때 계정 이름 쓰는 것 말이야, 관리자 계정도 항상 포함시킬거니까 쓰지 말고 모든 유저 대상으로 하도록 해"
- **소유자가 말한 이유:** 관리자 계정도 항상 관리 대상에 포함시킬 것이기 때문입니다.
- **AI가 정한 세부:**
  - 설치 프로그램의 "Work account" 화면을 없애고, 설치 프로그램과 `install.cmd`가 언제나 `install --manage-all`을 실행하게 했습니다. 업데이트할 때도 모든 계정이 관리 대상이 됩니다.
  - 서비스의 `install --manage <계정>` 명령은 남겨 두었습니다. 관리자가 명령으로 직접 실행할 때만 씁니다.

### 8.19 도움말: 설정을 잠그는 방법, 누를 수 있는 Claude Console 링크
- **소유자 요청:** "도움말에 잠그는 방법도 추가해주렴. 어디에 버튼이 있는지 모르겠다." 이어서 "모든 앱이 잠겼을 때 도움말에 claude console의 주소가 적혀있기는 하나 주소를 클릭해서 들어갈 수 있게 해다오. 지금은 하이퍼링크가 아니라서" 그리고 "처음 설치할 때 설정을 보호하지 말고 내가 다 설정한 후 보호하게 만들거라."
- **소유자가 말한 이유:** 설정 보호 버튼이 어디에 있는지 몰랐습니다. Claude Console 주소가 링크가 아니어서 눌러 들어갈 수 없었습니다.
- **AI가 정한 세부:**
  - "잠그는 방법"은 설정 보호로 읽었습니다. 도움말 탭 맨 위에 펼쳐진 주제로 넣고, 설정 탭으로 바로 가는 버튼을 달았습니다. 확인 칸을 체크하기 전에는 **설정 보호하기** 버튼이 흐리게 보인다는 것도 적었습니다. 버튼을 찾기 어려웠던 까닭으로 보였기 때문입니다.
  - 설치 프로그램은 원래 설정을 보호하지 않으므로 코드는 바꾸지 않았습니다. 지웠다가 다시 설치하면 설정 폴더가 남아 보호가 이어진다는 것을 도움말에 적었습니다.
  - 링크는 Claude Console의 API 키 화면, 크레딧(결제) 화면, 예전 주소 세 개이고, 도움말과 잠금 안내(빨간 글) 양쪽에 넣었습니다.

### 8.20 다시 설치해도 API 키를 남긴다
- **소유자 요청:** "업데이트 할 때마다 api key 입력하는 게 번거로운데, 유지되게 만들 수는 없나"
- **소유자가 말한 이유:** 업데이트할 때마다 API 키를 넣는 것이 번거롭습니다.
- **AI가 정한 세부:**
  - 원인: 새 설치 파일을 그냥 실행하는 업데이트에서는 설정 폴더가 원래 남습니다. 그러나 프로그램을 지운 뒤 설치하면 설치기는 남은 설정 폴더를 믿지 않고 옆으로 옮겼습니다. 일반 사용자가 미리 만든 폴더일 수 있기 때문입니다. 그래서 그때마다 키가 사라졌습니다.
  - 해결: 설치기는 남은 폴더의 주인과 권한을 봅니다. 주인이 관리자 그룹이나 SYSTEM이고 다른 누구도 쓸 수 없으면 예전 설치가 잠가 둔 폴더이므로 그대로 씁니다. 설정 보호도 함께 이어집니다. 일반 사용자가 쓸 수 있는 폴더는 지금처럼 옮깁니다. Windows CI가 두 경우를 모두 시험합니다.
  - 키를 다른 곳(예: 사용자 폴더)에 따로 저장하지는 않았습니다. 사용자 폴더는 작업 계정이 마음대로 고칠 수 있어서, 보호된 설정을 우회하는 길이 되기 때문입니다.
  - 함께 고친 것: 설정 파일을 읽지 못하면 기본값으로 덮어쓰지 않습니다. 키가 사라질 수 있는 다른 길이었습니다.

### 8.21 관리자 말고는 프로그램을 지우지 못하게 한다
- **소유자 요청:** "흠 생각해보니 설치된 파일들을 유저가 지워버릴 수도 있군 혹시 관리자 빼고는 프로그램을 못 지우게 만드는 것(폴더 내 쓰기 권한 수정)도 설치할 때 같이 할 수 있나?"
- **소유자가 말한 이유:** 사용자가 설치된 파일을 지워 버릴 수 있기 때문입니다.
- **AI가 정한 세부:**
  - `C:\Program Files\DigitalWellbeing`은 Windows 기본값으로 이미 일반 사용자가 읽고 실행만 할 수 있었습니다. 그래도 위 폴더에서 물려받는 권한에 기대지 않도록, 설치기가 설치할 때마다 폴더의 주인을 관리자 그룹으로 바꾸고 권한(SYSTEM·관리자 모든 권한, Users 읽기와 실행)을 직접 씁니다. 물려받는 권한은 끊습니다.
  - Users에게 읽기와 실행은 남겼습니다. 작업 계정이 Focus 앱과 MCP 서버를 실행해야 하기 때문입니다.
  - Windows CI가 설치 뒤에 SYSTEM과 관리자 말고는 아무도 프로그램 폴더와 그 안의 파일을 고치거나 지울 수 없는지 확인합니다.

### 8.22 반복하는 할 일, AI가 정하는 시간, 할 일을 기다리는 잠금, 완료 보고, AI가 정하는 허용 기간, 할 일별 차단
- **소유자 요청:** "추가사항
1. 잠 자기나 출근 준비, 혹은 운동하기 처럼 반복적인 일을 끝냈을 때 없어지지 않고 후에 반복할 수 있도록, 할 일 수행 이후에 없어지지 않는 타입의 할 일도 추가할 수 있도록 하기
2. 할 일 목록에서 정해진 duration 외에도 AI가 지정할 수 있는지 확인하고 만약 지정할 수 없으면, AI 자의적 판단 하에 시간을 짧게 잡거나 길게 잡을 수 있는 기능을 추가하기.
3. 할 일을 받자마자 시작해버리면 내가 컴퓨터를 켜놓고 물 마시러 가거나 다른 일을 하고 있을 때도 시간이 지나가버린다. 그렇다고 내가 시작 버튼을 누를 때 까지 기다렸다 시작하면, 7시에 지정해준 게 8시 30분에 할 일을 시작해서 틀어질 수 있지. 그러니 할 일을 배정받지 않았을 때는 모든 앱과 웹사이트를 잠구고 유저가 할 일 받기 버튼을 누를 때 까지 기다려라.
4. 할 일이 완료 된 후에 사용자가 완료보고를 하도록 해서 해당 할 일을 없앨지 유지할지 고려하기. (완료 보고 전에 다른 일로 넘어가지 말라)
할 일 목록에서 예상 시간 뿐만 아니라 지금까지 소요한 시간 역시 적기
5. 5번 접근 허용 기간은 사용자가 기본적으로 요청하지 않고 AI가 판단해서 허용하도록
6. 할 일 별로 차단 목록을 관리하기. 그래서 할 일이 바뀌었을 때 차단 목록도 바뀌게."
- **소유자가 말한 이유:**
  - 1번: 잠자기, 출근 준비, 운동처럼 반복하는 일은 끝낸 뒤에도 나중에 다시 해야 합니다.
  - 2번, 5번: (말하지 않음)
  - 3번: 할 일을 받자마자 시간이 흐르면, 사용자가 자리를 비운 동안에도 시간이 지나갑니다. 사용자가 시작 버튼을 누를 때 시작하면, 7시에 정해 준 일이 8시 30분에 시작되어 계획이 틀어질 수 있습니다.
  - 4번: 끝난 할 일을 목록에서 없앨지 남길지 정하기 위해서입니다. 완료 보고 전에는 다른 일로 넘어가면 안 됩니다.
  - 6번: 할 일이 바뀌면 차단 목록도 바뀌어야 합니다.
- **AI가 정한 세부:**
  - 1번: 할 일에 "반복하는 할 일"(`repeat`) 표시를 더했습니다. 반복하는 할 일은 끝내도 목록에 남고, 할 일 탭·AI 비서·Claude Desktop 모두에서 표시할 수 있습니다. 목록에는 "(반복)"이 붙습니다. 8.17에서 미뤄 둔 "반복 할 일"이 이것입니다.
  - 2번 확인 결과: AI는 원래 할 일의 시간(분)을 스스로 정했습니다. 다만 지시문은 15~240분이라고 했고, 코드는 10~480분으로 잘랐습니다. 이제 지시문과 코드가 모두 10~720분(12시간)이고, 지시문은 예상 시간에 묶이지 말고 AI의 판단으로 짧게도 길게도 정하라고 말합니다. 12시간은 잠자기 같은 반복하는 할 일을 담기 위해 고른 상한입니다.
  - 3번: 할 일은 사용자가 "할 일 받기"를 누를 때만 정해집니다. 예전에는 agent가 15초마다 스스로 할 일을 정했습니다. 맡은 할 일이 없으면 모든 앱과 브라우저를 잠급니다(잠금 이유 `NoTask`). 이 잠금은 AI 연결 잠금(8.16)처럼 설정이 보호되어 있을 때만 걸립니다. 설정 단계에서 시험하다가 갇히지 않게 하기 위해서입니다. Claude Desktop, Windows에 필요한 프로그램, 이 앱, "검사하지 않는 앱"은 남깁니다. 브라우저는 이 잠금에서는 끕니다. "할 일 받기" 버튼 하나로 풀리므로 웹사이트가 필요 없기 때문입니다. 다시 로그온하면, 이미 맡은 할 일이 있으면 그대로 이어집니다.
  - 4번: 할 일의 계획된 끝이 지나면 완료 보고만 받습니다. "끝냈다"는 지금처럼 AI가 심사하고, "다 못 했다"(`not_finished`)는 심사 없이 받아들여지며 할 일은 목록에 남습니다. 보고 전에는 다른 일 받기와 AI 검사 멈추기가 거절됩니다. 보고한 뒤에는(끝냈다가 승인되어도) 다음 "할 일 받기"까지 아무 할 일도 정하지 않습니다. 그래서 예전의 "시간이 다 되면 알리기만"과 "시간이 다 되면 새 할 일 받기" 요청은 없앴습니다. 계획된 끝 전에 끝냈다고 하는 것은 지금처럼 됩니다.
  - 4번의 둘째 줄: 할 일 목록의 줄마다 "지금까지 쓴 시간 / 예상 시간"을 보여 줍니다. 반복하는 할 일은 마지막으로 끝낸 뒤에 쓴 시간을 셉니다.
  - 5번: "5번 접근 허용"은 차단 탭의 접근 요청으로 읽었습니다. 차단 탭에서 기간 칸을 없앴고, 요청은 "AI가 정함"(`ai_decides`)으로 갑니다. AI는 설정의 최대 길이와 영구 허용 여부 안에서 정합니다. AI 비서와 Claude Desktop은 사용자가 기간을 직접 말했을 때만 기간을 보냅니다.
  - 6번: AI가 건 차단은 그 차단을 건 할 일에 속합니다. 할 일이 바뀌면 이전 할 일의 차단은 보관되고 새 할 일의 차단이 적용되며, 이전 할 일로 돌아오면 그 차단이 다시 적용됩니다. 할 일의 글만 고친 것은 같은 할 일입니다. 항상 막을 프로그램과 항상 막을 웹사이트는 할 일과 상관없이 늘 적용됩니다. 이 버전 전에 걸린 차단은 어느 할 일에도 속하지 않아 적용되지 않고, 설정 탭의 "걸린 차단"에만 남습니다.

### 8.23 컴퓨터 없이 하는 일은 모든 앱을 잠그고, 급한 일로만 바꾼다
- **소유자 요청:** "아 그리고 컴퓨터로 하지 않는 종류의 일이면 모든 앱과 웹사이트를 잠구도록 해줄래? 예를 들면 잠자기라든지 운동하기 라든지, 그리고 급한 일로만 바꾸도록"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 할 일에 "컴퓨터 없이 하는 일"(`away_from_computer`) 칸을 더했습니다. 사용자가 비워 두면 할 일 변경을 심사하는 AI가 채우고, 이 기능 전에 만든 할 일은 AI가 고를 때 판단합니다. 할 일의 값이 AI의 판단보다 우선합니다.
  - 잠금은 다른 잠금처럼 설정이 보호되어 있을 때만 걸리고, 브라우저도 끕니다. 이 앱은 열려 있어서 끝나면 보고할 수 있습니다.
  - "급한 일로만 바꾸도록"은 "이런 일을 하는 동안에는 급한 이유가 있을 때만 다른 일 받기와 AI 검사 멈추기를 승인한다"로 읽고, 변경 요청 심사 지시문에 넣었습니다. 코드가 급한지 판단할 수는 없으므로 AI가 판단합니다. "끝냈다"는 지금처럼 심사합니다.

### 8.24 약속: 시각이 정해진 일은 고정하고, 받을지는 AI가 약속 규칙에 따라 정한다
- **소유자 요청:** "음 그리고 할 일 말고 "약속"을 추가해주도록 할래? 그래서 약속이 있을 때는 고정해서 하도록" 이어서 "약속을 악용할 수도 있으니 약속을 받을지 말지 AI가 결정하게 하는데, 그 룰도 설정에서 설정할 수 있게 해줘."
- **소유자가 말한 이유:** 약속이 있을 때는 그 시간에 고정해서 해야 합니다. 약속은 악용될 수 있습니다.
- **AI가 정한 세부:**
  - "고정"을 "시작 시각에 하던 일 대신 저절로 현재 할 일이 되고, 끝나는 시각에 저절로 끝난다"로 읽었습니다. 사용자가 "할 일 받기"를 누르지 않아도 시작합니다(agent가 15초마다 확인). 하던 할 일은 보고 없이 끝나고 목록에 남습니다. 약속은 완료 보고가 필요 없습니다.
  - AI가 할 일을 고를 때 다가오는 약속을 보고, 할 일의 계획된 끝은 다음 약속의 시작에서 끊깁니다. 7일 계획도 약속을 압니다.
  - "그 룰"은 설정 탭의 새 칸 **약속 규칙**(`appointment_rules`)과, 고칠 수 있는 다섯째 지시문 "약속을 받을지 심사"(`APPOINTMENT_PROMPT`)로 만들었습니다. 생활 규칙처럼 보호된 뒤에는 변경이 예약됩니다.
  - 코드가 먼저 막는 것: 2글자보다 짧은 제목, 이미 지난 약속, 24시간이 넘는 약속, 이미 받은 약속과 겹치는 약속.
  - 거절된 약속은 할 일 변경과 달리 "AI 없이 하기"로 예약할 수 없게 했습니다. "받을지 말지 AI가 결정하게"라는 요청 때문입니다. 지우기는 시간을 돌려줄 뿐이므로 AI 없이 바로 됩니다.
  - 약속 동안 다른 일로 바꾸려면 8.23처럼 급한 이유가 필요합니다. 컴퓨터 없이 하는 약속이면 모든 앱이 잠깁니다.
  - 할 일 탭, AI 비서, Claude Desktop(`add_appointment`, `remove_appointment`)에서 약속을 넣고 지울 수 있습니다. 시각은 "14:00", "오후 2시", "2시 반"처럼 적을 수 있습니다.

### 8.25 모델은 목록에서 고르고, 적용 전에 확인하고, 목록은 일주일마다 새로 받는다
- **소유자 요청:** "모델을 dropdown 메뉴로 변경할 수 있게 해줘. 그래야 내가 오타를 안내지 그리고 내가 모델을 없는 이름으로 고쳐서 악용할 수 있기도 하고. 이 역시 적용버튼 누르면 모델이 있는지 아무 콜이나 보내서 확인하도록 하고. 그리고 주기적으로 claude model을 찾아서 뭐가 있는지 확인하고  업데이트 하도록 해.(한 일주일 마다 한번씩?)"
- **소유자가 말한 이유:** 오타를 막고, 없는 모델 이름으로 고쳐서 악용하는 것을 막기 위해서입니다.
- **AI가 정한 세부:**
  - "아무 콜"은 비용이 들지 않는 모델 API 조회(`GET /v1/models/<모델>`)로 했습니다. 확인이 실패하면(모델이 없거나 인터넷이 끊김) 적용하지 않습니다. 이 확인은 연결 상태를 바꾸지 않습니다.
  - 확인은 agent가 설정을 쓰기 직전에 하므로, 설정 탭뿐 아니라 Claude Desktop의 설정 예약도 같은 확인을 거칩니다.
  - 목록은 agent가 일주일마다 받아 `models.json`에 둡니다. 받지 못하면 6시간 뒤에 다시 시도하고, 그동안은 프로그램에 들어 있는 기본 목록을 보여 줍니다.
  - API 키가 없을 때는 확인할 수 없으므로 변경을 받아들입니다. 키가 없으면 어차피 모든 호출이 실패하고, 보호된 뒤라면 모든 앱이 잠기기 때문입니다.

### 8.26 통계 탭에 기능별 AI 비용을 보여 준다
- **소유자 요청:** "AI API call이 생각보다 비싸더라고 60분 썼는데 1달러 정도 들었어. 그래서 어느 기능에서 가격이 드는지 알고 싶으니 통계에서 이를 보여주도록 해. 각 기능에서 얼마나 썼는지."
- **소유자가 말한 이유:** 60분에 약 1달러가 들어서, 어느 기능이 비용을 쓰는지 알고 싶습니다.
- **AI가 정한 세부:**
  - 프로그램은 이미 용도별로 사용량을 세고 있었으므로, 새로 센 것은 없고 보여 주는 표만 만들었습니다. 표는 기능마다 오늘, 최근 7일, 이번 달의 비용과 호출 수, 한 번의 평균 비용, 이번 달 비중, 이번 달의 입력과 출력 토큰을 보여 줍니다. 이번 달 비용이 큰 기능부터 나옵니다.
  - 기능 이름은 한국어로 바꾸고("창 검사(AI 검사)" 등), 이름 위에 마우스를 올리면 그 기능이 언제 AI를 부르는지 나오게 했습니다.

### 8.27 사용 중지 버튼
- **소유자 요청:** "그리고 사용 중지 버튼을 추가하도록 해. 그 버튼을 누르면 모든 앱과 웹사이트가 막히고 차단 외 모든 동작을 멈출거야."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 버튼은 할 일 탭 맨 위의 "데일리 웰빙" 옆에 두고, 한 번 더 **멈추기**로 확인하게 했습니다. 잘못 눌러 할 일이 끝나는 것을 막기 위해서입니다.
  - 지금 할 일은 끝나고 목록에 남습니다(다 못 한 것과 같음). 모든 앱이 잠기므로 이것으로 일을 피해도 얻는 것이 없어서, 완료 보고를 먼저 요구하지 않았습니다.
  - "차단 외 모든 동작"은 AI 검사, 약속 시작, 연결 확인, 모델 목록 받기, AI를 부르는 요청(할 일 변경, 7일 계획, AI 비서)으로 정했습니다. 항상 막을 프로그램과 웹사이트, 걸린 차단, 프로그램 업데이트와 시간대 지키기(서비스가 함)는 그대로입니다.
  - 이 잠금은 다른 잠금과 달리 설정 단계에서도 겁니다. 사용자가 직접 눌렀고 **다시 사용하기** 하나로 풀리기 때문입니다. "할 일 받기"도 멈춤을 풉니다.

### 8.28 도움말: 설치 방법과 우회를 막는 방법
- **소유자 요청:** "설치 방법과 우회 방지 방법 역시 정리해서 도움말에 적어두도록 해."
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 도움말 탭에 "설치하기와 업데이트하기"와 "우회 막기 (이 프로그램이 막는 것과 관리자가 할 일)"를 더했습니다. 우회 막기는 이 프로그램이 스스로 막는 것, 관리자가 직접 해야 하는 것(표준 계정, 관리자 비밀번호 맡기기, BIOS 비밀번호와 USB 부팅 끄기, 안전 모드 끄기, 다른 기기), 남는 한계로 나눴습니다.
  - 릴리스 페이지로 가는 링크를 넣었습니다. 자세한 명령은 도움말에 다 옮기지 않고 `docs\multi_account.md` 4.4절을 가리키게 했습니다.

### 8.29 설정 탭의 걸린 차단 목록이 순서를 지킨다
- **소유자 요청:** "지금 걸린 차단의 목록이 마우스 움직일 때마다 순서가 마구잡이로 바뀌는 데 고쳐봐" 이어서 "아 참고로 차단 탭의 지금 걸린 차단은 정상 동작하는데 설정 탭의 지금 걸린 차단이 이상해"
- **소유자가 말한 이유:** (말하지 않음)
- **AI가 정한 세부:**
  - 원인: 설정 탭은 화면을 그릴 때마다(마우스를 움직이면 다시 그림) 차단 파일을 해시 표로 새로 읽었고, 해시 표는 읽을 때마다 순서가 다릅니다.
  - 지금 할 일의 차단을 먼저, 그다음 할 일과 이름 순서로 정렬했습니다.
